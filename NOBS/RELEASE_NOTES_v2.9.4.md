# OBS 排障助手 V2.9.4 发布说明

> 版本：**2.9.4**｜上一版：2.9.3
> 主题：**简单录像**（一键配置 OBS 并开录）· **帮助与反馈页** · **仓库封面与社区文件**。
> 落地纪律沿用 V2.9.3：写配置前先整备份、写后读回逐项校验、可回滚、逐项可取消。

V2.9.3 的「一键部署录制环境」把与录制质量相关的配置一次到位，
但它回答的是「配置应该长什么样」；真到「我就想录个像」这一步，用户还要自己回 OBS 按开始、
自己判断现在能不能录、录完自己去找文件。本版把这条路上的五个疙瘩
（配好 → 验好 → 开录 → 录得住 → 录完找得到）串成首页上的一次操作。

依据：[`docs/FEATURES_USERVIEW_2026-10-05.md`](docs/FEATURES_USERVIEW_2026-10-05.md)（用户视角结论）、
[`docs/SIMPLE_RECORDING_DESIGN.md`](docs/SIMPLE_RECORDING_DESIGN.md)（逐文件施工图）。

## 一、简单录像：选一个词，然后开始

首页顶部新增「简单录像」卡。三档预设只回答「录什么」，不替用户决定「怎么编码」：

| 预设 | 录像规格 | 适合谁 |
|---|---|---|
| **快速录像**（默认） | 1080p · 60fps · HQ · Hybrid MP4 | 通用推荐 |
| **会议 / 网课** | 1080p · 30fps · HQ · Hybrid MP4 | 文件更小、CPU 更友好 |
| **游戏高码率** | 1080p · 60fps · HQ · Hybrid MP4 · **自动分段** | 长录制，不产生单个巨型文件 |

采样率（48kHz）只在 obs-websocket 通道写入，文件通道不写 —— 沿用 V2.9.3 的口径：
INI 里音频设置的位置随 OBS 版本变动，赌错就是把用户配置搞乱。

预设落到配置上的写项，只新增这几类**可验证的键**：

| 写项 | 取值 | 三档差异 |
|---|---|---|
| 录像格式 | Hybrid MP4（`hybrid_mp4`） | 三档一致 |
| 录像质量 | HQ | 三档一致 |
| 音频轨 | `RecTracks = 1` | 三档一致（兼容旧版 OBS 的默认值） |
| 分段 | `RecSplitFile = true` + 分段时间 / 单段大小 | **仅「游戏高码率」** |

帧率与画布 / 输出分辨率复用 V2.9.3 已经写过的同一批目标（同一份 `StaticTargets`），
因此不会出现「部署卡写一套键、简单录像写另一套键」的漂移。

**为什么只写这几个键**：输出模式、编码器族与码率属于用户自己的选择，
改了会连带影响他正在用的工作流，而且本机无法验证取值是否正确 —— 需要它们时走「高级设置」，
跳到 V2.9.3 那张部署卡。**本版没有新增任何一个码率写项**：
「游戏高码率」这个档名对应的是 60fps + 自动分段，码率仍由用户自己在 OBS 里设定。

## 二、OBS 没启动：本工具拉起、等就绪、自动开录

按「现在到底是什么状态」分流，每一档都给得出可照做的下一步：

| 当前状态 | 本版行为 |
|---|---|
| 已连上 OBS | 走 obs-websocket 落地（即时生效、无需重启）→ 直接开录 |
| 没连上、**OBS 进程也没跑**，`basic.ini` 可写 | 先整备份再落地 → **拉起 obs64.exe** → 每 1 秒轮询等 obs-websocket 就绪（最长 75 秒）→ 自动开录 |
| 没连上、但 OBS 进程在跑 | **不落地、不拉起**，只给原因与出口（去 OBS 打开 WebSocket，或退出 OBS 走文件通道） |
| 录制中 / 推流中 | 直接阻断，**不写任何配置** |

拉起前会问一次；文件通道改完还会提示「需要重启 OBS 才生效」（WebSocket 通道不需要）。

**exe 怎么找**：注册表 `Uninstall\OBS Studio` 的 `DisplayIcon`（形如
`"C:\...\bin\64bit\obs64.exe",0`），以及已探测到的安装根
（`根\bin\64bit\obs64.exe` → `根\obs64.exe` → `根\bin\obs64.exe`），
全部过 `File.Exists` 校验，去重并保序。
**解析字符串与磁盘探测刻意分成两层**：前者是纯逻辑、被单测钉死
（带引号 + `,0` 尾巴 / 无引号 / 只有路径 / 空值四种形态），
后者才需要碰注册表与文件系统 —— 这样「路径推导错在哪一段」永远有机器证据。

**找不到就不猜**：便携版（`portable_mode.txt`）与绿色解压版的识别能力有限，
找不到 exe 时只提示「请自己启动 OBS」，不去猜一个可能不对的路径把它拉起来。

## 三、录之前一句话，录之中看得见

- **「现在能不能录」只有一行结论**：就绪，或者阻断 + 原因 + 出口。
  判定按硬门槛排序：正在推流 → 缺配置 / 文件通道写不了 → OBS 在跑但没连上 →
  录前自检有失败项 → 有警告项。最后两种情形在 V2.9.3 会被笼统归到
  「OBS 在跑但没连上」，真实原因（直播中不能改输出参数）反而看不到。
- **录制中显示已录时长与剩余可录时长**：
  - 已录时长按「开始录制到现在」计，**暂停的时间不计入** —— 口径直接写在界面上，不让人自己猜；
  - 剩余可录按时长估算：`空闲空间(GB) × 1024 × 8 ÷ (预设码率(kbps) × 1.5) ÷ 60`（分钟），
    即给码率留 **50% 冗余**，沿用工具箱磁盘写入体检的同一口径；
  - 剩余低于 **10 分钟**给出低空间提示；录制中还显示已写文件大小；
  - 首页卡、控制台输出区与托盘 ToolTip 共用同一份状态，不需要分别去看。
- **录完找得到**：停止后提示文件已生成并读回文件大小，可一键「打开目录」；
  本机有 ffmpeg 时可一键无损转封装成 MP4，没有 ffmpeg 时给 OBS 自带「重新封装录像」的菜单路径
  （而不是留一个点了报错的按钮）。

## 四、新增设置项（不改也能用）

| 设置 | 作用 |
|---|---|
| 默认预设 | 简单录像卡打开时即选中它，不必每次重选；三项都持久化在 `prefs.json` |
| 文件通道时允许自动启动 OBS 并开录 | 允许之后，OBS 没跑时才走「拉起 → 等就绪 → 自动开录」；不允许时仍由用户自己启动 OBS |

「替你启动一个外部程序并且自动开始录制」是有副作用的动作，所以它是**显式设置项**：
是否允许由用户在设置里决定，而不是悄悄替他执行。不静默安装、不静默改配置、
不做无人值守的后台改写，这条基调与 V2.9.3 一致。

## 五、沿用 V2.9.3 的落地纪律

| 纪律 | 本版做法 |
|---|---|
| 先整备份 | 任何写入前先整份备份当前配置集，备份失败即中止 |
| 写后读回校验 | 文件通道写盘后重新读回、逐项比对目标值 |
| 可回滚 | 每一项都记旧值，回滚就是把旧值写回去 |
| 逐项可取消 | 折叠区列出「当前 → 建议」，每一项都能单独不应用 |

明确不碰的东西与 V2.9.3 一致：**推流参数、输出模式（`Output/Mode`）、编码器族（`RecEncoder`）、码率**。
新增文案中英成对，键集由既有单测钉死。

## 六、帮助与反馈：把「反馈」从两页底部搬到一级导航

V2.9.3 的反馈卡只出现在「工具箱」与「搭建」页的底部 ——
**要反馈的用户得先猜到它在哪一页，这等于没有入口**。本版新增一级导航「帮助与反馈」：

| 内容 | 说明 |
|---|---|
| 反馈入口 | 复用 V2.9.3 的反馈卡：腾讯文档表单（手机扫码即可填）、GitHub Issues、**随包离线二维码** |
| **一键复制报错材料** | 把「版本 / 系统 / OBS 是否连接 / 当前场景与场景数 / 录前自检结论」拼成一段文字复制到剪贴板，粘贴即可提交 |
| 隐私边界 | 复制的材料**只有版本号与本地检测结论**：不含路径、设备名、日志原文；是否发送完全由用户自己决定 |
| 作者与仓库 | 开发者署名（GitHub 主页）与项目仓库直达；两个地址与反馈入口共用同一套 https + 域名白名单校验 |

入口不止一个：首页快捷入口、左侧导航、托盘菜单各一处。剪贴板可能被别的程序占用，
复制会重试三次再报「复制失败」，而不是一次失败就打扰用户。

## 七、仓库封面与社区文件

- **重绘矢量图标与封面**：`assets/icon.svg`（显示器 + 录制指示点 + 体检对勾，
  语义是「正在录」与「已查清」）、`assets/banner.svg`（README 封面）、
  `assets/social-preview.svg`（GitHub 社交预览 1280×640）。**SVG 是源文件、PNG 由脚本渲染**
  （`scripts/render_assets.ps1`，用系统自带 Edge/Chrome 无头模式，不引入任何依赖）——
  社交预览只吃位图，手点一次截图很容易被后来的改动落下；
  图标在封面里是**内联**的，避免 GitHub 的 camo 代理把外部引用拦成裂图。
- **补齐 GitHub 社区标准**：行为准则（`CODE_OF_CONDUCT.md`）、贡献指南（`CONTRIBUTING.md`，
  含本仓库真实的构建 / 测试 / 文案成对 / 纯逻辑带单测约定与提交规范）、
  安全策略（`SECURITY.md`，含私密报告通道）、Issue 表单（bug / 功能建议，YAML Issue Forms）、
  PR 模板。
- 顺带修掉一处**文档与实现不一致**：Release 说明承诺「拉起 OBS 前会问一次」，
  而实现里此前是直接拉起。本版补上确认弹窗（`ConfirmDialog`），
  且服务层的确认回调**未注入时按「不允许」处理** —— 在自检 / 后台这类没有界面的路径上
  不会悄悄替用户启动别的程序。

## 八、质量基线

- 本版的纯逻辑（预设取值与键集合、就绪判定的每一条分支、exe 路径解析的四种形态、
  进度估算的边界）都由单测覆盖，并纳入既有的文案表检查（键集一致 / 非空 / 英文侧无汉字）；
  新增 XAML 引用继续由 `scripts/check_resources.py` 与 Headless 自检把关，
  两个目标框架（`net10.0-windows` / `net6.0-windows`）均需可编译。
- **626 项单元测试全部通过**（上一版 565 项，本版新增 61 项）：
  `SimpleRecordingCoreTests` 37 项 + `ObsLaunchCoreTests` 16 项 + `RecordingEnvCoreTests` 追加 6 项
  + 新增的**文案调用点体检** `StringsCallSiteTests` 2 项（见下）；
- **新增一类常驻测试：文案调用点体检**（`StringsCallSiteTests`）。既有的 `StringsTests` 只管
  「文案表自己是否自洽」，管不到调用点 —— 而调用点有两种错误编译器完全看不见：
  ① **调用了不存在的键**（界面直接显示键名本身）；② **占位符个数对不上**
  （少传时界面出现字面 `{0}`，多传时参数被静默丢弃）。本版靠它抓到了 3 个真实缺陷：
  `simple.state.stopping` 与 `main.watchedMore` 两个键根本不存在、`env.writeFailed` 的异常原因被静默丢掉。
  该测试按源码静态扫描全部 `Strings.T("字面量", …)` 调用点（含逐字串 / 插值串），
  并**显式跳过拼接键**（`Strings.T("env.item." + key + ".label")`）—— 那类由各页面用
  「取不到就退回键名」的兜底处理；
- **Headless 自检 22 项全部 PASS**（路由 18 项 + 新手引导 + 迷你小窗 + 文案资源 + 语言切换往返）；
- `scripts/check_resources.py` 全绿（33 个 XAML / 1505 处引用 / 1835 个文案键全部可解析）；
- 三轮分视角审校（数据安全与配置写入 / 双目标与线程生命周期 / 交互文案与文档一致性），
  记录见 [`docs/reviews/REVIEW_2026-10-05-v2.9.4.md`](docs/reviews/REVIEW_2026-10-05-v2.9.4.md)，
  其中如实标注了「哪些结论有机器证据、哪些只是人工核对」。

## 九、已知边界

- ⚠️ **「这些取值对真实 OBS 到底落成什么样」没有做过端到端验证**：
  `HQ` / `hybrid_mp4` / `RecSplitFile*` 这些取值，以及「文件通道落地 → 拉起 OBS →
  等就绪 → 自动开录」这条完整链路，只做到**协议 / 键名 / 纯逻辑单测**级别；
  真机落地效果与端到端时延属于人工核对项，本说明不宣称已验证。
- ⚠️ **便携版 / 绿色版 OBS 的安装路径识别能力有限**：只认注册表 `DisplayIcon`
  与常见安装目录；找不到时不猜路径，直接提示用户自己启动 OBS。
- 剩余可录是**估算**（预设码率 × 1.5 冗余），不是实测写入速率；真实码率随画面内容波动。
- 文件通道写入的项需要重启 OBS 才生效，界面上有对应引导；WebSocket 通道不需要。
- 录制中 / 推流中一律不落地配置：这是硬门槛，不是提示。

## 十、升级方式

- **应用内增量更新**：「检查更新」→ 增量更新，下载后自动校验、提权替换并重启；
- **完整安装包 / 便携包**：见 Release 资产，便携包解压即用；
- 产物命名与构建口径沿用 V2.9.3（主构建 + `_win7` 兼容构建双份，同一 AppId，
  兼容构建所用 .NET 6 已停止安全更新，新机器请用主构建）。
