# V3.5.2 发布说明

## 一句话摘要

V3.5.2 是一次**状态可信度修复版**：解决「录制已经停止，电脑端和手机端却还显示正在录制 / 直播中」的问题。根因有两层——OBS 在停止事件之后仍会短暂把 `outputActive` 报成 `true`，而助手的批量状态查询协议此前一直发错，导致连接后的状态刷新静默失效。本版把两处都修好，并让手机端的「直播中 / 录制中」文案按真实状态区分。

## 新增功能

本版无新增功能，只修复问题。

配套的小改进（不构成新功能）：

- 手机端状态灯文案区分「直播中」「录制中」「直播中 · 录制中」；只录制时不再显示「直播中」。
- 迷你小窗「还可录约 X 分钟」改为整数显示，不再出现 `50.20700444444444` 这类未格式化数字。

## 修复的问题

### 1. 电脑端：停止录制后仍显示「录制：进行中」

- **以前**：在 OBS 或助手里停止录制，OBS 已经明确返回 `outputActive=false`，但控制台、迷你小窗与托盘的录制状态仍停在「进行中」，必须手动点「刷新」或重连才会消失。
- **原因**：OBS 在发出 `RecordStateChanged(STOPPING/STOPPED)` 之后，仍会短暂（实测约 0.5–1 秒）让 `GetRecordStatus` 返回 `outputActive=true`。旧实现把这次「补齐查询」的结果直接写回 `Active`，于是刚停止的录制被翻回运行中，而此后不会再有事件来纠正。
- **现在**：状态事件是权威来源，查询只补时长与字节数；查询结果与最近事件冲突时，3 秒内以事件为准。另有每 3 秒一次的轻量对账，兜住偶发丢失的事件；只有状态真的变化时才刷新界面。

### 2. 手机端：页面刷新后明明没有直播 / 录制，却显示「直播中」「录制中」

- **以前**：手机页面刷新或 WS 重连时，服务端直接回放缓存里的 OBS 状态；一旦缓存被上述竞态写脏，手机就一直显示红灯、计时器停在几秒，看起来像还在录。
- **现在**：手机页面刷新 / 重连前先向 OBS 对一次输出状态；状态灯文案按 `streaming` / `recording` 区分；不在录制时录制计时器固定为 `00:00:00`。

### 3. 批量状态查询协议发错，连接后的状态与音量全部不刷新

- **以前**：批量请求被当成 `requestType = "CallBatch"` 的普通请求发送，OBS 返回 `204 Your request type is not valid`；执行方式又传了字符串 `"Parallel"`，即使走对操作码也会被 OBS 以 `4004` 断开。结果是连接后的录制 / 推流 / 虚拟摄像头状态、音频静音与音量全部依赖事件，刷新与对账形同虚设。
- **现在**：改用 obs-websocket 5.x 的 `RequestBatch`（op 8）与 `RequestBatchResponse`（op 9），执行方式使用协议要求的数字枚举，并默认串行执行。
- **为什么不用 Parallel**：在 OBS 33.0.1 / obs-websocket 5.7.6 上实测，`executionType=2 (Parallel)` 会把 `results[].responseData` 错配到别的子请求（录制 / 推流 / 虚拟摄像头互相串位）；`0 (SerialRealtime)` 与 `1 (SerialFrame)` 结果正确。本版选择串行，宁慢一点也不能拿错状态。

### 4. 其它连带修复

- 不在录制 / 推流时，`RecordElapsed` / `StreamElapsed` 固定返回 0，停止后不会再显示上一轮的时长。
- 手机端连接后音频输入能正确显示静音状态与真实音量（此前批量失败时只有 `??` / `0`）。

## 兼容性与升级

- 版本号：`3.5.1` → `3.5.2`，可覆盖升级，无需卸载旧版。
- 安装目录、程序集名、数据目录（`%LocalAppData%\OBS_Helper`）均未改变；设置、模板、提词稿、手机配对记录、壁纸库全部保留。
- 系统要求不变：Windows 10 / 11；Win7 兼容构建仍可运行。
- 协议要求不变：主构建仍使用 obs-websocket 5.x（OBS 28+）；Win7 兼容构建的 4.x 旧协议路径未改动。
- 增量包：V3.5.1 → V3.5.2 版本连续，可生成增量包；实际以 CI 的基准资产为准。

## 已知边界

- 安装包与便携包仍未做 Authenticode 代码签名：需要开发者本人的代码签名证书与私钥，仓库内没有该证书；SmartScreen 仍可能提示「未知发布者」。
- 本版实测环境为真实 OBS 33.0.1 + obs-websocket 5.7.6；手机端使用 390×844 移动视口与无头浏览器验证，**未在真实手机硬件上复测**。
- 「Parallel 批量会串位」是 OBS 33.0.1 / obs-websocket 5.7.6 的实测结论；后续 OBS 版本若修复，本版仍保持串行，性能影响仅为本地几次往返。
