# 总纲：体验评估、对策与实施顺序

## 1. 先评估：这些要求实际用起来会怎样？

| 需求 | 用户真实场景 | 现状问题（推断 / 实测） | 体验风险 |
| --- | --- | --- | --- |
| 图标图文不符 | 在导航里找「手机 / 工具箱 / 功能中心」 | 多个入口复用同一几何图形（功能中心与模板、工具箱与搭建都叫 `IconGeomSetup/Templates`） | 图标失去导航价值，用户靠读字 |
| 插件需 GitHub | 国内网络打开插件广场、搜索、安装 | 没有加速器提示；失败后只显示网络错误 | 用户以为软件坏了 |
| 已安装插件不显示 | 装完插件回来看「已安装」 | 只读 `installed.json`，用户用 OBS 自己装的插件完全不可见 | 页面显示「还没有插件」，与事实相反 |
| 手机当摄像头 | 想用手机当第二机位 | 依赖 mediamtx，但清单标记 `manual: true`，没有一键安装；未连接 OBS 时直接失败 | 大多数用户根本无法启动 |
| 虚拟主播模板 | 选模板后直接在 OBS 看到可用排版 | 聊天框与虚拟形象区域重叠；模板数量偏少；缺少竖屏 / 歌回 / 学习等场景 | 落地后需要手工大改，模板价值低 |
| 小窗控制 | 全屏游戏时快速操作 | 只有录制 / 推流 / 虚拟摄像头三个按钮 | 新功能都在主窗口，小窗价值下降 |
| 手机改提词稿 | 手机端着看稿，临时改一句 | 手机只能播放/暂停/调速，不能改内容 | 必须回电脑，打断直播 |
| 指引过期 | 新用户第一次打开 | 文档落款仍是 1.6.0，缺少手机、插件、虚拟直播 | 教会用户错误路径 |
| 全局背景 | 想让软件更像「自己的桌面」 | 壁纸只盖内容区，左侧导航与顶栏仍是实色 | 割裂感明显 |
| X/V 混更 | X 用户检查更新 | 旧逻辑解析所有 tag，X/V 会互相提示 | 装错通道 |

## 2. 定对策（按投入产出排序）

### P0：让「坏掉」的功能重新可用

1. **插件已安装列表合并双数据源**
   - `installed.json`（本应用管理，可卸载/回滚）
   - 本机 OBS 插件扫描（只读，标注「本机检测」）
   - 去重键：规范化安装目录；管理记录优先。
2. **手机摄像头一键媒体服务**
   - `sidecars.json` 的 mediamtx 从 `manual` 改为可校验下载（固定版本 + GitHub 资产 SHA-256 + 体积）。
   - 未连接 OBS 也允许启动媒体服务；连接后再补建来源。
   - 摄像头面板直接给出「安装媒体服务 → 启动 → 手机推流 App → OBS 拉流」四步。
3. **手机提词稿编辑**
   - 新增 `teleprompter.set` 命令（Operator 及以上），长度上限 20,000 字符。
   - 手机端新增多行编辑框 + 保存按钮，保存后电脑端提词器立即刷新。

### P1：让体验「顺手」

4. **插件 GitHub 加速引导**
   - 插件页顶部固定「GitHub 访问引导」卡片：下载 Watt Toolkit（Steam++）→ 开启 GitHub 加速 → 回来重试。
   - 保留「我已知晓 / 不再提示」，但不阻断浏览。
5. **小窗控制重构**
   - 两级布局：常用（录制/推流/虚拟摄像头/重播）＋ 展开面板（场景、音频、提词器、工作室模式）。
   - 所有按钮有明确状态色与失败提示；不新增常驻采样。
6. **虚拟主播模板**
   - 修正重叠坐标；新增歌回、学习陪伴、双人联动、手部机位 4 套。
   - 新增 `vtuber-frame.html` 等透明叠加页，统一视觉语言。

### P2：让产品「像 3.5」

7. **UI 全局背景**
   - 壁纸层从内容区提升到窗口根 Grid，覆盖导航与顶栏。
   - 导航 / 顶栏 / 卡片在图片模式下使用半透明表面；高对比模式保持不透明。
8. **手机连接页 / 功能中心**
   - 手机连接页：状态英雄区 + 分段导航 + 配对卡 + 三步引导。
   - 功能中心：新增「现在能做什么」状态区（OBS / 手机服务 / 摄像头 / 提词器），一键直达。
9. **指引文档**
   - 重写 `troubleshooting.md` / `.en-US.md`，新增「5 分钟上手」。
10. **图标体系**
    - 引入 Tabler Icons（MIT）风格的 24×24 线性几何，替换复用 / 图文不符的入口。
    - X1031 使用全新极简应用图标（`OBS helper` 字标 + 重叠 O 元素）。

## 3. 实施顺序（按范围由小到大）

1. 保存 UI 基线（tag `ui-baseline-v3.4.2`）与文档。
2. 实现共享需求 1–8：图标体系、插件、手机摄像头、模板、小窗、提词器、指引。
3. 实现 X 系列通道 + 新应用图标（需求 9），三轮自检 → 发布 `X1031`。
4. 在 X1031 基础上实现全局 UI 重构、手机连接页与功能中心体验优化。
5. 三轮自检 → 发布 `V3.5.0`（不含新应用图标）。
