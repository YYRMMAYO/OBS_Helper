# V2.7.0 发布说明 —— 录屏与直播工具箱

发布日期：2026-08-24

V2.7.0 基于 2026-08-24 的第二轮网络调研（Reddit r/obs、OBS 官方论坛 / GitHub Issue
#13360 / 32.x 发布说明、2026 年度设置指南、中文社区），聚焦「体检」主题：
把画质（色彩）、音质（采样率）、磁盘吞吐、编码参数、推流节点这五个
「开播 / 开录前最值得核对但最难查」的环节做成一键只读体检。
实施依据见 [`docs/OPTIMIZATION_V2.7.0.md`](docs/OPTIMIZATION_V2.7.0.md)。

## 一、工具箱新增五张体检卡

### 1. 色彩体检
从当前 Profile 只读解析色彩范围 / 色彩空间 / 色彩格式三件套：
命中 Full Range（画面发灰泛白的高发原因）、非 Rec.709 空间或 RGB 格式时
给出警告与修改指引；键缺失按 OBS 默认值处理，不制造虚假告警。

### 2. 音频采样率体检
枚举系统活动音频设备的共享模式采样率（注册表 MMDevices，只读），
与 OBS 设置比对：任一端不是 48kHz 即提示改哪一端——重采样伪影是
音质发闷、爆音与音画漂移的典型根因。枚举失败降级为手动核对指引。

### 3. 磁盘写入基准
向录像目录写入 256MB 临时文件测顺序写速度（测完立即删除），
对照计划码率 × 1.5 冗余给出三档结论。「编码正常但录像卡顿」
多半是磁盘链路，这张卡把它变成可量化的判断。

### 4. 编码顾问
读取显卡型号后直接给出具体参数组合：NVENC 按 RTX 代际分档 P4/P5、
RTX 40 系以上给 AV1 CQP 22 录像方案、AMF/QSV 对应预设；
勾选「边播边录」时叠加双编码 +10~15% GPU 预算提醒与降级顺序。

### 5. 推流节点延迟探测
内置 B站 / Twitch / YouTube 候选入口，支持自定义地址，
并发 TCP 握手测 RTT 并排序。结论中明确提示「ping 低只是必要条件」，
入围节点需实推验证，避免误导。

## 二、浏览器源健康检查清单

告警挂件空白 / 弹幕面板卡住的处理顺序：URL 有效性验证 → 来源刷新 →
CEF 缓存清理（直达 %AppData%\obs-studio 按钮）→ 自定义 Dock 的变通方案。
背景：官方已确认自定义浏览器 Dock 缺少刷新能力（Issue #13360），本卡收录全部可用 workaround。

## 三、问题库扩充 v1.9 → v2.0（140 → 149 条）

按调研结论新增 9 条（拟定清单与既有条目去重后的净增量）：

- **A 组**：浏览器告警挂件失效（widget URL 过期 / 缓存）、自定义 Dock 无法刷新、
  OBS 隐性开销（隐藏来源未关停 / 重复捕获 / 浏览器源数量）、双编码 GPU 预算；
- **B 组**：x264 与 NVENC P1~P7 预设速查、录像 CQP 恒定质量参考值
  （H.264 18~20 / AV1 22）、字幕转写插件方案、推流节点实测选点；
- **C 组**：磁盘写入速度不足导致录制卡顿（HDD / 满盘 SSD）。

所有 `related` 引用均校验为真实条目 id；随包热更新通道照常生效。

## 四、日志分析与录前自检扩展

- 日志规则 +4 条：`LOG-COLOR-RANGE`（Full 范围 → 发灰提示）、
  `LOG-BITRATE-DROP`（动态码率下调 → 上行波动）、`LOG-CAPTURE-CARD`
  （DeckLink 等初始化失败）、`LOG-AUDIO-RESAMPLE`(实时重采样警告)；
- 录前自检新增「关键帧间隔」项：keyint = 0 或 > 4 秒即警告并关联知识库
  （关键帧设 0 会导致观众中途进入长时间模糊）；键缺失按默认处理不告警。

### 升级与兼容性说明

- 全部新功能只读探测或独立 IO 测试：不改任何 OBS 配置与系统设置；
- 磁盘测速临时文件用后即删，异常路径也有 finally 兜底清理；
- 采样率枚举走注册表只读查询，权限受限时自动降级为手动核对指引；
- 问题库热更新通道不变，老版本用户启动后静默获取 v2.0 问题库。
