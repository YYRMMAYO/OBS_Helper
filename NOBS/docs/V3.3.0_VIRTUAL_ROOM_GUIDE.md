# V3.3.0 虚拟直播间模板与素材指引

> 配套主文档：[`PLAN_V3.3.0.md`](PLAN_V3.3.0.md)
> 本文覆盖：房间模板清单、场景/来源设计、6 套可爱画风、SVG/PNG 资产规范、可下载素材索引与许可、应用后使用文档、模板 schema 与验收。
> **已确认（2026-10-25）**：6 套模板与 6 套画风全部纳入 3.3.0 P0。
> **原则**：原创 SVG 优先；下载素材只用明确许可（CC0/CC-BY）；不使用同人图、平台 Logo、Live2D 示例模型或来路不明的“免费素材包”。

---

## 1. 目标

让一个虚拟主播用户能够：

1. 在模板页按“可爱/清爽/深夜/像素/手账”等风格筛选；
2. 预览模板的场景、来源、形象位、所需插件、素材许可；
3. 一键新建场景集合并落地；
4. 按“应用后检查清单”替换形象、麦克风、聊天 widget、BGM；
5. 打开一份中英文使用说明，知道每个场景/源是做什么的。

## 2. 模板清单（6 套）

所有模板都遵循：
- 默认新建场景集合，不覆盖用户现有集合；
- 麦克风/桌面音频跨场景 `shared`，避免重复占用设备；
- 形象位 `role=avatar`，可被 Live2D 一键配置绑定；
- 聊天位 `role=chat`，默认本地占位页，可替换为用户自己的 widget URL；
- 场景切换过渡 300 ms；「减少动画」用户可用 OBS 的 Cut 或模板的 `transition` 覆盖；
- 字体只用系统字体（微软雅黑 / Segoe UI），不打包字体文件。

## 3. 6 套可爱画风（风格索引）

> 每套画风是一组**配色 + 形状语言 + 装饰母题 + 动效**，不是某个角色的同人图。所有角色位都用“原创剪影/占位框”，用户用自己的 Live2D 模型替换。

## 4. 资产清单与规范

### 4.1 每个画风需要的文件

| 类别 | 文件 | 尺寸/格式 | 用途 |
|---|---|---|---|
| 背景 | `bg_main.png` / `bg_brb.png` / `bg_ending.png` | 1920×1080 / 1080×1920，PNG | 场景底图 |
| 边框 | `frame.png` | 同画布，透明 PNG | 全屏装饰 |
| 形象位 | `avatar_placeholder.png` | 900×1080，透明 PNG | 未绑定 Live2D 时的占位剪影 |
| 聊天框 | `chat_panel.png` | 420×600，透明 PNG | 聊天区域底板 |
| 标题/下三分之一 | `lower_third.png` | 900×220，透明 PNG | 标题/社交 |
| 目标条 | `goal_bar.png` / `goal_fill.png` | 600×32，透明 PNG | 目标进度（静态/可被 OBS 文字覆盖） |
| 暂离 | `brb_card.png` | 800×450，透明 PNG | BRB |
| 开播等待 | `starting_card.png` | 1000×600，透明 PNG | Starting Soon |
| 下播 | `ending_card.png` | 1000×600，透明 PNG | Ending |
| 倒计时底板 | `countdown_panel.png` | 400×180，透明 PNG | 倒计时文字底 |
| 装饰 | `deco_*.png` | 64~256 px，透明 PNG | 星星/云朵/花瓣/气泡 |
| 网页 | `web/chat.html`、`web/clock.html` | HTML/CSS/JS | 本地占位/时钟 |
| 许可 | `LICENSES.md` | Markdown | 每个素材的作者/来源/许可证/修改说明 |

### 4.2 画布与安全区

| 场景 | 画布 | 安全边距 | 备注 |
|---|---|---|---|
| 横屏 | 1920×1080 | 四周 60 px | 平台 UI 可能遮挡底部 |
| 竖屏 | 1080×1920 | 左右 48 px，底部 160 px，顶部 120 px | 抖音/视频号 UI 安全区 |
| 聊天框 | 420×600 | 内边距 24 px | 文字行高 1.35 |
| 下三分之一 | 900×220 | 内边距 28 px | 标题/社交 |

### 4.3 对比度与可读性

- 正文文字与底板对比度 ≥ **4.5:1**；大字号（≥ 24 px 粗体/≥ 32 px）≥ **3:1**。
- 不要在浅色花纹上直接压白字；加半透明深色底板（`#000000` 40%~60%）或深色文字。
- 聊天框底板建议 70%~85% 不透明；既保证可读，又不完全挡住背景。
- 状态色（成功/警告/失败）只用于状态，不与装饰色混用；状态必须有文字/图标。
- 提供“高对比版”资产：纯深底/纯浅底 + 高对比文字，作为可选包。

### 4.4 动效

- 只做缓慢、低幅度、可关闭的动效；不做闪烁/快速缩放/强对比切换。
- 页面支持 `?motion=0`（由应用设置/「减少动画」传入）时，CSS 不启动动画。
- OBS 侧不要依赖动画表达信息；静态截图也必须能看懂。
- 动效不得影响文字可读性（不遮字、不闪烁）。

### 4.5 文件命名

```
rooms/<packId>/
  manifest.json
  overlays/bg_main.png
  overlays/frame.png
  overlays/avatar_placeholder.png
  overlays/chat_panel.png
  overlays/lower_third.png
  overlays/goal_bar.png
  overlays/brb_card.png
  overlays/starting_card.png
  overlays/ending_card.png
  overlays/deco_star_01.png
  web/chat.html
  web/clock.html
  LICENSES.md
```

- 只用小写字母/数字/下划线/短横线；不要中文/空格/特殊字符。
- 2x 资产用 `@2x` 后缀；OBS 里优先用 1x/2x 中清晰度足够的一版。
- 不打包字体；需要字体时用系统字体。

## 5. SVG / PNG 生产管线

### 5.1 推荐：原创 SVG 为源，导出 PNG 供 OBS

- `source/*.svg` 保留在仓库/设计源，便于改色/改文案；`export/*.png` 是提交到资产包的成品。
- SVG 只用基本形状/路径/线性渐变；不要嵌入位图/外部字体/脚本。
- PNG 导出要求：
  - 透明背景；
  - sRGB；
  - 横屏 1920×1080 / 竖屏 1080×1920；
  - 单文件 ≤ 2 MB（装饰小图 ≤ 200 KB）；
  - 边缘不留白边/黑边；
  - 文字尽量少（文字用 OBS 文本源，便于用户改）。
- 如果设计工具不能批量导出，使用人工导出 + `manifest.json` 记录尺寸/哈希；**CI 只校验，不在构建时转换 SVG**（避免引入 Inkscape/ImageMagick 依赖）。

### 5.2 为什么不在运行时把 SVG 转 PNG

- .NET/WPF 没有内置 SVG 渲染器；引入第三方库违背零依赖。
- OBS `image_source` 对 SVG 支持不稳定；`browser_source` 可以渲染 SVG，但会增加浏览器源数量。
- 构建时调用外部工具（Inkscape/ImageMagick）会让 CI/开发机依赖不可控。
- 结论：**设计时导出 PNG，仓库提交成品 + 源文件**；运行时只读 PNG/HTML。

### 5.3 可选：用 OBS browser source 渲染 SVG

如果某个装饰必须矢量缩放，可把它放进本地 `web/` 页面，用 `browser_source` 渲染；但：
- 每个 browser source 都有 CEF 开销；
- 透明/缩放/性能要实测；
- 不作为默认方案。

## 6. 可下载素材索引与许可

> 下面的站点/资源只作为**设计参考/素材来源**。下载前必须逐个核对许可证；不要把“免费”当成“可商用/可再分发”。

### 6.1 推荐来源

| 来源 | 典型许可 | 适合 | 注意 |
|---|---|---|---|
| **Kenney.nl** `https://kenney.nl/assets` | CC0 | UI 边框、按钮、游戏图标、像素素材 | 确认具体 pack 的 LICENSE；CC0 也要保留来源记录 |
| **OpenGameArt** `https://opengameart.org/` | CC0 / CC-BY / CC-BY-SA 等 | 背景、装饰、像素 | 逐个看 License；CC-BY 需署名；SA 可能传染 |
| **SVG Repo** `https://www.svgrepo.com/` | 每个图标不同（CC0/MIT/商业） | 图标、简单形状 | 必须打开单个图标页面确认；不要整站抓取 |
| **unDraw** `https://undraw.co/` | 开源许可（以官网为准） | 扁平插画、空状态 | 可改色；保留许可说明 |
| **Coolors** `https://coolors.co/` | 工具（配色） | 配色灵感 | 不产生素材版权 |
| **Google Fonts** `https://fonts.google.com/` | OFL 等 | 字体参考 | **不打包字体**；用系统字体 |
| **Unsplash/Pexels** | 各自许可 | 照片背景 | 不用于“可爱插画”；注意人物/商标 |

### 6.2 不推荐/禁止

- **同人图/动漫角色截图**：即使“免费”也不能作为产品资产再分发。
- **Live2D 官方示例模型**（如 Hiyori/Mao 等）：有使用限制；不作为模板内置模型。
- **平台 Logo/品牌素材**：抖音/B 站/YouTube 等 Logo 是商标；未经许可不要打包；用文字/通用图标代替。
- **“免费素材站”的打包下载**：来源/许可证不清，容易混入盗图/恶意文件。
- **AI 生成且来源不明的图**：版权状态不清；如使用，必须记录生成工具/日期/人工修改，并做法律评审。
- **需要署名但未署名的 CC-BY 素材**：不合规。

### 6.3 素材登记模板

每个资产包附 `LICENSES.md`：

```markdown
# 素材许可

## cream-cloud
- 背景/边框/装饰：原创，MIT（本仓库）
- 云朵图标：Kenney UI Pack, CC0, https://kenney.nl/assets/ui-pack, 下载日期 2026-10-25, 未修改
- 字体：系统字体（微软雅黑/Segoe UI），未打包
- 备注：所有 PNG 由 source/*.svg 导出；未使用第三方角色图
```

### 7.3 落地器改动

`SceneTemplateService`：
- 在 `CreateSourceWithFallbackAsync` 前解析 `Asset` → 绝对路径（`RoomAssetService.Resolve`）；
- 对 `Browser`，把 `page` 替换为 `RoomOverlayServer` 的 URL；
- 对 `role` 不做自动绑定（由 Live2D/检查清单处理），只保留元数据；
- 资产缺失 → 记入占位清单，不阻断其它源；
- 资产校验失败 → 整个模板应用失败并回滚（或跳过该源 + 明确提示，推荐后者）。

`RoomAssetService`：
- 解压内嵌 zip 到版本目录；
- 校验 manifest/hash/尺寸；
- 防 zip slip；
- 提供 `Resolve(templateId, version, relativePath)`，返回绝对路径并二次确认在版本目录内；
- 清理旧版本（保留当前 + 上一版）。

`RoomOverlayServer`：
- `TcpListener(IPAddress.Loopback, 0)` 随机端口；
- 只服务当前房间版本目录下的 `web/` 与允许的静态资源；
- URL 带随机 token；
- 只允许 GET/HEAD；
- 设置 `Content-Type`/`Cache-Control`/`CSP`/`X-Content-Type-Options`；
- 关闭时释放端口；OBS 源重启后重新设置 URL。

## 9. 用户使用文档（中文草稿）

> 这份草稿用于产品内 `MarkdownView` 或帮助页；英文版按同结构翻译。

### 9.1 虚拟直播间是什么

虚拟直播间是一套已经搭好的 OBS 场景：背景、边框、形象位、聊天框、标题、BGM 通道都放好了。你只需要把自己的 Live2D 形象、麦克风、聊天组件放进去。

### 9.2 应用模板

1. 打开「虚拟直播 → 直播间」。
2. 选一个风格（奶油云朵/樱花糖果/薄荷汽水/深夜电台/像素游戏/手账贴纸）。
3. 选一个模板（杂谈/游戏/电台/纪念回/竖屏/三件套）。
4. 点「应用」；默认会新建一个 OBS 场景集合，不会覆盖你现在的场景。
5. 应用完成后，按检查清单逐项处理。

### 9.3 绑定 Live2D 形象

1. 点「绑定形象」→「Live2D 一键配置」。
2. 选择你的 `.model3.json` 或模型目录。
3. 按提示在 VTube Studio 内允许本应用访问 API。
4. 选择布局（全身/半身/右下角/左侧）。
5. 完成后回到 OBS，形象应该已经在“虚拟形象”源里。

### 9.4 麦克风与桌面音频

- 「我的麦克风」：选你的麦克风；说话时 OBS 音量条应该动。
- 「桌面音频」：选系统声音/游戏声音；如果不需要可以静音。
- 如果使用 VTube Studio 面捕，OBS 仍然直接采麦克风；不要从 VTS 再采一路，否则会双声。

### 9.5 聊天框/弹幕

模板里的聊天框默认是占位页，显示“请粘贴你的聊天 widget URL”。你可以：
- 用你常用的直播聊天 widget 服务，复制它的浏览器源 URL；
- 在 OBS 里选中「聊天框」→ 属性 → 粘贴 URL；
- 或在应用的检查清单里点「设置聊天框」粘贴。
应用不会读取你的平台账号，也不会代理聊天请求。

### 9.6 常见问题

**Q：应用后画面是黑的？**
A：先看“虚拟形象”源是否可见、是否被边框/背景挡住；再检查 Live2D 采集方式（NDI/Spout/虚拟摄像头/窗口）。黑屏时点「检查形象」会给出具体原因。

**Q：形象没有透明背景？**
A：优先用 NDI/Spout2；如果只能用窗口采集，把 VTS 背景设成纯绿/纯蓝，再加色键。窗口采集的透明支持取决于 Windows/OBS 版本，不保证 100%。

**Q：聊天框是空的？**
A：默认是占位页；需要你粘贴自己的聊天 widget URL。应用不提供平台账号登录。

**Q：可以商用吗？**
A：模板/原创素材的许可见 `LICENSES.md`；你使用的 Live2D 模型、字体、聊天 widget、BGM 由你自行确认授权。

### 9.7 English outline

- What a virtual room template is.
- Apply a template (new scene collection by default).
- Bind your Live2D avatar (VTube Studio integration).
- Select microphone/desktop audio.
- Replace the chat placeholder with your own widget URL.
- Troubleshooting: black screen, no transparency, empty chat.
- Licensing: templates/assets vs your model/music/widgets.
