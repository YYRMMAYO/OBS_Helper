# V2.9.4 代码审校记录（三轮）

> **关于「独立」二字**：这三轮由同一批执行方按**不同视角**分轮进行，不是三个互相不知道对方结论的人。
> 因此这里对每条结论都标注了**证据类型**：
> `[机器]` = 有单测 / 构建 / 脚本等可复现证据；`[人工]` = 只能靠对读与推理，结论强度弱于前者。
> 真正意义的独立复核（换人换实现）不在本次范围内，不作宣称。
>
> **另一个必须写明的边界**：审校期间实现仍在写入（三个写手 + Lead 并行）。
> 每轮都以「当时磁盘上的版本」为基线，并在报告里记录了 mtime/hash；
> 最终以**冻结后重跑的全量测试 + Headless 自检**为准（见文末「冻结后的机器证据」）。

审校范围：V2.9.4 的全部改动 —— 简单录像（预设 / 就绪判定 / 双通道落地 / 拉起 OBS / 录制中信息 /
停止收尾 / 跨会话回滚）、帮助与反馈页、仓库封面与社区文件、文案与文档同步。

三轮视角：

1. **数据安全与用户配置写入** —— 「这个版本会不会改坏用户的东西，或把用户带到不该去的地方」
2. **双目标构建边界 + 线程 / 生命周期 / 资源泄漏** —— 「兼容构建会不会悄悄降低能力，新加的状态会不会跨线程出事」
3. **交互与文案一致性 + 文档与事实一致性 + 测试有效性** —— 「用户看到的字对不对，文档说的和代码做的是不是一回事」

## 二、逐项核对通过的部分（凭什么通过）

### 2.1 写用户配置的路径是安全的 `[机器]` + `[人工]`

- 4 条写入路径**全部先整备份**，且备份失败在写盘前 `return`，**没有「备份失败还继续写」的分支** `[人工]`；
- 文件通道写后**重新读回逐项校验**（新版按 target 逐个查）；写前落同目录 `.obshelper.bak` `[人工]`；
- 回滚表按 `(Category, Parameter)` 记旧值并原样写回 `[人工]`；
- `RecordingEnvCoreTests` 覆盖 INI 打补丁的保真性：同节同名才替换、注释行不动、跨节同名键不受影响、
  CRLF 行尾保留、补丁后一定能读回目标值 `[机器]`。

### 2.2 没有静默改写 `[人工]`

- 所有 `SetProfileParameter` 调用点都来自 UI 事件（部署卡 / 简单录像卡 / 回滚按钮）；
  就绪检查、快照读取、计划构建都是纯读 `[人工]`；
- **拉起 OBS 前会弹确认**，且服务层的确认回调**未注入时按「不允许」处理** ——
  在自检 / 后台这类没有界面的路径上不会悄悄替用户启动别的程序 `[人工]`；
- 找不到 OBS 可执行文件时**不做任何 `Process.Start`**，只提示用户自己启动 `[人工]`。

### 2.3 出站白名单 `[机器]`

- `IsTrustedFeedbackUrl` 只放行 https + `docs.qq.com` / 本仓库路径 / **作者账户主页（精确前缀）**；
  同前缀仿冒域（`github.com.evil.example`、`github.com/YYRMMAYOEvil`）、`http://`、异域全部拒绝；
- 反馈表单地址与二维码内容被单测钉成同一个常量，防止二者漂移 `[机器]`。

### 2.4 双目标与线程生命周期 `[人工]` + `[机器]`

- 全仓扫描 .NET 7+ 独有 API（`Enum.IsDefined<T>`、`TimeProvider`、`SearchValues`、集合表达式…）→ **0 命中** `[机器]`；
  `Enum.IsDefined(id)` 用的是**非泛型**重载（net6 可用）；
- 两个 TFM 均编译通过 `[机器]`；
- `SimpleRecordingService.Dispose` 被 `ShutdownServices` 调用（有 `IsValueCreated` 守卫），
  `Dispose` 先停计时器再置空；卡片订阅 / 退订对称，`Detach` 确实被 `OnNavigatedFromAsync` 调用 `[人工]`；
- 预设按钮的事件挂在对象初始化器**之后**，因此重建不会触发多余的服务写入 `[人工]`。

### 2.5 文案表与调用点 `[机器]`

- 中英两表**各 1852 条、键集完全一致**、无重复键、无空值、英文侧无汉字与全角标点、占位符逐键一致；
- `scripts/check_resources.py`：33 个 XAML / 1505 处引用全部可解析；
- 新增的 `StringsCallSiteTests` 静态扫描全部字面量调用点，断言「键存在」与「占位符个数 == 实参个数」；
- **已闭环的真实缺陷**：`simple.state.stopping`、`main.watchedMore`、`log.summary.itemFromKbTail`
  三个键缺失；`env.writeFailed` 的异常原因被静默丢弃（少传占位符）。

### 2.6 测试本身的有效性 `[人工]`

三轮都没有发现「断言恒真」「把实现抄一遍再断言」的假测试：

- `SimpleRecordingCoreTests` 刻意构造**偏离默认值**的输入（如 `fps: 144`、`splitSeconds: 300`），
  阻断原因的断言用「不可能出现在文案表里的串」验**透传**而不是验具体文案；
- `ObsLaunchCoreTests` 用**注入的存在性谓词 + 幽灵路径**断言实现没有自己去探测磁盘；
- 调用点体检测试带「扫描到的调用数 > 300」的最低量护栏，防止正则失效后静默全绿。

### ⚠️ 未验证项（如实声明，不宣称已验证）

1. **预设取值对真实 OBS 的落地效果**：`HQ` / `hybrid_mp4` / `RecSplitFile*` / `RecTracks`
   这些取值只做到「协议与键名正确 + 纯逻辑单测」，**没有在真实 OBS 上点过一次并核对设置界面**；
2. **「文件通道落地 → 拉起 OBS → 等就绪 → 自动开录」的端到端链路**：超时（75s）、轮询间隔（1s）、

3. **便携版 / 绿色解压版 OBS 的路径识别**：只认注册表 `DisplayIcon` 与常见安装目录，
   找不到时不猜路径；实际覆盖率**未实测**；
4. **剩余可录时长是估算**（预设码率 × 1.5 冗余），不是实测写入速率，真实码率随画面内容波动；
5. **回滚把原本不存在的键写成空值**后 OBS 的行为（S3）**未验证**。
