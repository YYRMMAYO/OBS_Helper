## 1. 数据安全：三个「会丢东西」的缺陷

### 1.1 文件事务回滚不再删除唯一的恢复副本 ★

`Services/ObsConfig/FileTx.cs` 的回滚原先在「恢复失败」后仍然删除回收副本，
而 `StageMove` 早已把原文件从原位删掉 —— 那份副本就是**唯一**一份。
导入备份 / 彻底重置中途失败（文件被 OBS、杀软或资源管理器占用）时，
用户的全部场景集合与 profile 会永久丢失；注释写着「留待人工处理」，下一行却把要留的东西删了。

现在：恢复失败时**保留副本**、记入 `RollbackFailures`，只有全部恢复成功才清理事务目录；
`HasRetainedRecoveryCopies` 供上层提示。回归测试见 `FileTxTests`（含「部分失败」与「Dispose 未提交」两条路径）。

### 1.2 路径护栏真正覆盖所有写 `basic.ini` 的入口

原先写 `basic.ini` 的三处（一键部署、回滚、简单录像）**全部不过** `ObsSafePath`，
而写入路径来自 `global.ini` 的 `basic.profiledir` —— 这个值可以被「导入备份包」整份改写：

- `Path.Combine` 遇到根化段会丢弃前缀：`profileDir = C:\Windows\System32` → 写到系统目录；
- `profileDir = ..\..\..\..` → 逃出配置目录。

现在：
- `ObsSafePath.SafeProfileDir()` 把该值净化成**单个目录名**（根化与 `..` 从源头消失）；
- 解析后再次断言落在配置目录之内；
- 新增 `SafeIniFile.Write()`：**先过护栏 → 留 `.obshelper.bak` → 同目录临时文件 → 原子替换**，
  三处写入统一走它（写一半断电不再留半截 ini）。

### 1.3 路径护栏的可信根改为「登记制」

闸 3 原先只按「目录名是不是 `obs-studio`」判定，两头都不安全：
手动指定的非该名目录 → 彻底重置必被拒（功能不可用）；恰好叫 `obs-studio` 的任意目录 → 放行。
现在由 `ObsPathService` 在定位成功时**登记**可信根（自动探测或用户手动确认），护栏按登记判定。

### 1.4 机密存储读失败不再被当成「空存储」

`HostBridge.LoadSecrets` 原先把任何异常都吞成空字典，而调用方会拿这份字典**整份覆盖写回** ——
「杀软临时占用 `secrets.dat`」这种瞬时故障会变成：用户改一次 API Key，
OBS WebSocket 密码与其它密钥一起被静默清空，界面还显示「已保存」。
现在只有「文件不存在 / 空文件」才返回空字典，读取失败一律抛出并由调用方如实返回失败；
写入 / 读取 / 删除失败都落日志。

### 1.5 其它可靠性修复

| 修复 | 位置 | 说明 |
|---|---|---|
| 重连额度不再被双扣 | `ObsConnectionService.OnClosed` | 握手失败时接收循环结束也会广播 `Closed`，而失败分支已排过一次重连 → `MaxAttempts = 8` 实际约 4 次就放弃。现在只有「已建立会话」的断开才排重连 |
| `LocalStore` 损坏留痕 | `Services/Host/LocalStore.cs` | 原先静默重置为空，随后一次写入就用空字典覆盖整份 prefs.json。现在另存 `*.corrupt` + 落日志 |
| 回滚也要先整备份 + 读回校验 | `RecordingEnvService.RollbackAsync` | 回滚原先是唯一「无备份、无读回校验」的写盘路径 |
| 危险确认框默认按钮改「取消」 | `Controls/ConfirmDialog.xaml.cs` | 原先确认按钮是 `IsDefault`，而「彻底重置」是**连续两个**危险确认 —— 连按两下回车就完成了不可撤销的操作 |
| 崩溃时日志不再丢 | `App.xaml.cs` / `FileLogger` | 致命异常处理器里补 `Flush()`；日志开头写「版本 / 构建 / 系统 / PID / 数据目录」；异常递归展开 `InnerException`（原先根因丢失） |
| 连接失败与「从未连接」可区分 | `Controls/ConnectionBadge.xaml.cs` | 通用失败原先置 `Disconnected`，徽章只在 `Failed` 时显示原因 → 全产品最高频任务失败后无任何提示 |
| 热键 / 小窗 / 后台刷新不再静默 | `GlobalHotkeyService` / `MiniControlWindow` / `ObsConnectionService.FireAndForget` | 分别补可见提示与日志 |
| 导出包脱敏失败不再原样打包密钥 | `ObsBackupService.AddServiceJsonRedacted` | 原先脱敏失败会 `AddFileRaw` 原样打包 `service.json`（含流密钥），而 manifest 仍标「已脱敏」；现在退化为**不含密钥的占位条目** |

## 2. 安全与隐私

- **日志脱敏补四类漏点**（`LogSanitizer`）：SRT `passphrase`（10~23 字符的短口令原先既躲过键值规则又躲过长串规则）、
  **公网 IPv6**（原先只有 IPv4 规则）、**标准 Base64 令牌**（字符集排除 `+/=` 会被拆碎）、
  **`Authorization: Bearer <jwt>`**（`bearer` 后是空格，键值规则匹配不上）。
- **外链拒绝本机 / 内网**（`HostBridge.OpenExternalAsync`）：知识库、插件目录、排障指引都经热更新通道下发，
  链接属于外部数据 —— 一条 `http://127.0.0.1:…` 或内网地址足够把用户引到内网设备管理页。
  现在与出站请求同口径（仅 http/https + 拒绝私网），失败落日志。
- **`WHEN`：仍待办** —— 发布物 Authenticode 签名、更新包哈希校验（见下文「已知边界」）。

## 3. 无障碍（详见 [`../ACCESSIBILITY.md`](../ACCESSIBILITY.md)）

- **键盘焦点可见**：`SegmentButton`、`AppComboBox`、`ComboBoxItem` 补 `IsKeyboardFocused` 触发器 ——
  原先这三个控件只有鼠标悬停态，而它们恰好是「语言 / 主题 / 字号 / 录像预设」这些纯键盘最容易迷路的控件。
  段控件的「选中 + 聚焦」用 `MultiTrigger` 单独处理，避免焦点框被品牌底色吞掉。
- **屏幕阅读器实时区域**：`ToastCard` 声明 `AutomationProperties.LiveSetting="Assertive"` ——
  「已连接 OBS」「开录失败」这类提示不需要焦点，实时区域是它们能被播报的唯一途径。
- **跟随 Windows 高对比主题**：原先只认应用内开关，系统级高对比用户得不到应有的配色；
  现在 `HighContrastEffective = 应用内开关 OR 系统高对比`，并监听系统变更实时重刷。
- **跟随系统「文本大小」**：应用内档位最大 1.28×（低视力用户常常不够），
  现在再乘一次系统缩放系数（注册表 `HKCU\…\Accessibility\TextScaleFactor`，钳 1.0~2.0）。
- **危险确认框的初始键盘焦点**落在「取消」上。

## 4. Windows 7 兼容构建：支持旧协议 obs-websocket 4.x

**背景**：obs-websocket 5.x 是随 OBS 28 一起内置的，OBS 28 起不再支持 Windows 7/8.1。
也就是说 Win7 用户能用的最新 OBS 是 27.x，只能配 **obs-websocket 4.9.x 插件**（默认端口 **4444**）。
本工具此前只讲 v5 协议，于是**兼容构建在 Win7 上根本连不上 OBS**，只剩离线知识库那一半能力。

**本版做法（部分兼容，不假装支持不存在的请求）**：

| 层次 | 做法 |
|---|---|
| 协议判定 | v5 服务端连上就推 `Hello`；v4 什么都不说。因此先给 900ms 窗口等 Hello，没等到就按 v4 主动发 `GetAuthRequired`。**该逻辑只在兼容构建启用**，主构建路径与改造前等价 |
| 鉴权 | v4 算法：`base64(sha256(base64(sha256(password + salt)) + challenge))` |
| 请求翻译 | v5 请求名/字段 → v4 等价物（如 `GetRecordStatus`→`GetRecordingStatus`、`SetSceneItemEnabled`→`SetSceneItemRender`、`GetVolume/SetVolume` 用倍率而非 dB） |
| 响应归一化 | v4 响应**归一化回 v5 形状**，因此 `ObsConnectionService` 与各页面**一行都不用改** |
| 事件映射 | `SwitchScenes`→`CurrentProgramSceneChanged`、`SourceMuteStateChanged`→`InputMuteStateChanged` 等 |
| 批量 | v5 `CallBatch` → v4 `ExecuteBatch` |
| 场景来源可见性 | v4 的 `GetSceneItemList` 不返回 `visible`，用一次 `ExecuteBatch` 的 `GetSceneItemProperties` 补齐 |
| 明确不支持 | `SetProfileParameter`（v4 无此 API）→ **录制环境落地改走文件通道**（原本就有整备份 / 读回 / 回滚）；`SetVideoSettings`、`SetSceneItemIndex`、`SetSceneItemTransform` 亦不假装支持 |
| 简单录像 | 旧协议下跳过「在线改配置」这一步直接开录，并在界面说明（录制本身完全可用） |

**独立的数据目录**：兼容构建使用 `%LocalAppData%\OBS_Helper_Win7`（主构建仍是 `OBS_Helper`，刻意一字不改）。
两代构建面向的系统与 OBS 代次完全不同（设置、端口、缓存、待回滚记录都不一样），
共用一份 `prefs.json` 会让「在 Win7 机器上连过 4444 的配置被带到 Win10 机器上」互相打架。

**默认端口按构建区分**：兼容构建 **4444**（v4 插件默认），主构建 **4455**（v5 默认）。

**测试**：`ObsLegacyV4CoreTests` 59 项 —— 鉴权算式、端口分叉、请求映射表、不支持请求必须返回 `null`、
单位换算往返、响应归一化（含场景顺序反转）、事件映射、不影响时间戳前缀的回归护栏。

## 5. 新功能

### 5.1 回放缓存一键存片（托盘 + 全局热键 + 设置页）

OBS 的回放缓存（Replay Buffer）在内存里滚动保留最近一段画面，一键即可把「刚才那段」落盘 ——
这是直播里存精彩片段的通用做法，而 obs-websocket 本身就有这个能力，本工具此前**一处未用**。

现在：托盘菜单新增「保存回放（存刚才那段）」与「开启 / 关闭回放缓存」两项（未在缓存时存片按钮自动禁用），
设置页新增「存片（回放缓存）」热键（默认 `Ctrl+Alt+V`，可改可关），
存片成功后托盘气泡给出文件名（旧协议不返回路径时如实说明）。
旧协议（4.x）同样支持 `StartReplayBuffer` / `SaveReplayBuffer`。

### 5.2 简单开播（首页一键，先查清楚再按）

对新手来说，「开始推流」按下去没反应的头号原因是 **OBS 里的推流服务没填全**（服务器或串流密钥为空），
而 OBS 自己的提示很短、一闪而过。首页新增「简单开播」卡：按之前就把这件事查清楚，
并把会影响直播的风险提前说出来。

- 判定顺序即用户的心智顺序：**已经在播 → 没连上 OBS → 没填服务器 → 没填串流密钥 → 可以开播**；
- 「读不到推流设置」（旧协议 / 权限）与「没配置」给**不同**的文案 —— 否则用户会按错的提示去排查；
- 风险只提醒、不阻断：上行拥塞、已在下行丢帧、正在同时录制；
- 可选「开播时同时本地录制」；
- **不声称「已开播」直到 OBS 确认**：`StartStream` 只是「命令被接受」，真正的 `outputActive`
  会稍后才翻转，本服务轮询确认（最多 8 秒）后才改状态 —— 不确认就显示「已开播」，
  会在其实没播出去的时候让用户以为在播；
- 开始后显示实时指标：**已播时长 · 推流码率（按已发送字节实测）· 丢帧率 · 重连状态**；
- **推流密钥不进本应用**：读设置时只把响应归约成「填没填服务器 / 填没填密钥」两个布尔，
  密钥本身不存字段、不写日志、不进界面状态（旧协议的映射阶段就丢掉了密钥）。

### 5.3 录制档案 + 收尾流水线（含录制中打点）

现状问题：录制产物只留一个**单值**（`LastRecordFile`），下一轮即被覆盖 —— 没有历史、没有清单，
用户想知道「刚才那次录了多久、有多大、是不是空的」只能自己翻目录。而 **OBS 官方至今没有
「录制中标记精彩瞬间」的能力**（issue #13567），只能事后靠时间戳回忆。

现在：

- **录制档案**（`LocalStore` 的 `recording_archive`，上限 200 条）：每次停止写一条 —
  开始时间、时长（用 OBS 自报 timecode，**暂停不计入**）、大小、路径、丢帧率、是否分段、打点；
- **控制台「最近录制」列表**：一眼看出哪次是空文件 / 过小 / 文件已不在（健康度三档 + 警告色），
  并给出快捷动作：打开目录 / 转 MP4 / 导出章节 / 按规则重命名；
- **录制中打点**：托盘菜单「打点（标记精彩瞬间）」或全局热键 `Ctrl+Alt+K`（设置页可改可关），
  每次打点即时气泡反馈位置；**2 秒内的重复打点自动合并**（热键很容易连按两下）；
- **停止后导出章节**：生成 `<文件名>.ffmetadata`（给 ffmpeg 用）与 `<文件名>.chapters.txt`
  （可直接贴到视频简介）—— 打点数为 0 时不生成空文件；
- **批量转 MP4**：复用既有 ffmpeg 重封装（`-c copy`，**不重编码**，几十 GB 的录像几秒完成）；
  有打点的录像会走 `-map_metadata 1` 把章节**写进 MP4**，并由集成测试钉住参数形状。

> 已知边界：这版只做「健康度三档」的轻量完整性判定（0 字节 / 过小 / 文件不在），
> 没有做逐帧/容器级的完整性校验（提案里提到的「文件完整性快检」更深的那一层）。

### 5.4 配置回收站：看得到、认得出、放得回去

本产品对 OBS 配置「永不硬删」：每次移动或覆盖前都会在
`%LocalAppData%\OBS_Helper\trash\tx_*` 留一份恢复副本。但这些副本此前**只有写、没有读** ——
用户根本看不到它们，出了事也无从下手（对抗式审查两次指出这一点）。

现在在「OBS 配置」页新增**配置回收站**：
- 按时间倒序列出每一组副本（时间 / 文件数 / 体积），被锁定（回滚未竟）的组给出明确标记；
- `FileTx` 新增 `restore-manifest.json` 记录「副本 ← 原始路径」，因此每一组都能**一键放回原位**；
- 恢复**绝不覆盖**已存在的文件：原位有新文件时改放到旁边（`名字.restored`）并**逐条**说明去了哪里；
- 恢复写入同样要过 `ObsSafePath` 护栏（只允许落回受信任的 OBS 配置目录）；
- V3.0 之前产生的旧事务目录没有对应表，界面如实说明并退化为「打开所在文件夹」手工取用；
- 带 `.obshelper-retained` 标记的组**永远不会被自动清理**（`CleanupTrash` 会跳过）。

### 5.5 自检清单按本机实测回填

诊断页那 8 条自检清单此前全靠用户自己勾 —— 而其中 6~7 条本机就能判定，
等于把可以自动化的排查手工化。现在清单区新增「按本机实测回填」：

| 清单项 | 本机判据 |
|---|---|
| ① 管理员权限 | 当前进程是否以管理员运行（`WindowsPrincipal`） |
| ② 硬件编码 | 读当前 Profile 的 `basic.ini` 编码器键，识别 NVENC / AMF / QSV / Apple 等 |
| ③ 码率 ≤ 上行 75% | 码率取 `basic.ini`，上行取用户在工具箱填写的值 |
| ④ 捕获方式与双显卡 | 显卡数量 + `obs64.exe` 的 GPU 首选项（只读注册表） |
| ⑤ 48kHz | `basic.ini` 的 `[Audio] SampleRate` |
| ⑥ 冲突软件硬件加速 | `ConflictScannerCore` 扫当前进程 |
| ⑦ 有线网络与丢帧 | 网卡默认网关 + OBS 实时丢帧率 |
| ⑧ 服务器与串流密钥 | 既有的「只判存在性」推流设置读取 |

**三态是本功能的全部价值**：通过 / 需注意 / **无法判定**。判成「需注意」要给出具体数字与建议线；
判成「无法判定」要说明**为什么**（例如「本机还没填过上行速度 —— 先去工具箱填一次」）。
把「不知道」蒙成通过是撒谎，蒙成失败是冤枉用户 —— 两者都会让清单失去意义。因此核心逻辑
（`ChecklistAutoFillCore`）是纯函数，30 项单测覆盖，其中专门有一条断言「完全没有证据时八条全为无法判定」。

> 与之配套的「开播前体检」见下面 5.6：它把同样的检查合成**一句结论**，并给出可落地的录制档位。
### 5.6 开播前体检 + 一键处方

黑屏体检、编码顾问、带宽计算、磁盘测速、节点探测**各自都是一页**，用户要跑五遍才知道
「我这台机器到底行不行」。诊断页新增「开播前体检」：一次跑完全部只读探测，
按**严重度**排好并给一句人话结论。

- **阻塞项**（必须先解决）：录制盘写入速度达不到当前码率、剩余空间不足 20 GB；
- **建议项**：Game DVR 开着、多显卡没设 obs64.exe 的 GPU 偏好、在用电池、节能电源计划、
  软件编码、码率超上行 75%、到节点延迟 > 150 ms、录制格式不是 MKV/分片 MP4、采样率不是 48 kHz；
- **可落地的一键处方**：给出建议的录制档位（硬件编码 + 磁盘够快 → 60fps 游戏档；
  软件编码或磁盘吃紧 → 30fps 会议档），并复用「简单录像」既有的**备份 + 回滚**链路落地
  （只写录制侧，落地前后都不开始录制）；
- **边界（提案原文）**：**推流侧只给建议，绝不自动改** —— 推流参数与平台/网络强相关，
  自动改的风险远大于收益。

两条克制之处写进了单测：① **有阻塞项时不给档位建议**（先解决问题，别建议往坏盘上录）；
② **完全没有证据时不报警、不建议**（`MachineProfileCore` 在信息不足时只输出「读不到」的信息项）。

顺带把磁盘实测逻辑从工具箱**页面**搬进服务层（`DiskBenchmarkService`）：
原先「开播前体检」要用它就得反向依赖一个 View，分层不对也测不了；现在两处共用一份实现，口径不会漂移。
### 5.7 本次会话复盘

现状问题：实时预警只在**首次**命中时弹一条托盘气泡（90 秒抑制 + 每小时限流），
于是「今晚一共被提醒了哪些问题、哪一类反复出现、这场比上场差在哪」在事后完全无从回答 ——
而这三个问题恰恰是主播复盘时最想知道的。

现在日志页顶部新增复盘卡片：

- **`LogTailerService.SessionHits`**：按规则码累计本次会话的命中次数与首末时间。
  关键取舍：**每次命中都记，不受预警节流影响** —— 节流是「别打扰用户」，复盘要的是真实频次，
  两者目的不同，不能共用一个计数；只统计警告及以上，与实时通道同一口径（把 info 级计进来只会变成噪音）；
- **一句话结论**：命中几类、共几次，并与上次会话比较（多/少 N 次）；
- **命中明细**：按次数降序，带规则说明与**该问题自带的修复建议**（不另起一套话术）；
- **跨会话比较**：点「结束本次统计并清零」会把当前结果存为「上次会话」，下次进来就能看出变化；
- **可导出 Markdown**：复用诊断报告的标题风格，同一套报告在用户眼里应该长得一样。

实现细节：命中变化**每个轮询周期最多通知一次**（一批日志可能命中几十行，
逐行触发会让界面重建几十次）；页面订阅在离开时退订（本页 `CanReleaseOnLeave`，
不退订会订在已死的实例上 —— 这是本项目刚清理过的那类泄漏）。
### 5.8 搜索增强（拼音首字母 / 同义词 / 字段加权 / 无结果建议）

现状问题：搜索与助手都只做**子串包含**（拼成一大串后 `Contains`），于是
拼音首字母（`hp` → 黑屏）零结果、「落帧」查不到「掉帧」、带空格的多词查询整串匹配失败。

| 改法 | 实现 |

| ③ 字段加权排序 | 标题 12 &gt; 别名 9 &gt; 症状 6 &gt; 原因 4 &gt; 步骤 3 &gt; 分类 2 &gt; 提示 1；标题**恰好等于**查询词再给 25 分（否则「黑屏且花屏」会压过标题就叫「黑屏」的那条） |

搜索页与助手现在**共用同一套检索核心**（过去同一句话在两处的结果可能不一致）。
另加了 18 项**基于真实知识库**（212 条）的端到端测试，其中包括：

- `hp` 必须查到黑屏条目、`落帧` 必须查到掉帧条目；
- **只出现在别名里**的词（「沙沙声」）必须能查到对应条目 —— 这条专门验证数据侧别名真的生效；
- 每一条问题都必须能被**自己的标题**搜到（「搜得到自己」是最低要求）。

`Services/Search/SearchQueryCore.cs`，`Services/ProblemService.cs`，`Services/AssistantService.cs`，`Views/SearchPage.xaml(.cs)`，`Assets/problems.json`
### 5.9 插件 × OBS 版本兼容性 + 语言注册表

**① 插件目录新增「与本机 OBS 版本兼容性」一维**（D9）

OBS 每次大版本都会让一批插件**悄悄失效**（面板不显示、捕获源消失），而用户完全不知道原因 ——
此前只能靠问题库条目事后接。现在插件目录多了可选字段 `obsCompat`（走既有热更新通道，纯数据改动），
插件广场在**装之前**就提示：

| 声明 | 含义 |
|---|---|
| `30+` | 30 及以上 |
| `28-32` | 28 到 32（含两端） |
| `!33` | 明确**不**兼容主版本 33 |
| `30+,!33` | 逗号组合，全部条件都要满足 |

两条克制之处写进了单测：**读不懂的声明一律判「未知」**（不猜），**本机版本读不到时也判「未知」**
（宁可什么都不说，也不要给用户一个假的「不兼容」警告）——给能用的插件打黄标会直接让用户不敢装。
已按插件自身文档为本产品 Dock 插件标注 `30-32`（`PRNOBS/ARCHITECTURE_PLUGIN.md` 写明兼容 30.x～32.x）。

**② 语言从「两语言硬编码」改为注册表驱动**（D9）

在 `LanguageRegistry` 出现之前，语言在**两处**硬编码：`Strings.Table(language)` 的三元判断与
`ContentAssets.IsEnglish(language)`。于是「加第三种语言」并不是纯数据成本 —— 还得改这两处，
而且漏改会**静默走错分支**（例如繁体用户拿到简体文案）。现在：

- 新增 `LanguageRegistry`（纯 BCL）：语言的标识 / 展示名 / 内容资产后缀 / 文案表 / 归一化别名集中一处；
- `Strings.Normalize`、`Strings.Table`、`Strings.DisplayName`、`ContentAssets.SuffixedFileName` 全部改为注册表驱动；
- 加一门语言的清单收敛为三步：**写表 → 注册一行 → 并列一份内容资产**（顺序有意如此：先有表再注册）；
- 守护测试把「半成品翻译」拦在门外：任何语言的键集必须与默认语言**完全一致**、无空值。

> 已知边界（如实说明）：本版**没有**交付繁中 / 日语的**文案内容** —— 那需要逐条翻译约 2100 个键，
> 机器翻译的成品质量不足以直接发布。本版交付的是**机制**与守护测试：翻译就位后，加语言确实只需
> 「写表 + 注册一行 + 并列资产」这三步，不再需要改任何逻辑分支。
### 5.10 测试工程结构性修复（E2）

**① 堵上「测试全绿、主工程编译不过」的系统性盲区**

测试工程是靠逐个 `<Compile Include>` 链接纯逻辑源文件的，**从不编译主工程** ——
于是「1000 项测试全绿，但主工程有一处编译错误」是可能发生的（本轮开发中就真的发生过：
漏了一个 `using`，测试全绿而主工程编译失败）。现在测试工程多了一条
`ProjectReference`（`ReferenceOutputAssembly=false`，只构建不引用），`dotnet test` 会先把主工程编一遍。

**这个守护是验证过的**：往一个**未被测试链接**的文件（`Views/HomePage.xaml.cs`）里注入
`int y = "不是数字";` 之后，`dotnet test` 立刻以 **exit 1** 失败，两个 TFM 都报错；还原后重新全绿。

**② 把机密编解码从 `HostBridge` 拆成可测单元（`SecretCodec`）**

`HostBridge` 里的「机器绑定密钥派生 + AES-256-GCM 值级编解码 + 旧版明文兼容 + 认证失败 fail-closed」
是机密存储里最容易出错、后果最重的一段（编错 = 密钥静默丢失，解错 = 用户读不回自己的密钥），
却因为长在一个依赖注册表 / DPAPI / 文件系统的类里而**结构上无法被单测覆盖**。

现在拆出 `SecretCodec`：**只做纯计算**，机器 GUID 由调用方读好传进来，整条链路可在普通测试进程里跑。
新增 20 项回归测试覆盖每个分支：往返（含中文/emoji/长值）、每次密文不同（随机 nonce）、
存储格式契约（`v2:nonce:tag:cipher` 四段定长）、无密钥退化、**旧版明文原样返回**、
**格式容错绝不误删**（5 种畸形输入）、**认证失败返回 null 而不是半个明文**（错误密钥 / 篡改密文 / 篡改 tag）。
### 5.11 语言切换彻底化 + UI 线程同步 IO（F5 / F8）

**① 一个真实缺陷：英文内容资产从来没生效过**

新加的「逐页语言重放」自检刚跑起来就红了：英文界面上仍显示中文。日志里躺着三条早就存在、却没人看见的 WARN：

```
[Plugins] 英文插件目录资产缺失，已回退中文随包内容：plugins.en-US.json
[Guide]   英文排障指引资产缺失，已回退中文随包内容：troubleshooting.en-US.md

V2.9.3 起的英文内容支持实际上从未生效。修法是给这四条资源加 `WithCulture="false"`，
并把原因写进 csproj 注释（这条有单测守护，见下）。

**② 文案「冻在首次加载」的多处残留**

| 位置 | 症状 | 修法 |
|---|---|---|
| `Views/GuidePage` | 用 `bool _loaded` 早退；指引是**分语言**资产，切语言后整页仍是旧语言 | 改记「已渲染的语言」，语言变了重新取 |
| `Services/Obs/ObsLogAnalyzer.DropKinds` | `static readonly` 数组在类型初始化时冻住三条丢帧文案 | 改为按需构造 |
| `Views/PluginsPage` 的 `Entries` / `StreamFxMigrations` | 同上（静态字段冻文案） | 改为按需构造 |
| `Controls/FeedbackCard`、`Controls/ObsDownloadCard` | 文案只在**构造函数**取一次，而控件被多页共用、页面实例被缓存 | 新增 `ApplyLanguage()`，宿主页进入时调用 |
| `Views/ToolboxPage` | 处方下拉框与分节导航按钮在构造函数里取文案 | 实现 `INavigationAware`，语言变化时重建 |

**③ 自检补上「逐页语言重放」并真的抓到了东西**

新增第 23 项：切到英文后**逐页重放 18 条路由**，遍历页面可视树，检查
① 是否出现文案键本身；② 是否出现**只存在于中文表的文案**（＝冻结的旧语言）。
两个细节值得记下：判定用 `IsVisible` 而不是 `Visibility`（父节点 Collapsed 时子控件自身仍是 Visible，
否则会把隐藏覆盖层里的旧文案算成缺陷）；判定范围收窄为「恰好等于某条中文文案」，
因此知识库正文里的中文散文不会被误报。

**④ F8：四处 UI 线程同步 IO**

- `ObsBackupService.ListBackups`（逐个 zip 打开 + 读 manifest）→ `Task.Run`；
- `ToolboxPage` 的 `Process.GetProcesses()` 全机枚举 → `Task.Run`；
- `FeedbackPage` 剪贴板重试的 `Thread.Sleep(60)` ×3 → `await Task.Delay`（剪贴板必须在 UI 线程调用，
  但等待期间要让出线程）；
- `HostBridge` 的 `GetSecretAsync` / `SetSecretAsync` / `DeleteSecretAsync` / `AiChatAsync`：
  信号量空闲时 `await WaitAsync` **不会让出线程**，DPAPI + AES + JSON 会直接在 UI 线程上跑 →
  统一挪进 `Task.Run`（`AiChatAsync` 同时改为真正异步取锁）。

### 5.12 obs-websocket 那批「现成但未用」的能力（D7）

obs-websocket 一直都有这些请求，本工具此前**一处未用**。本版补齐协议层并落地两个入口：

| 能力 | 请求 | 本版落地 |
|---|---|---|
| 节目画面截图 | `SaveSourceScreenshot` / `GetSourceScreenshot` | 控制台「节目截图」：一键存 PNG 到录制目录（拿不到就存图片目录），文件名带时间戳 |
| 演播室模式 | `GetStudioModeEnabled` / `SetStudioModeEnabled` / `TriggerStudioModeTransition` | 控制台开关 + 「切换（预览 → 节目）」按钮；未连接或未启用时按钮自动置灰 |
| 滤镜控制 | `GetSourceFilterList` / `SetSourceFilterEnabled` | 协议层 + 种类展示名（降噪 / 色键 / 锐化…，19 种已知种类，未知原样显示） |
| 媒体控制 | `TriggerMediaInputAction` / `GetMediaInputStatus` | 协议层 + 动作白名单（6 个官方取值）与播放状态判定 |
| 音频监听 | `SetInputAudioMonitorType` / `GetInputAudioMonitorType` | 协议层 + 取值归一化（接受 `none`/`关闭`/`monitorOnly`/`仅监听` 等写法） |
| 场景集合 / 配置集快切 | `SetCurrentSceneCollection` / `SetCurrentProfile` | 协议层（上一轮已补 v4 映射，本版补上服务层入口） |

**旧协议（OBS 27 / Win7）一并映射**，其中三处字段名/请求名并不一致，映射错了**不会报错**、
只会静默失效，因此每条都有单测：

- `SetSourceFilterEnabled` → v4 `SetSourceFilterVisibility`（名字不同）；
- `GetInputAudioMonitorType` → v4 `GetAudioMonitorType`（名字不同）；
- `GetSourceFilterList` 的响应字段 `filterName/filterKind/filterIndex/filterEnabled/filterSettings`
  ↔ v4 `name/type/enabled/settings`（**逐条改名**，直接透传会让上层读到一堆空字符串）；
- `GetStudioModeEnabled` 的 `studioModeEnabled` ↔ v4 `studioMode`；
- `SaveSourceScreenshot` 的 `width/height/quality` ↔ v4 `imageWidth/imageHeight/imageCompressionQuality`。

两处**克制**值得一提：媒体动作与监听类型都做**本地白名单校验**，拼错时直接返回失败并列出可用取值，
而不是发一个必然被拒的请求让用户去猜 OBS 的报错；本地校验失败用独立的返回码
（`ClientValidationFailed`），与 OBS 的返回码区分开 —— 上层「参数错了」和「OBS 拒绝了」是两种处理方式。

> 已知边界：v4 映射依据的是 obs-websocket **4.9.1 官方协议文档**并有单测覆盖，
> 但本版仍未在真实 OBS 27 上做过握手验证（与既有的 v4 边界一致）。
> 滤镜列表 / 媒体控制 / 监听类型的 UI 入口留待后续轮次（协议层已就绪）。
### 5.13 「我的模板」：把当前场景集合反向存成模板（D6）

模板能力此前是**单向**的（官方 12 套 → 在线落地 / 离线导出）。用户自己调好的一套
（摄像头裁剪、滤镜、降噪）想换机或重装，只能靠整包配置备份，粒度太粗。

现在模板页多一个「把当前场景存成模板」：读回当前 OBS 场景集合的场景、来源、位置、设置与**滤镜**，
存成一份模板，落到 `%LocalAppData%\OBS_Helper\templates`。它与内置模板**同一 schema**，
因此列表、落地、导出给别人的三条路径**共用一套代码**，不需要为「我的模板」另写落地器 ——
这也是这一项只用了不到一天的原因。

三条关键取舍（每条都决定换机后能不能用，而且**错了不会报错**，所以都有单测）：

| 取舍 | 为什么 |
|---|---|
| **机器相关设置一律不带走**：`device_id` / `device_name` / `local_file` / `playlist` / `window` 在捕获阶段剔除，换成「换机后需重新选择设备/文件/窗口」的占位提示 | 带过去只会让落地「成功但没画面」，比不写更糟 |
| **跨场景复用的来源只带一次设置**：同一路麦克风出现在多个场景时，第二次只引用（`Shared = true`），不带设置与滤镜 | 否则 OBS 会报重名，或产生第二个设备占用 |
| **层级按 OBS 口径换算**：OBS 的 `sceneItemIndex` 0 = 最上，模板 `zOrder` 0 = 最底，捕获时反转 | 弄反会让整场画面层级颠倒 |

配套改动：

- 模板 schema 增加 `filters`（滤镜名/种类/开关/设置）与 `isMine` 标记；落地时按 `CreateSourceFilter`
  → `SetSourceFilterSettings` → `SetSourceFilterEnabled` 建回滤镜，**失败不阻断落地**
  （滤镜种类可能属于未安装的插件，那种情况下应该照常把场景搭起来、把缺失记进占位清单）；
- 旧协议（OBS 27）一并映射 `CreateSourceFilter` / `SetSourceFilterSettings`；
- 单份模板文件损坏只跳过它，不影响其它模板；写盘走「临时文件 + 替换」，中途崩溃不会留下半份 JSON；
- 自检里那张 18 条路由的页面重放覆盖了模板页，坏模板文件不会让页面崩掉。

> 已知边界：反向捕获依赖 OBS 在线（未连接时按钮明确提示）；滤镜设置里的设备/文件键同样被剔除，
> 因此带「音频延迟」这类**与机器无关**的滤镜能完整带走，而带设备选择的滤镜需要用户重选一次。
### 5.14 知识库贡献闭环（D8）

知识库此前只能**被动接收热更新**，用户端没有回写路径 —— 于是「这条不解决问题」这个最有价值的信息
根本传不回来，反馈入口（腾讯表单 / GitHub Issue）也明确不收路径、设备名与日志原文。

**① 问题详情页底部「这条解决问题了吗？」**

两个按钮（解决了 / 没解决）+ 一个可选的补充说明框，生成一份 Markdown 回执：

- **不自动上传**：回执是复制到剪贴板、由用户自己贴到 Issue 或邮件里。
  「本地生成」与「点一下就外发」是两件事，不该让用户点个评价就变成一次静默的数据外发；
- **带上条目 id 与知识库版本**（还有应用版本、OBS 版本、系统）：否则维护者收到「这条没用」时，
  既不知道说的是哪一条，也不知道对方看的是哪一版内容（热更新会改条目）；
- **Issue 链接只带标题不带正文**：正文上千字，塞进 URL 有可能被浏览器/代理截断，
  而截断后的 Issue 比没有更糟（用户以为贴上了）。

**② 本地知识库：把我的踩坑笔记沉淀成资产**

用户自己的条目写在 `%LocalAppData%\OBS_Helper\data\my-problems.json` —— 与热更新文件**同目录、同
schema**，因此加载、搜索、分类、落地全部复用既有路径；文件名叫 my-problems.json，所以**热更新永远不会
覆盖它**。页面上有「创建我的知识库示例文件」（JSON 没有注释，一条完整示例就是最短的说明书）。

三条合并规则（错了都会静默消失或串位，因此都有单测）：

| 规则 | 为什么 |
|---|---|
| 同 id 时**本地优先** | 用户显然是想覆盖官方那条；改错了删掉文件即可恢复 |
| 分类名写错时归到保留分类「我的条目」 | 手写 JSON 写错分类名是常态，条目不该因此从界面上消失 |
| 本地文件里的重复 id 只保留第一条 | 复制粘贴出重复是手写 JSON 的常见事故 |

读取容忍 `{problems:[...]}` 与 `[...]` 两种写法、注释与尾随逗号；**单条坏数据只跳过它**，
不会因为一条写错就让整份本地知识库消失。条目在详情页带「本地」标记，与官方内容一眼可分。

**③ 存储目录改为构造参数**

本地知识库的存储目录从内部写死改为构造参数注入，因此**真实的文件读写也能被单测覆盖**
（不再只能测纯逻辑）：新增 11 项测试跑完整的「写示例 → 用户改 → 读回 → 并入知识库」闭环，
以及缺文件 / 两种写法 / 注释 / 尾随逗号 / 坏文件 / 空文件 / 不覆盖既有文件等分支。
顺带去掉了一个不必要的依赖：存储类不再自己写日志，而是把失败原因交给调用方（`LastError`），
由 `ProblemService` 记录 —— 这样「文件坏了」与「压根没文件」在排查时能分得清。
### 5.15 国际化残留收尾（E5）

提案里这一项的重点不是「还有几个中文字面量」，而是那条**静默回退**：

**① 内容资产回退现在会在界面上说出来**

四份内容资产（知识库 / 插件目录 / 场景模板 / 排障指引）都有英文并列文件。一旦英文资产缺失，
`ContentAssets.Resolve` 会退回中文随包内容 —— 以前**只写一条 WARN 日志，界面上什么都不说**，
英文用户只会觉得「这软件怎么一半是中文」。这与 V2.9.1 raw 404 那类「静默且合法」的坑是同一个形状：
功能没坏，体验错了，且没人知道。

现在：

- 登记点放在 `ContentAssets` 内部（唯一的回退出口），**调用方不可能忘记上报** ——
  少写一行日志是小事，少一条界面提示是这一项的全部意义；
- 主窗口顶部出现一条可关闭的提示条，**点名是哪几块内容受了影响**
  （只说「出问题了」等于没说）；文案随语言即时切换；
- 判定三条件：发生过回退 ∧ 当前语言不是中文（中文界面下回退到中文本来就对）∧ 用户没点过「知道了」；
  「知道了」只在本次运行内生效 —— 下次启动如果仍然缺失，用户应该再看到一次。

自检新增第 24 项覆盖这条接线（上报 → 显示 → 文案点名资产 → 忽略 → 语言判定），
判定逻辑本身另有 16 项单测（含事件重复上报不重复通知、订阅者抛异常不影响上报方）。

**② 清掉两处写死的展示文案**

| 位置 | 原状 | 现在 |
|---|---|---|
| `Models/ObsConfig/SceneTemplate.Transition` | 默认值写死 `"淡入淡出"` | 取文案键 `template.transition.default`（英文下为 "Fade"；`PickTransitionName` 两种写法都认，跨语言共用模板不失效） |

**① 严重：数据目录不可创建时，应用启动即死且界面上一个字都没有**

第一次运行兼容构建（`net6.0-windows`）时它**直接崩溃**（exit `0xE0434352`，连自检结果都没产出）。堆栈追到：

```
Unhandled exception. System.TypeInitializationException: The type initializer for
'OBS_Helper.Wpf.Services.FileLogger' threw an exception.
 ---> System.UnauthorizedAccessException: Access to the path
      'C:\Users\...\AppData\Local\OBS_Helper_Win7' is denied.
   at HostBridge.get_AppDataDirectory() : line 113
   at FileLogger..cctor()          : line 28

`HostBridge.AppDataDirectory` 的属性 getter 里直接 `Directory.CreateDirectory`，

**③ `Copy` 丢了 `Severity`（深拷贝引入的回归，已修）**

用户在 `my-problems.json` 里写的 `"severity": "严重"` 经合并会变成默认的「常见」，
牵连药丸配色、排序与 AI 诊断分级。已补上字段，并新增**逐字段保全**断言（以后再漏字段测试会红）。

**④ v4 映射缺 5 条捕获要用的请求 —— 兼容构建下「每个来源都变成误导性占位」（已修）**

缺 `GetInputSettings` / `GetSceneItemTransform` / `GetSourceFilter` / `GetSceneSceneTransitionOverride` /
`SetSceneSceneTransitionOverride`。最严重的是 `GetInputSettings`：旧协议下每个来源的 `inputKind` 都读不到，
于是全部落进「分组没能展开」分支，照存一份**全是占位**的模板 —— 错误归因，不是协议限制。
已按 v4 真实请求名补映射（`GetSourceSettings` / `GetSceneItemProperties` / `GetSourceFilterInfo` / 单 Scene 版），
并补响应归一化；`GetGroupSceneItemList` 是 v5 新增、v4 确实没有，**故意不映射**，
提示文案也分流成「旧协议读不到分组内容」而不是「数据坏了」。

**⑤ 新增「请求名守卫」测试：这类缺陷从此能被测试拦住**

上面第 ②条的教训是：请求名写错在编译期、单测、自检里都不报错。新增
`ObsRequestNameGuardTests`：把源码里出现的**每一个** v5 请求名（当前 64 个）与
**官方协议表**（独立整理，非从源码抄）逐一比对，不在表里又没写豁免理由就直接红；
另有反向着断言，禁止再出现已被证伪的名字（`SetSceneTransitionOverride` 等 8 个）。
这一条会真实地拦住下一轮同类错误，而不是靠人肉逐名核对。

**⑥ 增量包门禁「永远红」的根因（已修）**

`verify_delta.py` 拿 `publish` 目录当参照系，而 publish 里含 `*.pdb` 这类**打包时按设计排除**的文件
（V3.0 起便携包不再带 pdb）—— 于是「老包里的 pdb 被增量包正确删除」反而被判成
「最新发布缺失 OBS_Helper.pdb」，这条端到端门禁**从 V3.0 起就一直是 FAIL**（真问题会被这条噪声淹没）。
现在优先用**新版便携包**（真正的发货产物）做基准，未提供时退回 publish 并忽略打包排除项，
CI 也已改为传 `--new`。实测：2.9.6 → 3.0.0 增量包应用后 **268 个文件 0 不一致、0 缺失**。

**⑦ CI 配置本身是坏的（已修）**

插入「无障碍静态检查」步骤时缩进层级错了，`ci.yml` **无法被 YAML 解析** → 整条流水线根本起不来。

### 5.19 其余体验补强

- **剩余可录时长改用实测写入速率**（`SimpleRecordingService`）：本产品刻意不写码率，

- **工具箱分节导航**（C6）：该页有 17 个分节、纵向很长，此前只能靠滚轮找，且**不知道自己错过了什么**。

- **音画同步偏移**（D7）：音画不同步是「观众一眼看出来、主播自己很难确认」的典型问题，

### 第二轮对抗式审查发现并修掉的缺陷

> 这一节保留下来，是因为它比「改了什么」更有价值：**这些是同一批改动里的真实漏洞**。

**数据与可靠性线**

| # | 缺陷 | 后果 | 处置 |
|---|---|---|---|
| 1 | `DispatcherUnhandledException` 里调 `FileLogger.Flush()` 会关闭日志队列，而 `e.Handled = true` 之后进程继续跑 | 此后整个会话的日志被**静默丢弃**，还会每次阻塞 UI 最多 2 秒 | 拆出 `Drain()`（只排空）与 `Flush()`（仅退出时关闭队列） |
| 2 | socket 在「Identify 成功」与 `SetState(Connected)` 之间被关闭，且新门控不排重连 | 永久「显示已连接、socket 已死、永不重连」 | `await connectTask` 后校验 `_client.IsOpen`，不 open 即 Disconnected + 排重连 |
| 3 | `_userInitiatedDisconnect` 在自动重连链路从不清除 | 「连接中点断开」后本会话**再也不自动重连** | 失败分支仅在非用户断开时排重连；重连成功路径不再残留该标志 |
| 4 | `OnClosed` 会把在途的 `Reconnecting/Connecting` 踩成 `Disconnected` | 徽章与倒计时不一致；录制守护依赖的 `Reconnecting → Connected` 跳变失效（丢录制却无提示） | 非 Connected 时只记录原因、不改状态，编排交给 `ConnectCoreAsync/ScheduleReconnect` |
| 5 | `FileTx` 的 `_creates` 在 `_moves` 之后处理 | 同事务「既 move 又 create」同一路径时，会把刚恢复的文件连同唯一副本一起删掉 | 同事务 move 过的路径一律不删（恢复优先） |
| 6 | 新加的「保留副本」机制没有出口，且 `CleanupTrash` 会把它删掉 | 用户只知道失败，不知道配置还在 `trash\tx_*` 里 | 打 `.obshelper-retained` 标记（`CleanupTrash` 跳过）+ 注入 `RollbackFailureReporter` 上报到日志与 Toast |
| 7 | 手动配置目录**零校验**即登记为可信根，`Trim("D:\")→"D:"` 让 `IsUnder` 对整卷成立 | 把整个盘当可信写区 | 盘符根/系统目录永不登记；名字兜底额外要求 `basic/` 或 `global.ini`；`AssertWritable` 补盘符根闸；设置页选中目录时按「像不像 OBS 配置」收口 |
| 8 | `SetPasswordAsync` 忽略落盘结果并强制 `RememberPassword = true` | 密码永远存不上、界面却说记住了（重启才暴露） | 按实际结果写回标志并返回；控制台当场提示「重启后需重填」 |
| 9 | `OpenExternalAsync` 可被 `http://localhost./`（尾点 FQDN）绕过私网拦截 | 热更新下发的外链仍可把用户引到本机/内网管理页 | 比较前 `TrimEnd('.')`；通配 DNS 属已知残留风险并写进注释 |
| 10 | `LocalStore` 的 `.corrupt` 只留一代 | 第二次损坏覆盖第一次 | 改成带时间戳的多代副本 |
| 11 | `SafeIniFile` 无任何单测 | 风险最高的写盘路径没有回归保护 | 新增 `SafeIniFileTests`（6 项：创建/备份/无残留临时文件/越界拒绝/绝对路径逃逸/覆盖写） |
| 12 | `ExtractProfileFile` / `ExtractSceneCollectionMerge` 写配置目录不过护栏；`.obshelper.bak` 会被导入回来 | 纵深防御缺口 + 陈旧内容进配置目录 | 两处补 `AssertInsideConfig`；导入时跳过 `.obshelper.*` |
| 13 | 回滚前「整备份失败即中止」 | 把用户最后的救命按钮交给无关故障（系统盘满）摆布 | 改为**尽力而为**：失败只记日志并继续回滚（`SafeIniFile` 仍在同目录留 `.bak`） |
| 14 | `ReportError` 包装了一层异常 | 只多出一条堆栈无用的日志 | 直接按对象记原异常，错误码进 category |

## 已知边界（如实说明）

1. **旧协议只做到「部分兼容」**：v4 没有 `SetProfileParameter` / `SetVideoSettings`，
   因此「一键部署录制环境」在旧协议下走文件通道（需重启 OBS 生效），部分能力在界面上明确提示不可用。
2. **旧协议的握手与端到端链路未在真实 OBS 27 + obs-websocket 4.9 上验证过** ——
   目前只有纯逻辑单测（鉴权算式、映射表、归一化）与协议文档对照。
3. **无障碍的实测边界**：没有在 NVDA / Narrator 下逐项验证播报效果，也没有真机复核高 DPI 最小宽度问题。
4. **更新链路的完整性**已改为校验 GitHub API 给出的资产 SHA-256 摘要（独立于包体的锚点），
   但**发布物仍无 Authenticode 签名** —— 证书需要购买/申请，本版只把签名步骤做进 `build.ps1`
   （`-SignPfxPath` / `-SignPfxPassword`），有证书时一条命令即可签名。没有签名时，
   Windows SmartScreen 仍会提示「未知发布者」，客户端也只能靠「MZ 头 + 摘要」判断包的真伪。
5. **安装包仍有约 22MB 可精简**：现代构建启用了 `UseWindowsForms`，
   自包含发布里因此带上 `System.Windows.Forms.dll`（13.1MB）+ `System.Windows.Forms.Design.dll`（5.8MB）
   + `System.Windows.Forms.Primitives.dll`（3.5MB）= 约 22MB（实测 160MB 总大小）。
   根因是**托盘图标基于 WinForms 的 `NotifyIcon`**：要摘掉它得自己写 `Shell_NotifyIcon` + 消息循环 + 右键菜单，
   属于高风险重写。本版只做了零风险的部分：安装包与便携包**排除 `.pdb` 与自检产物**。Win7 兼容构建另有
   `FolderBrowserDialog`（net6 没有 WPF 的文件夹选择器），因此那条线上 WinForms 是必需的。
6. 本清单来源（`docs/OPTIMIZATION_PROPOSAL_2026-10.md`）中的其余条目仍在推进，未列入本版的部分见该文档的排期。
