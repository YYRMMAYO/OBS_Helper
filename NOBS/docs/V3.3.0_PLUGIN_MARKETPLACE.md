# V3.3.0 插件广场：一键下载、安装、管理与 GitHub 联动

> 配套主文档：[`PLAN_V3.3.0.md`](PLAN_V3.3.0.md)
> 本文给出**多路线方案**，并对推荐路线做可实施的技术设计。**已确认（2026-10-25）**：3.3.0 采用“精选为主 + GitHub 导入”的混合路线；内嵌 GitHub 网页不做；Watt Toolkit 只做检测/启动/引导。
> **一句话结论**：精选目录 + 事务安装/回滚 + GitHub 原生搜索/粘贴导入 + 外部搜索 的“混合路线”最可行；**内嵌 GitHub 网页**和**任意仓库静默安装**不做；Watt Toolkit 只做检测/启动/引导，不自动改系统网络设置。

---

## 1. 需求拆解

用户希望：

1. 在“插件广场”检索插件，并联动 GitHub 搜索 OBS 插件；
2. 看到精选插件卡片，点“一键配置”后应用内完成下载、安装、配置；
3. 管理插件（已安装、更新、卸载、回滚）；
4. 打开插件广场时顺便配置 Watt Toolkit（Steam++）的 GitHub 加速，提升下载成功率；
5. 可以接受“网页搜索模式”或“精选卡片模式”，让你后期抉择。

把需求拆成五个能力：

| 能力 | 本质 | 风险 |
|---|---|---|
| 检索 | 精选目录 + GitHub 搜索/导入 | 结果可信度、API 限额 |
| 下载 | 官方 Release/官方站点资产 | 资产选错、伪造、断网、限流 |
| 安装 | 把 ZIP 内容放进 OBS 插件目录 | 路径穿越、覆盖、权限、OBS 占用 |
| 配置 | 加滤镜/加源/打开 OBS 对话框/文档 | 插件差异大，不能全自动 |
| 管理 | 版本、更新、卸载、回滚 | 误删、残留、OBS 未关闭 |
| 加速 | Watt Toolkit/系统代理 | 权限、冲突、第三方软件内部实现 |

## 3. 多路线方案（供后期抉择）

### 3.1 路线 A：精选卡片 + 一键安装/管理（已选主线，P0）

**形态**

- 现有 `plugins.json` 增加安装元数据（资产名、哈希、布局、配方、许可）。
- 卡片内“一键配置” → 下载 → 校验 → 备份 → 安装 → 提示重启 OBS → 安装后配方。
- “已安装/更新”Tab：版本、路径、更新、卸载、回滚、打开目录。

**优点**

- 可信度最高；每个插件都能人工验证资产/许可/兼容性。
- 可以做哈希、签名、回滚、兼容性、配方。
- 与现有目录/扫描/兼容/关注能力天然衔接。
- 用户体验最接近“点一下就好”。

**缺点**

- 目录维护成本：插件每次发版，资产名/哈希可能变；需要人工复核或半自动草稿。
- 覆盖面受限于“已收录”插件。

**适合**：P0 主线；先覆盖 15~25 个高频插件。

### 3.2 路线 B：GitHub 原生搜索/导入（已选次级，P0）

**形态**

- 软件内搜索 GitHub：`topic:obs-plugin` / `topic:obs-studio-plugin` / `obs plugin in:name,description`。
- 结果卡片：仓库名、描述、Star、License、最近提交、归档状态、Release 资产。
- “导入”按钮：粘贴 `owner/repo` 或 GitHub URL，解析最新 Release；列出资产让用户选；强警告后安装。
- 外部浏览器搜索按钮：`https://github.com/search?q=topic%3Aobs-plugin&type=repositories`。

**优点**

- 覆盖面最大；用户想装什么都能找到。
- 不依赖内嵌浏览器；原生卡片可访问性好。

**缺点**

- 任意仓库不可信；资产命名不统一；很多插件只提供源码/无 Release。
- GitHub 搜索 API 未认证 **10 次/分钟**；Release API 60 次/小时；必须缓存/用户触发/可选 token。
- 安全边界复杂：未签名、哈希不可预知、可能装错架构。

**已选**：3.3.0 P0 次级路线；默认只允许“查看/打开仓库”，安装需进入“高级模式 + 明确风险确认”；不要做静默自动装。

### 3.3 路线 C：内嵌 GitHub 网页（不推荐）

**形态**：在应用内嵌一个浏览器，打开 GitHub 搜索页；用户浏览后复制仓库名，再回到应用导入。

**技术现实**

- WPF `WebBrowser` 是 IE/Trident，GitHub 现代页面基本不可用；不安全。
- WebView2 需要 `Microsoft.Web.WebView2` NuGet + Evergreen Runtime；破坏“零第三方 NuGet 包”和 Win7 兼容目标；还要处理用户数据目录/CSP/崩溃。
- 即使嵌入成功，用户仍要复制名称；体验并不比“外部浏览器 + 粘贴 URL”好。

**结论**：不做内嵌网页；改为：
- “在浏览器中打开 GitHub 搜索”（外部）；
- 应用内“粘贴 GitHub URL/owner/repo 导入”（原生 API）。

### 3.4 路线 D：混合路线（已选最终形态）

```
精选卡片（A） + GitHub 导入（B） + 外部搜索（C 的轻量替代）
```

- 默认 Tab“精选”：可信、可一键、可回滚。
- Tab“搜索/导入”：GitHub API 结果 + 粘贴导入；强警告；高级模式。
- Tab“已安装/更新”：管理。
- Tab“网络”：Watt 检测/启动/连通性诊断/系统代理说明。

### 3.5 路线对比

| 维度 | A 精选 | B GitHub 原生 | C 内嵌网页 | D 混合 |
|---|---|---|---|---|
| 覆盖面 | 中 | 高 | 高 | 高 |
| 可信度 | 高 | 低~中 | 低~中 | 高（默认）+ 低（高级） |
| 一键安装 | 是 | 需确认/高级 | 否（复制名称） | 是（精选）/确认（导入） |
| 工程成本 | 中 | 中高 | 高（WebView2） | 中高 |
| 安全/合规 | 可控 | 复杂 | 复杂 | 可控 |
| 依赖/打包 | 零新增 | 零新增（HTTP/JSON） | 新增 WebView2 | 零新增 |
| Win7 | 可 | 可（API） | 基本不可 | 可 |
| 建议/决策 | **P0 主线** | **P0 次级** | **不做** | **已选** |

## 4. 推荐架构

### 4.1 服务拆分

```
Services/Plugins/
  PluginInstallService        编排下载/校验/安装/更新/卸载/回滚
  PluginInstallCore           纯逻辑：资产选择、zip 路径映射、清单、版本比较、PE 架构
  PluginReleaseAssetService   GitHub Release 资产列表/下载 URL/缓存/限流
  GitHubSearchService         GitHub 搜索/仓库元数据/URL 解析（缓存/限流/可选 token）
  PluginRecipeService         安装后配方：加滤镜/加源/打开对话框/文档
  PluginStateStore            installed.json、backups、downloads
  NetworkAccelerationService  Watt 检测/启动/连通性/系统代理说明
  AuthenticodeVerifier        WinVerifyTrust（可放 Services/Security/）
  PeArchitecture             读取 PE 头判断 x64/x86（纯逻辑）

Models/Plugins/
  PluginInstallManifest.cs    目录安装元数据
  PluginInstallRecord.cs      已安装记录
  PluginReleaseAsset.cs       Release 资产
  PluginSearchResult.cs       GitHub 搜索结果
  PluginRecipe.cs             安装后配方

Views/
  PluginsPage（扩展 Tab：精选 / 搜索 / 已安装 / 更新 / 网络）
  Controls/InstallProgress.xaml
  Controls/PluginInstallDialog.xaml（确认/风险/进度/回滚）
```

### 4.2 目录数据结构（扩展 `plugins.json`）

保持旧字段不变，新增可选 `install`：

```jsonc
{
  "id": "obs-backgroundremoval",
  "name": "Background Removal",
  "repo": "occ-ai/obs-backgroundremoval",
  "dlls": ["obs-backgroundremoval"],
  "install": {
    "mode": "zip",                    // zip | installer | manual
    "assetPattern": "*windows*x64*.zip",
    "sha256": "…",                    // 可选：目录锁定的版本哈希
    "size": 12345678,
    "version": "1.3.0",
    "layout": "obs32",               // obs32 | legacy | auto
    "requiresAdmin": false,           // ProgramData 时可能 true
    "minObsVersion": "28",
    "license": "GPL-2.0",
    "homepage": "https://github.com/occ-ai/obs-backgroundremoval",
    "recipe": {
      "kind": "filter",
      "targetRole": "camera",         // 给哪个源加滤镜；由用户选
      "filterKind": "background_removal",
      "openProperties": true,
      "docsUrl": "https://github.com/occ-ai/obs-backgroundremoval"
    }
  }
}
```

注意：
- `sha256`/`size` 应绑定具体版本；插件发版后必须更新目录，否则拒绝安装（可给“查看新版本”出口）。
- `assetPattern` 只是候选；最终仍要列出资产让用户确认（精选可自动选唯一匹配）。
- `recipe` 是“建议”，不是保证；不能脚本化的插件 `kind="guide"`。

### 4.3 安装位置与布局

OBS 官方插件指南（`https://obsproject.com/kb/plugins-guide`）说明：

- **推荐（Windows）**：`C:\ProgramData\obs-studio\plugins\<插件名>\bin\64bit\<插件名>.dll` + `data\...`；
- **旧布局**：`C:\Program Files\obs-studio\obs-plugins\64bit`（官方说明未来会停止工作）；
- 本项目现有扫描还覆盖：
  - `%AppData%\obs-studio\plugins`（用户级，V2.9 起纳入）；
  - `%ProgramData%\obs-studio\plugins`（OBS 32.x 全局根，一插件一目录）；
  - 实际安装目录/Steam 库的 `obs-plugins\64bit`。

安装策略：

| 场景 | 目标 |
|---|---|
| OBS 32.x + 官方新布局 | `%ProgramData%\obs-studio\plugins\<id>\bin\64bit` + `data` |
| 用户级可用 | `%AppData%\obs-studio\plugins\<id>\bin\64bit` + `data`（避免 UAC，需实测 OBS 版本支持） |
| 旧版 OBS | `obs-plugins\64bit` + `data\obs-plugins\<id>` |
| 便携版 OBS | 安装目录下 `data\plugins` / `obs-plugins\64bit`（按 OBS 文档/用户指定） |

- **不要猜**：先读 OBS 版本/安装目录/已存在插件布局；用“能力探测 + 用户确认”决定目标。
- ProgramData 需要管理员权限：P0 可显示“需要管理员/UAC”；P1 做提升权限助手。**不静默提权**。
- 安装前要求 OBS 关闭；检测 `obs64` 进程；不强制结束（避免丢失录制）。

## 5. 下载与资产选择

### 5.1 来源

- 精选：GitHub Release 资产 / 官方站点；目录锁定 URL/资产名/哈希。
- GitHub 导入：`GET /repos/{owner}/{repo}/releases/latest`；读 `assets[]`；不要用 `releases` 列表第一项（可能是旧版/预发布）。
- 只允许 `https://github.com/...` / `https://objects.githubusercontent.com/...` / 官方 Release 资产域名；重定向后再次校验。
- 拒绝 Source code (`zip`/`tar.gz` 自动生成资产)；拒绝 `.7z`（BCL 不支持，提示用户手动或用官方安装器）。

### 5.2 资产选择算法（纯逻辑可测）

```text
候选 = assets 中：
  - 名称/内容类型含 windows / win64 / win / x64 / x86_64
  - 扩展名 .zip / .exe / .dll
  - 排除 source code、debug symbols、macOS/Linux、arm64、32-bit（除非用户明确）
  - 排除 checksum/签名文件（.sha256/.sig）作为主资产
评分：
  + 名称含 obs/插件名
  + 名称含 x64/win64
  + 大小合理（>10KB, <500MB）
  + 最近上传
  - 名称含 debug/pdb/source
若唯一最高分 → 自动选；否则列出让用户选。
```

- `.exe`：不静默安装；显示签名/大小/来源；用户点击运行。
- `.zip`：继续检查内部结构（见 §6）。
- `.dll`：仅在用户明确选择“单 DLL 插件”时安装；提示可能缺 data/locale。
- 无资产：显示“该项目没有 Windows 二进制 Release”，打开仓库/文档；不安装。

### 5.3 校验

| 校验 | 说明 |
|---|---|
| HTTPS + 域名白名单 | 拒绝 http/未知域名/短链 |
| 大小上限 | 默认 500 MB；超限拒绝 |
| SHA-256 | 目录有则必须匹配；GitHub API `digest`（如有）也校验 |
| Authenticode | 有签名则 `WinVerifyTrust`；显示签名主体；未签名明确提示 |
| PE 架构 | 读 PE header，要求 x64（或与 OBS 架构一致） |
| zip 安全 | 路径穿越、绝对路径、符号链接、文件数/大小/压缩比 |
| Defender | 可选调用 `MpCmdRun.exe -Scan -ScanType 3 -File <path>`；不可用则跳过并提示 |

> 插件生态大量未签名；不能因为“未签名”就一律拒绝，但必须**明确展示**并让用户确认。精选目录可以要求“已验证哈希”；任意仓库不能假装验证。

## 6. 安装事务

### 6.1 前置检查

- OBS 已安装；版本/架构明确；
- OBS 已关闭（或用户确认“仅复制，稍后重启”；默认要求关闭）；
- 磁盘空间 ≥ 2× 资产大小 + 备份；
- 目标目录可写；ProgramData 需要管理员；
- 插件兼容性（`PluginCompatCore`）通过或用户确认；
- 已安装同 id 的版本：走更新/覆盖确认；
- 冲突：同 DLL 名/同插件目录；提示覆盖/取消。

### 6.2 事务步骤

```text
1. 下载到 %LocalAppData%\OBS_Helper\plugins\downloads\<id>-<version>.zip.part
2. 校验大小/SHA-256/签名/PE
3. 解压到 staging：%LocalAppData%\OBS_Helper\plugins\staging\<guid>\
4. 校验 zip 结构 + 生成文件清单（相对路径、hash、大小）
5. 计算目标文件列表；确认所有路径在目标根内
6. 备份目标中将被覆盖的文件 → backups\<id>\<version>-<timestamp>\
7. 复制 staging → 目标（同卷 move；异卷 copy+delete）
8. 写 installed.json（id/version/files/hashes/source/installedAt/backup）
9. 失败：从 backup 回滚；清理 staging/part；保留错误详情
10. 成功：提示重启 OBS；可选安装后配方
```

- 用 `FileTx`/临时目录/原子 rename；不要边下载边覆盖。
- 不要删除目标目录中不属于本插件的文件；只覆盖清单内文件。
- 如果目标已有同名文件但不在清单中，先备份并提示。
- 安装后验证 DLL 存在/版本可读；可选解析 OBS 日志确认加载（重启后）。

### 6.3 更新

- 比较已安装版本与最新版本（`Version.TryParse`；非语义版本回退字符串比较并提示）。
- 下载新版本 → 备份旧版本 → 事务替换 → 写记录。
- 保留最近 2 个备份；失败回滚。
- 不自动更新；用户点“更新”或关注后提示。
- 更新前要求 OBS 关闭；录制/推流中禁止更新（明确提示）。

### 6.4 卸载

- 只删除 `installed.json` 里记录的文件；
- 不删除用户 OBS 场景/配置/插件数据（除非插件文档明确要求，且用户确认）；
- 先移到回收站/备份，再删除；可恢复；
- 如果文件被其他插件共享（同 hash/同路径），保留并提示；
- 未由应用安装的插件：只提供“打开所在文件夹/查看文档”，不删。

### 6.5 回滚

- 备份目录保留最近 2 份；
- “回滚到上一版” = 停止 OBS → 备份当前 → 恢复备份 → 写记录；
- 回滚失败保留现场，给路径和错误；
- 回滚不改变用户的 OBS 配置。

## 7. 安装后“一键配置”

### 7.1 配方类型

| `recipe.kind` | 行为 | 适用 |
|---|---|---|
| `filter` | 在用户选择的源上加滤镜（`CreateSourceFilter`），设置默认值，打开滤镜属性 | 背景移除、降噪、字幕、锐化 |
| `source` | 创建插件提供的源（如 NDI/Spout/Vertical） | NDI、Spout2、Aitum Vertical |
| `dialog` | 安装后打开 OBS 的源属性/滤镜对话框/插件停靠（能开的） | 需要用户选设备/参数的插件 |
| `guide` | 只显示图文步骤/官方文档 | 只能通过插件 UI 配置的插件 |
| `none` | 安装即可 | 纯后台插件 |

- `filter`/`source` 必须先用 `GetInputKindList`/`GetSourceFilterKindList` 确认插件已加载；否则提示“重启 OBS 后再配置”。
- 不写插件私有配置文件；用 OBS API 的输入/滤镜设置。
- 不覆盖用户已有滤镜；同名则提示。
- 任何配方失败都不影响“插件已安装”的事实；结果页分开显示“已安装/未配置”。

### 7.2 示例配方

| 插件 | 配方 |
|---|---|
| `obs-backgroundremoval` | 安装 → 选择摄像头源 → 加 `background_removal` 滤镜 → 打开滤镜属性 → 文档 |
| `obs-localvocal` | 安装 → 选择麦克风源 → 加字幕/转写滤镜 → 打开属性 → 说明模型下载 |
| `DistroAV` | 安装 → 检查 NDI Runtime → 添加 NDI 源 → 选源 → 文档（外部 GPL 插件，不捆绑） |
| `obs-spout2` | 安装 → 添加 Spout2 源/输出 → 选 sender → 文档 |
| `aitum-vertical` | 安装 → 打开插件/添加 Vertical 源 → 文档 |
| `advanced-scene-switcher` | 安装 → 打开 OBS 插件停靠 → 文档（无法全自动） |
| `composite-blur` / `advanced-masks` / `3d-effect` / `stroke-glow-shadow` / `retro-effects` | 安装 → 加滤镜 → 打开属性 → 文档 |

> 具体 filterKind/inputKind 以插件实际加载后的 OBS 列表为准；配方数据要可热更新。

## 8. GitHub 搜索/导入

### 8.1 搜索 API

```http
GET https://api.github.com/search/repositories?q=topic:obs-plugin&sort=stars&order=desc&per_page=20
Accept: application/vnd.github+json
User-Agent: OBS_Helper/<version>
```

可用查询：

- `topic:obs-plugin`
- `topic:obs-studio-plugin`
- `obs plugin in:name,description`
- `obs-studio in:name,description language:C++`
- `user:<owner> obs`（可选）

**限额**：
- 未认证搜索：**10 次/分钟**；核心 API：60 次/小时。
- 只在用户点击“搜索”时请求；输入防抖 ≥ 800 ms；最小 3 字符；缓存 24h；失败冷却 10 分钟。
- 显示 `X-RateLimit-Remaining`；为 0 时禁用搜索并提示“稍后/在浏览器打开/配置 token”。
- 可选 GitHub token（`secrets.dat`）：提高限额；不强制；不记录。

### 8.2 结果卡片

显示：
- 仓库名/作者/描述；
- Star、最近提交、License、是否归档/是否 fork；
- 是否有 Release/Windows 资产；
- “打开仓库”“导入安装”“查看 Release”。

过滤：
- 归档/无 Release/无 Windows 资产 → 只允许“打开仓库”；
- 无 License → 显示“许可未知”警告；
- 最近提交 > 24 个月 → 维护警告（不自动拒绝）；
- `topic` 不含 obs → 提示“可能不是 OBS 插件”。

### 8.3 粘贴导入

- 接受 `https://github.com/owner/repo`、`owner/repo`、`git@github.com:owner/repo.git`；
- 解析后调用 `GET /repos/{owner}/{repo}` + `releases/latest`；
- 显示仓库元数据、License、最近提交、资产列表；
- 用户选择资产 → 进入安装确认（高级模式）；
- 没有 Release → 打开仓库/文档，不安装。

### 8.4 外部搜索

- 按钮打开 `https://github.com/search?q=topic%3Aobs-plugin&type=repositories`（或带用户输入 query）；
- 只通过系统浏览器；不内嵌、不注入、不保存搜索内容。

## 9. Watt Toolkit（Steam++）加速

### 9.1 能做与不能做

| 想法 | 可行性 | 结论 |
|---|---|---|
| 检测 Watt 是否安装/运行 | 高 | 做 |
| 打开 Watt Toolkit | 高 | 做（官方安装路径/开始菜单） |
| 引导用户开启 GitHub 加速 | 高 | 做（图文/打开页面） |
| 应用使用系统代理下载 | 高 | 做（`HttpClient` 默认系统代理；可诊断） |
| 自动修改 Watt 配置 | 低/不安全 | 不做 |
| 自动改 hosts/系统代理/防火墙 | 低/不安全 | 不做 |
| 捆绑 Watt 安装包 | 许可证/安全风险 | 不做 |
| 内置第三方 GitHub 镜像 | 信任/安全风险 | 不做 |

### 9.2 推荐流程

```
打开插件广场 / 网络 Tab
  → 检测 Watt（进程/安装目录/开始菜单）
  → 未装：给官方 GitHub/官网入口（外部）
  → 已装未运行：按钮“打开 Watt Toolkit”
  → 已运行：提示“请在 Watt 内开启 GitHub 加速”
  → 应用做 GitHub 连通性/延迟诊断（HEAD/GET 小文件）
  → 仍慢/失败：提示重试、换时段、用系统代理、手动下载
```

- 不自动改任何系统网络设置；不改 Watt 配置；不读取 Watt 账号。
- 如果 Watt 已经设置系统代理，应用的 `HttpClient` 默认会走系统代理；这已经是“自动受益”，不需要额外配置。
- 可选“自定义代理”设置：用户自填 `http://127.0.0.1:port` 或公司代理；存 `prefs.json`（不含密码；如需认证，密码进 `secrets.dat`）。
- Watt Toolkit 是独立开源项目（GPL 系）；只做外部工具集成，不复制代码、不捆绑。

### 9.3 下载失败的回退

1. 直连 GitHub；
2. 系统代理/Watt；
3. 官方 Release 页面/浏览器下载；
4. 精选目录的备用官方源（如果有）；
5. **不使用**不明镜像/网盘/破解代理。

## 10. 管理页设计

### 10.1 Tab

| Tab | 内容 |
|---|---|
| **精选** | 现有分类 + 卡片；安装/更新/卸载按钮；兼容/维护/许可/AI 开销 |
| **搜索/导入** | GitHub 搜索框、结果卡片、粘贴 URL、外部搜索按钮 |
| **已安装** | 应用管理的插件 + 本机扫描到的插件；版本/路径/来源/更新/卸载/回滚/打开目录 |
| **更新** | 关注插件 + 可更新列表；一键更新（逐个确认） |
| **网络** | Watt 检测/启动/诊断；系统代理说明；GitHub 限流状态 |

### 10.2 已安装列表

数据来源：
- `installed.json`（应用管理）；
- `LocalPluginScanner`（本机所有插件 DLL/新布局）；
- `PluginCatalog`（匹配 id/名称/DLL）；
- OBS 日志（可选：加载失败/重复插件）。

显示：
- 插件名/版本/发布者/路径/来源（应用安装/手动/未知）；
- 兼容性（OBS 版本）；
- 更新可用（GitHub latest）；
- 操作：更新/卸载/回滚/打开目录/查看许可/关注；
- 未管理插件：只读，提示“不是本应用安装，删除请用插件自带卸载器”。

### 10.3 安全提示

- 安装确认对话框必须显示：插件名、版本、来源 URL、License、大小、签名/哈希状态、安装目录、将写入的文件数、是否需要重启 OBS、是否管理员。
- 未签名/哈希未知：红色/警告 + 勾选“我了解风险”。
- 任意仓库导入：额外警告“不是精选目录，未经过本项目验证”。
- 不把“安装成功”与“插件已加载”混为一谈；重启后检查日志/扫描，失败给“查看日志/回滚”。

## 11. 无障碍与老年模式

- 卡片/按钮：可 Tab、可回车/空格、可访问名称含插件名/版本/操作。
- 安装进度：`AutomationProperties.LiveSetting` + `RaiseAutomationEvent`；步骤列表可读；取消按钮可聚焦。
- 错误：图标+文字+颜色；错误码可复制；不自动消失。
- 老年模式：卡片单列、按钮 ≥48 DIP、文字更大；安装确认分步显示（来源/文件/风险），不把一屏塞满。
- 屏幕阅读器：不要在确认对话框自动朗读完整密钥/哈希；提供“朗读摘要”和“查看详情”。
- 键盘：所有操作可键盘完成；焦点返回原卡片；对话框焦点陷阱。

### 12.3 安全测试

- 恶意 zip：`..\..\Windows\...`、绝对路径、符号链接、超大文件、zip bomb；
- 伪造 `.exe`/错误签名/过期证书；
- GitHub 重定向到非白名单域名；
- 超长文件名/Unicode 路径；
- 目标目录 junction/symlink；
- 并发安装同一插件；
- 断网/磁盘满/权限变化；
- 日志中不出现 token/密钥/完整下载 URL 的敏感参数。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 任意插件是第三方 DLL | 精选 + 哈希/签名 + 用户确认 + 备份回滚；任意仓库高级模式 |
| 插件资产命名变化 | 目录热更新；`assetPattern` + 用户选择；发版后人工复核 |
| GitHub 限流 | 缓存、用户触发、可选 token、外部浏览器 |
| OBS 插件目录变化 | 能力探测 + 官方文档 + 用户确认；不硬编码 |
| ProgramData 权限 | UAC 提示；P1 提升助手；优先用户级（实测支持） |
| OBS 运行中替换 DLL | 要求关闭；不强杀；录制/推流中禁止 |
| 卸载误删 | 只删清单文件；备份/回收站；共享文件保留 |
| Watt 自动配置风险 | 只检测/启动/引导；系统代理自然受益；不改系统 |
| 内嵌浏览器 | 不做；外部浏览器 + 原生 API |
| 用户不懂“未签名” | 用一句话解释 + 推荐精选；高风险需勾选 |
| 插件兼容性 | 复用 `PluginCompatCore`；安装前提示；失败可回滚 |

## 14. 决策记录

### 14.1 已确认（2026-10-25）

| 决策 | 结论 |
|---|---|
| 整体路线 | **混合路线 D**：精选为主 + GitHub 原生搜索/粘贴导入；3.3.0 全上 |
| 精选插件 | **P0 主线**：一键安装/更新/卸载/回滚/管理 |
| GitHub 导入 | **P0 次级**：原生搜索 + 粘贴 `owner/repo`；高级模式 + 用户选资产 + 明确风险确认 + 可回滚 |
| 任意仓库自动安装 | **不做** |
| 内嵌 GitHub 网页 | **不做**；外部浏览器 + 粘贴导入 |
| Watt 自动配置 | **不做**；检测/启动/引导 + 系统代理 |
| 插件启用/禁用 | 3.3.0 不做（无稳定 API）；只做安装/更新/卸载 |
| 自动更新 | 默认关闭；用户点击/关注提示 |
| 插件哈希 | 精选必须；任意仓库尽力（GitHub digest/计算后展示） |

### 14.2 仍按建议默认执行

| 决策 | 默认 |
|---|---|
| 安装位置 | 用户级优先（如实测支持）；ProgramData 作为高级/UAC |
| 静默安装 `.exe` | **不做**；用户运行安装器 |
| 未签名插件 | 明确警告 + 用户勾选确认；精选优先 |
| ProgramData 提升 | P1 做提升助手；P0 明确 UAC/手动 |
