# OBS 排障助手 V2.9.5 发布说明

> 版本：**2.9.5**｜上一版：2.9.4
> 主题：**私密反馈通道修正**（GitHub 没有私信功能）· **安全策略改为中英双语**。

---

## 一、修正一条走不通的反馈指引

V2.9.4 新增「帮助与反馈」页时，把「安全问题请勿在公开 Issue 披露细节」写进了
`SECURITY.md`、行为准则与 Issue 表单 —— 但给出的私密通道里有一条是
**「GitHub 私信维护者」**。

**GitHub 并没有面向任意用户的私信功能**：`github.com/YYRMMAYO` 上没有任何「发消息」入口，
用户按这条指引走只会卡住，最后很可能退回公开 Issue 里去贴漏洞细节 ——
**一条指向不存在功能的指引，比不写指引更糟**。

本版把私密通道统一改成：

| 场景 | 渠道 |
|---|---|
| 安全漏洞（推荐） | 仓库 **Security** 选项卡 → **Report a vulnerability**（GitHub Security 私密报告，仅维护者可见） |
| 安全漏洞（备选）/ 隐私 / 人身安全 / 行为准则事件 | 邮件 **752139192@qq.com**（标题建议加 `[SECURITY]` / `[CoC]` 前缀） |
| 贡献 / 发布相关的问题（提交规范、打包流程、如何署名…） | 邮件 **752139192@qq.com** |

应用内的反馈卡也补了一行**安全上报引导**（中英双语），
让用户在点「到 GitHub 提 Issue」之前就知道「安全问题不能贴在这里，该走哪里」。

## 二、安全策略改为中英双语

`SECURITY.md` 现在是**中英两个完整版本**（不再只是中文正文 + 英文摘要）：

- 支持范围、私密报告方式、报告应包含的内容与**不应包含**的内容（流密钥 / 密码 / 未脱敏日志）；
- 我们关注的安全面：本地机密双层加密（DPAPI + AES-256-GCM、GCM 失败 fail-closed）、
  日志目录白名单与 `..` 二次校验、出站强制 https 且限官方域名、拒绝内网 / 回环（含 DNS rebinding 场景）、
  日志与诊断脱敏、配置写入的可回滚性；
- 响应时限（尽力而为、先致谢后修复）、不在范围内的情形。

同时把语言口径写清楚：**中文、英文、中英双语都可以** ——
`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、Issue 表单、PR 模板都加了同一句话。

## 三、行为准则与贡献指南同步

- `CODE_OF_CONDUCT.md`：中英**都是正式版本**（若有出入以中文版为准）；
  举报渠道由「GitHub 私信」改为**邮件**，处置梯度里的「禁止私信」也随之改为「禁止邮件」。
- `CONTRIBUTING.md`：中英双语完整版；新增「反馈与联系」一节说明三条渠道；
  并把 V2.9.4 审校里学到的两条约定写进正文 ——
  **占位符个数必须与实参个数一致**、**拼接键不能靠「取到非空」判存在**（缺键时 `Strings.T` 返回键名本身）。
- Issue 表单与 `config.yml`：新增「私密沟通 / Private contact」与「贡献指南」两条引导链接，
  并在表单末尾提示语言口径与「安全漏洞请勿公开」。

## 四、质量基线

- 双目标（`net10.0-windows` / `net6.0-windows`）均编译通过。

## 五、已知边界

- 本版是**文档与引导修正 + 一处界面文案补全**，不涉及功能行为变化；
- 邮件回复由个人维护，**尽力而为**，没有 SLA；
- 邮箱是公开渠道，请勿在邮件里附带未脱敏的流密钥或个人敏感信息
  （需要贴日志时请先移除推流地址与密钥）。
