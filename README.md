**OBS帮助助手**（V2.9.6 前的名字是「OBS 排障助手」，同一个软件、同一条升级链路）是面向直播新手的 OBS Studio 排障工具：**纯离线可用**——212 条问题的知识库、排障指引、日志分析规则全部内嵌在程序里，不联网也能查；连上 OBS 之后还能远程控制场景、录制与推流，并做一键体检。

这是原 Blazor WebAssembly + WebView2 版本的**原生 WPF 重构**（源码在 [`NOBS/`](NOBS/)），功能一比一对齐，但去掉了浏览器内核这一层：冷启动直接起窗口、自包含单目录发布、无需安装 WebView2 与 .NET 运行时。**V2.9.2 起支持中文 / English 即时切换**，**V2.9.3 起连随包离线内容也是中英双份**（知识库 212 条 / 插件目录 57 条 / 场景模板 12 套 / 排障指引全部英译，切语言即时生效）；**V2.2 起内置插件广场**（57 个精选插件 + 本机只读体检，v1.4 目录已全量复核）；**V2.1 起支持增量更新与知识库独立更新**。

> **兼容性**：主构建面向 **Windows 10 / 11**（.NET 10）；另有一套 **Windows 7 SP1 兼容构建**（.NET 6，最后一个支持 Win7 的 .NET 版本），安装包与便携包都在 Release 里，按系统选一个即可。
>
> **OBS 版本适配**：当前对齐 **OBS Studio 32.2.2**（最新稳定版）——日志解析、配置键、obs-websocket 协议与本机插件扫描（含 32.x 新增的「一插件一目录」插件根）均已按真实 32.2.2 环境核对，详见 [V2.9.3 发布说明](NOBS/RELEASE_NOTES_v2.9.3.md)。

## V3.0.0 亮点：数据安全 · 无障碍适配 · Win7 旧协议兼容 · 我的模板与我的知识库

> 这是 V3 的第一个正式版，改的是**底子**：让你敢把工作交给它。数据先保住、键盘能全程操作、
> 老机器（Windows 7 + OBS 27）也有一条支线可用；同时补上「把当前场景存成模板」和
> 「自己记一条排障笔记」这两个最常被问到的能力。
> 版本号、安装包、便携包、增量包与仓库标签都对齐到 **3.0.0**。

| | |
|---|---|
| **数据安全（本版主线）** | 所有「写用户文件」的动作走同一条事务通道：**写前快照 + 原子替换 + 校验读回**，中途失败自动回滚；设置、知识库、模板、录制归档都覆盖。路径一律做**越界护栏**（不再能写到目标目录之外）；OBS 密码等机密独立加密存储，不进普通配置 |
| **我的模板（D6 反向捕获）** | 把 OBS 里**当前的场景集合**一键存成模板：场景顺序、来源设置、位置 / 缩放 / 裁剪 / 旋转、滤镜、分组都带上；换机器或重装后一次落地。落地会逐项校验并**如实报告**哪一项没成功，读不到的信息写成显式占位而不是假装成功 |
| **我的知识库（D8）** | 除了内置 212 条，你可以自己写条目（含自建分类），与官方库按 id 合并、本地优先；支持搜索与标签；发现知识库写错或过时可以一键生成回执（Markdown + Issue 模板），正文自动脱敏 |
| **协议层补齐（D7）** | 节目截图存盘、滤镜开关 / 参数、媒体播放控制、音频监听类型、演播室模式切换与转场——主构建走 obs-websocket v5，Win7 兼容构建走 v4.9.1，两套请求名与字段名分别按官方协议对照实现（含 v4 的 60 个请求名全量核对与守卫测试） |
| **Windows 7 兼容构建** | 另有一套 `.NET 6` 构建（安装包 / 便携包 / 增量包同名带 `_win7`）：默认端口 4444、默认启用旧协议，数据目录独立为 `%LocalAppData%\OBS_Helper_Win7`，与主构建互不影响、可各自安全卸载 |
| **无障碍适配** | 连接徽章可 Tab 聚焦并用空格 / 回车激活；设置页 6 个背景色板可键盘选择（此前只能鼠标点）；图标按钮有可访问名称；Toast 主动抛实时区域事件（读屏能被通知）。新增静态检查脚本并接入 CI，承诺与已知限制写在 [`ACCESSIBILITY.md`](ACCESSIBILITY.md) |
| **国际化机制与守卫** | 界面与随包内容中英双语，切换即时生效（含代码拼出来的文案原地重放）；英文内容资产缺失时**界面上会说明哪几块回退成了中文**，不再悄悄显示中文 |

## V2.9.4 亮点：简单录像 · 帮助与反馈页 · 仓库封面与社区文件

> 一句话：V2.9.3 解决的是「配置长什么样」，V2.9.4 解决的是「点一次就能录上，且录的时候心里有数」。

| | |
|---|---|
| **简单录像：三档预设，一个词配好并开录** | 把「配好 → 验好 → 开录」收进首页一张卡。预设只回答「录什么」：**快速录像**（1080p / 60fps，通用推荐）、**会议 / 网课**（30fps，文件小、CPU 友好）、**游戏高码率**（60fps + 自动分段，长录制不产生单个巨型文件）。落到配置上的写项只有「录像格式 / 录像质量 / 音频轨 / 分段」这几类可验证的键——**仍然不碰推流参数、输出模式、编码器族与码率**，那些属于用户自己的选择 |
| **OBS 没启动也能一键进入可录状态** | 录不了的第一大原因是 OBS 根本没开：从注册表 `DisplayIcon` 与常见安装目录解析 `obs64.exe`，拉起后每 1 秒轮询等 obs-websocket 就绪（最长 75 秒），就绪即自动开录。字符串解析与磁盘探测刻意分成两层，**找不到 exe 就不猜路径**，直接提示用户自己启动；文件通道改完还会提示「要重启 OBS 才生效」 |
| **「现在能不能录」只有一行结论** | 不想读六行自检清单的人只看这一行：就绪，或者阻断 + 原因 + 出口。阻断按硬门槛排序（正在推流 → 缺配置 / 文件通道写不了 → OBS 在跑但没连上 → 自检失败项 → 警告项）。原先这两种情形会笼统掉进「OBS 在跑但没连上」，真实原因（**直播中不能改输出参数**）反而看不到 |
| **录制中看得到已录时长与剩余可录** | 「还要多久录满」是录制场景第一大未知：时长优先用 OBS 自报的 timecode（**暂停不计入**），拿不到才退回本地计时；剩余按预设码率 × 1.5 冗余估算，低于 10 分钟提示低空间。首页卡、控制台输出区与托盘 ToolTip 共用同一份状态 |
| **录完找得到** | 停止后读回文件大小（正面回应「录完才发现是空文件」），装了 ffmpeg 可一键无损转封装成 MP4，没有时给 OBS 自带「重新封装录像」的菜单路径，而不是留一个点了报错的按钮 |
| **反馈终于找得到了** | V2.9.3 的反馈卡只埋在「工具箱」与「搭建」页底部——要反馈的人得先猜到它在哪一页，等于没有入口。本版新增**一级导航「帮助与反馈」**：反馈表单 / GitHub Issue / 离线二维码，外加**一键复制报错材料**（版本号 + 系统 + OBS 连接与场景 + 录前自检结论，**不含路径、设备名与日志原文**），并在首页快捷入口与托盘菜单各留一个入口 |
| **仓库封面与社区文件** | 重绘矢量图标（`assets/icon.svg`）与封面（`assets/banner.svg` + 1280×640 社交预览），用脚本渲染成 PNG 一并入库（GitHub 社交预览只吃位图）；补齐 GitHub 社区标准缺的五项：行为准则 / 贡献指南 / 安全策略 / Issue 表单 / PR 模板 |
| **质量基线** | **626 项单元测试全部通过**（上一版 565 项，本版新增 61 项）。新增部分钉的是「编译器看不见」的错法：预设只写录制侧参数、三档预设的分段差异、就绪判定的优先级与三种阻断原因互不相同、`DisplayIcon` 的四种真实形态（含目录名里带逗号）、剩余可录的边界（0 码率不除零 / 负数归零 / 10 分钟阈值）。三轮分视角审校见 [审校记录](NOBS/docs/reviews/REVIEW_2026-10-05-v2.9.4.md) |

> **已知边界（如实说明）**：简单录像的预设取值与「拉起 OBS → 自动开录」这条链路**没有对真实 OBS 做过端到端验证**，
> 只做到协议 / 键名 / 纯逻辑单测级别；剩余可录是**估算**而非实测写入速率；便携版与绿色解压版 OBS 的安装路径识别能力有限，

- **迷你小窗** — 置顶小窗一键开始 / 停止录制与推流（含虚拟摄像头），可拖拽、记住位置；托盘菜单、控制台页按钮或全局热键随时呼出
- **全局热键** — 系统级快捷键（默认 `Ctrl+Alt+R/S/C/M/O`），全部可在设置页改键或停用
- **场景自动切换** — 按前台窗口标题自动切换场景，支持关键词 / 正则规则，规则表在设置页管理

### 保持健康 & 快速开播

- **系统监控** — CPU / 内存 / 网络上下行 / 磁盘空间实时曲线（近 2 分钟），与 OBS 渲染帧率、丢帧数据联动，磁盘空间不足时预警
- **场景模板** — 6 套内置直播间模板，连上 OBS 一键落地场景与来源（自动设置过渡与时长）；未连接时可导出为标准场景集合 JSON
- **OBS 配置管理** — 配置目录检测、备份 / 导出（ZIP，默认脱敏不含推流密钥）、导入（覆盖 / 合并，自动预备份）、轻度重置与彻底重置
- **直播搭建** — 从零到开播的 6 步流程 + 10 个主流平台的推流配置
- **外观** — 浅色 / 深色 / 跟随系统，4 档字号，高对比与减少动画
- **语言** — 简体中文 / English 即时切换（默认中文，无需重启）；安装向导里选定的语言是首次启动的默认值。**界面与随包内容（知识库 / 模板 / 插件目录 / 指引）同步跟随**
- **一键部署录制环境** — 搭建页的录制环境卡：逐项列出推荐值与当前值，勾选后先备份再落地，可一键回滚
- **简单录像** — 首页的简单录像卡：三档预设一键配好并开录，OBS 没启动时会先拉起并等就绪；录制中显示已录时长与剩余可录；停止后可打开目录或一键转 MP4
- **获取 OBS** — 官方三条入口 + 应用内下载官方安装包（带进度、可启动安装向导）+ 瓦特工具箱 / 微软商店两条备选通道
- **帮助与反馈** — 一级导航直达：表单二维码随包离线可扫、GitHub Issue 入口，**安全上报引导**（邮件 / 仓库 Security 私密通道），以及**一键复制报错材料**（版本与检测结论，不含路径与日志原文）

## 智能诊断

连上 OBS 后一键体检，三种引擎可选：

| 引擎 | 原理 | 成本 |
| --- | --- | --- |
| **本地规则引擎**（默认） | 确定性离线规则匹配，与日志分析同源 | 免费、纯离线 |
| **免费 AI（内置）** | 两条通道——**智谱免费模型**（国内直连最稳，密钥构建时加密内嵌）与 **Pollinations**（国外免 Key 公共通道）。本地限频：智谱 **10 次/天**、Pollinations **20 次/天**，独立计数、互不挤占，每天 0 点恢复 | 免费、免注册 |
| **云端大模型** | OpenAI 兼容接口 + function calling，接入你自己的 API Key（双层加密保存在本机） | 你的 API 费用 |

云端 / 免费失败时**自动回退本地引擎**，并在结果中说明原因。免费档为单轮普通对话（不做知识库工具调用）；需要多轮深度排查或更高频使用，请接入你自己的云端 API。

## 隐私与安全

所有数据只存在本机：

- **偏好**（外观、语言、收藏、步骤进度、连接设置、热键键位、自动切换规则、托盘行为）→ `%LocalAppData%\OBS_Helper\prefs.json`——明文 JSON，**均不含任何凭据**
- **OBS 密码与 AI API Key** → `%LocalAppData%\OBS_Helper\secrets.dat`——**双层加密**：值先经 AES-256-GCM（密钥由本机 `MachineGuid` 经 PBKDF2-SHA256 派生）加密，整个文件再经 DPAPI（绑定当前 Windows 用户 + 应用熵）加密；换机 / 换用户无法解开，即使文件被离线窃取也无法还原

**发现了安全漏洞？** 请勿在公开 Issue 里披露细节 —— 走仓库 **Security → Report a vulnerability** 私密通道，或发邮件到 **752139192@qq.com**（标题加 `[SECURITY]`）。完整策略见 [SECURITY.md](SECURITY.md)（中英双语）。中文或英文都可以。

只有在你**主动开启**「免费 AI」或「云端诊断引擎」并发起诊断时才会联网，且请求前会先对日志脱敏。OBS 配置备份 / 导出默认不含推流密钥（可勾选包含），密码与 Token 自动脱敏。

## 构建

需要 [.NET 10 SDK](https://dotnet.microsoft.com/download)（构建 Win7 兼容目标时会自动拉取 .NET 6 的参考包）；
打安装包还需要 [Inno Setup 6](https://jrsoftware.org/isdl.php)。

```powershell
# 在仓库根目录
cd NOBS

# 跑起来看看
dotnet run --project OBS_Helper.Wpf

# 双目标：主构建 + Win7 兼容构建 -> 安装包 / 便携 zip / 增量包 / 知识库资产
.\build.ps1

# 只出主构建（快速迭代时）
.\build.ps1 -SkipLegacy

# 额外出一个单文件 exe（主构建）
.\build.ps1 -SingleFile

# 没装 Inno Setup 时只出便携包
.\build.ps1 -SkipInstaller

# 跳版本发布：指定增量包基准（让停留在更早版本的用户也能直接增量升级）
.\build.ps1 -DeltaBaseVersion 2.0.0

# 发布后校验增量包可完整升级（模拟升级 + 全文件 SHA-256 比对）
python scripts\verify_delta.py --old PAKE\windows\OBS_Helper_Portable_2.9.5.zip --delta PAKE\windows\OBS_Helper_Update_2.9.6.zip --publish OBS_Helper.Wpf\bin\Release\net10.0-windows\win-x64\publish

# 全量单测（含中英内容对等 / 资产按语言装载 / INI 打补丁 / 版本判据等）
dotnet test OBS_Helper.Wpf.Tests\OBS_Helper.Wpf.Tests.csproj -c Release
```

产物落在 `NOBS\PAKE\windows\`：

- `OBS_Helper_Setup_2.9.6.exe` — 安装包（主构建，MinVersion 10.0，向导含语言选择页）
- `OBS_Helper_Setup_2.9.6_win7.exe` — 安装包（Win7 兼容构建，MinVersion 6.1sp1）
- `OBS_Helper_Portable_2.9.6.zip` / `…_win7.zip` — 解压即用
- `OBS_Helper_Update_2.9.6.zip` — 增量更新包（含 `update_manifest.json`，应用内增量更新用）
- `OBS_Helper_Portable_2.9.6.exe` — 单文件（需 `-SingleFile`）
- `OBS_Helper_Knowledge_2.9.6.json` / `…2.9.6.en-US.json` — 问题库热更新资产（中英各一份）
- `OBS_Helper_Plugins_2.9.6.json` / `…2.9.6.en-US.json` — 插件广场目录热更新资产（中英各一份）
- `manifests/manifest_<ver>.json` — 各版本完整文件清单（SHA-256，增量包 diff 基准；不随 Release 发布）

  OBS_Helper.Wpf.Tests/    1209 项单测（直接链接纯逻辑源文件，不引用整个 WPF 工程）
  build.ps1                Windows 构建与打包脚本（双目标：安装包 / 便携 / 增量包 / 清单 / 内容资产）

换肤与换语言走的是同一条路：**把当前主题的调色板 / 当前语言的文案整体写进 `Application.Resources`**，
XAML 一律用 `DynamicResource`（主题键直接用、文案键写作 `Loc.<键>`）引用，
所以两者都是整窗即时生效的，不需要重建窗口或重启。
代码里拼出来的文案由 `LocalizationService` 广播事件、主窗口把当前页面原地重放一次刷新。
