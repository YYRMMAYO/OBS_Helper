## 1. 第一轮：功能正确性

**目标**：确认「所有用户可见文案都走文案表」且「切换语言真的即时生效」。

### 1.1 扫出的问题（均已修复）

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1.1 | **`ObsBackupService` 整个文件漏翻**（30 处：备份进度、导入 / 导出错误、扫描拒绝原因、导入改名后缀） | 英文界面下做备份 / 导入 / 重置时，弹出的错误与进度全是中文 | 全部改走文案表（`backup.*` / `scan.*`） |
| 1.2 | **`KnowledgeBaseUpdater` 5 条返回消息未翻**（拉取失败 / 内容无效 / 写入失败 / 检查异常） | 这些字符串会原样显示在「设置 → 关于」与更新弹窗的状态行 | 改走 `kb.*`（`FileLogger` 的技术日志按约定保留中文） |
| 1.3 | **`NavigationService` 的「未注册的路由」明细未翻** | 该异常经 `ReportError` 拼进用户可见的报错弹窗 | 新增 `err.detail.unregisteredRoute` |
| 1.4 | 多处静态字段 / 构造期缓存把文案冻在首次访问的语言（引导步骤、搭建向导、助手示例问句、工具箱处方、**AI 工具 schema**） | 切换语言后这些位置仍显示旧语言 | 一律改为**属性**（每次取文案）；`ObsToolRegistry.Tools` 由构造缓存改为每次现建 |
| 1.5 | 严重度 / 步骤难度 / 插件角标 / 冲突软件风险色是**展示文案但被逻辑使用** | 英文数据下卡片配色与排序会塌掉；XAML `DataTrigger` 在中英切换后全部落空 | 新增 `DataValues` 做跨语言判定；冲突扫描把 `RiskLevel`（逻辑）与 `Risk`（展示）拆开；`DiagnosticSeverityMapper` 同时认中英取值 |

### 1.2 保留为中文的部分（**有意为之**，已在代码注释与发布说明中写明）

- `FileLogger` / `Debug.WriteLine` 的技术日志：排障材料而非界面内容，混入界面语言会让跨版本比对与检索变难；
- Headless 自检报告（`selftest_result.txt` 与其检查项描述）：给开发者 / CI 看的构建产物；
- `DataValues` / `DiagnosticSeverityMapper` 里的中英**逻辑取值**、日志正则里的中英关键字、`SceneTemplate.Transition` 的默认值（别名表同时认中英）、`Strings.DisplayName` 的语言名（各语言用各自语言书写）。

### 1.3 收尾检查

- XAML 属性值里已无硬编码中文（仅剩注释）；
- `.cs` 里的中文串只剩上述 1.2 类与日志；
- 运行时：自检新增 `i18n`（三个代表控件的文案解析）与 `i18n-swap`（中 → 英 → 中，断言导航项与顶栏即时跟随、往返还原）——**21 项全 PASS**。

## 2. 第二轮：安全与数据

**目标**：确认改动只换了文案，没有动摇护栏与数据边界。

| # | 检查项 | 结论 |
|---|---|---|
| 2.1 | `ObsSafePath` 的路径护栏（越界 / 根目录 / 保留子目录 / 符号链接 / 系统目录） | 判定逻辑与常量**逐字未动**，只换了异常文案 ✔ |
| 2.2 | 官方下载白名单（`obsproject.com` 含子域、`github.com/obsproject/obs-studio`）与签名者名 | 常量仍是硬编码；签名者名作为**参数**注入文案（`{0}`），翻译改不到它 ✔ |
| 2.3 | 备份「原因」传入 `CreateBackupAsync` 后进入**文件名**与包内清单 | 已确认它**只用于展示**（列表页从文件名抠出原因段显示），无任何逻辑按原因文本分支；因此跟随界面语言是安全的（英文用户得到英文文件名）。中文用户所见与旧版完全一致 ✔ |
| 2.4 | `language.ini`（安装向导写、应用读） | 固定文件名 + `AppContext.BaseDirectory`，无路径拼接；内容经 `Strings.IsSupported` + `Normalize` **白名单归一化**，任意值只会落到中文或英文 ✔ |
| 2.5 | 语言标识比较与大小写 | 全部 `Ordinal` / `OrdinalIgnoreCase`，无 `ToLower()` 这类区域性敏感调用，土耳其语 `i/I` 无关 ✔ |
| 2.6 | 语言偏好写入位置 | 复用 `LocalStore` → `prefs.json`，明文键值、不含任何凭据（凭据仍在 DPAPI + AES-GCM 的 `secrets.dat`）✔ |
| 2.7 | 安装包目录名 / AppId / 卸载标识 | **刻意不随语言变化**：Inno 会记住安装目录并在升级时复用，若随语言变化，英文用户重装会落到第二个目录、应用内增量更新也会找不到目标文件 ✔ |
| 2.8 | 语言切换是否影响数据文件 | 不影响：本版**未**新增内容资产，知识库 / 模板 / 插件目录 / 指引仍是原来那几份，中英界面读的是同一份数据 ✔（内容英译见 `docs/I18N_EN_CONTENT_PLAN.md`） |

## 3. 第三轮：构建与边界

**目标**：确认产物能构建、版本一致、编码与文档不掉链子。

| # | 检查项 | 结论 |
|---|---|---|
| 3.1 | 版本一致性 | `csproj` Version/FileVersion/AssemblyVersion = 2.9.2、`.iss` 默认 `MyAppVersion` = 2.9.2；全仓扫描 `2.9.1` 只剩「历史版本说明 / 上一版发布说明 / 增量基准清单」等刻意提及 ✔ |
| 3.2 | 安装脚本可编译 | 用本机 ISCC 实编译通过；**警告仅有一条既有提示**（`PrivilegesRequired=admin` 与 `[UninstallDelete]` 触及 `localappdata`），与语言改动无关 |
| 3.2a | **只在本机验证是不够的：CI 编不过（发布后发现）** | 首轮本地编译用的是本机 Inno 6.5 **自带**的 `Languages\ChineseSimplified.isl`，而 CI 里 `choco install innosetup` 装的那份**没有这个社区翻译文件**，直接 `Couldn't open include file`。修法：把 `OBS_Helper.Wpf/installer/ChineseSimplified.isl`（MIT，文件头保留原作者归属）**入库并显式引用**，让本地与 CI 的编译输入一致、翻译版本被钉住。**验证方式**：把本机 Inno 的语言文件临时移走（复现 CI 条件）→ ISCC 仍成功编译 → 还原。教训已写进文档：涉及「外部工具自带资源」的改动，必须按 CI 的安装方式复现一遍 |
| 3.3 | `.iss` 语言页行为 | `[Languages]` 第一条 = 简体中文、`LanguageDetectionMethod=none` + `ShowLanguageDialog=yes` ⇒ 必定弹选择页且默认中文；`{language}` 经 `[INI]` 写入 `language.ini`；`{cm:...}` 覆盖快捷方式 / 卸载项 / 任务 / 完成页文案 ✔ |
| 3.4 | `.iss` 编码 | 按 UTF-8 **带 BOM** 保存。实测：Inno 6 对**无 BOM** 的 UTF-8 也会自动识别（用 `AppPublisher` 写中文进版本信息、回读验证），带 BOM 只是把这一点固定下来，避免换编辑器 / 换旧版 ISCC 后退化成 ANSI 解析 ✔ |
| 3.5 | `check_resources.py` | 原先只认 `Themes/*.xaml` 的键，现已把 `Localization/StringTable*.cs` 的文案键一并读入并映射成 `Loc.<键>`；实跑：全局资源键 121 + 文案键 1671，1392 处引用**全部可解析** ✔ |
| 3.6 | 测试确定性 | 语言是**进程级可变状态**，而大量断言比对成品文案；xUnit 默认并行会让「切到英文的测试」与「断言中文的测试」互相干扰（单跑过、全量挂）。已显式 `DisableTestParallelization`；连跑 3 次全绿。串行耗时约 1 秒，代价可接受 ✔ |
| 3.7 | 文档同步 | 根 README（中 / 英）版本徽章与「版本亮点」区块**只保留最近 2 条**（V2.9.2 / V2.9.1），旧版亮点段落已移除；NOBS/README 同步；`docs/ARCHITECTURE.md` 新增「16. 国际化」；`docs/CODEBASE.md` 新增 2.9 节与脚本 / 文档清单；新增 V2.9.3 内容英译计划 ✔ |
| 3.8 | 残留与草稿 | 已清理：试编译产物、`selftest_result.txt`、临时 no-BOM 探针脚本、临时的 `.en-US.json` 占位资产（本版不发布内容资产）；仓库内无新增临时文件 ✔ |
| 3.9 | CI 兼容 | `.github/workflows/ci.yml` 的三步（`dotnet test` → `build.ps1` → `check_resources.py`）在本地逐条复跑通过，无需改 workflow ✔ |

## 5. 遗留与已知边界

1. **随包离线内容仍是中文**（本版刻意不做）：英文界面下知识库 212 条、场景模板、插件目录 57 条、
   排障指引显示中文。做法、字段约定（哪些能译、哪些是逻辑键）、热更新通道改造与验收口径见
   [`../I18N_EN_CONTENT_PLAN.md`](../I18N_EN_CONTENT_PLAN.md)。
