# V3.3.0 开源复用与供应链审计

> 配套主文档：[`PLAN_V3.3.0.md`](PLAN_V3.3.0.md)
> 本文回答：**哪些开源项目可以借鉴/集成、哪些只能作为外部工具、哪些不能碰；如何验证一个项目不是“已经废弃的垃圾代码”**。
> **已确认（2026-10-25）**：Live2D 采用 VTube Studio 公开 API 集成；pixi-live2d-display 不作为 3.3.0 依赖；GPL 插件/工具只做外部集成。
> 结论先行：**能用公开协议就不抄代码；GPL 代码不进 MIT 主程序；Cubism/示例模型不随包；任何复用都要有版本、许可证、哈希和退出方案。**

---

## 1. 复用原则

1. **协议优先**：OBS WebSocket、VTube Studio API 都有公开协议；自己写 C# 客户端，比复制第三方实现更可控。
2. **许可证优先**：本项目是 MIT。MIT/BSD/Apache-2.0 代码可在保留声明的前提下借鉴；GPL/AGPL 代码不复制进主程序；专有 SDK 不随包。
3. **外部工具优先**：GPL 插件（DistroAV/Spout2/LocalVocal）、Watt Toolkit、VTS 等作为用户自行安装的外部软件；应用只做检测/启动/引导/协议调用。
4. **不复制“能跑但没人维护”的代码**：先看最近提交/Release/Issue/PR/构建可重复性；星多不等于可维护。
5. **不引入隐形供应链**：能不用 NuGet 就不用；必须引入时 pin 版本 + 哈希 + 许可证 + 安全公告 + 退出方案。
6. **不复制平台私有接口/抓包脚本**：平台登录、推流码、弹幕接口以官方文档/官方客户端为准；不逆向、不绕过。
7. **不复制 UI 自动化脚本**：平台 UI 改版即失效；只做白名单 + 失败回退。
8. **可替换**：每个外部依赖都有“不可用时怎么办”（手动/外部浏览器/官方安装器/回退方案）。

### 3.1 逐项结论

#### VTube Studio API（已选）

- 公开 API 文档、MIT；默认 `ws://localhost:8001`、UDP 发现 `47779`；鉴权/模型/NDI 请求都有文档。
- 只调用公开 API；不注入、不读内存、不改 VTS 配置。
- 风险：API 版本变化、用户拒绝授权、NDI 权限；用错误映射 + 回退采集处理。
- **不复制**其示例代码；按协议写自己的 `VTubeStudioClient`/`VtsProtocolCore`。

#### obs-websocket（只用协议）

- GPL-2.0；复制进 MIT 主程序会造成许可证冲突。
- 只使用请求名/字段/事件名；自己实现 JSON/WebSocket 封装（现有 `ObsWebSocketClient` 已经是这样）。
- 新增 `SetStreamServiceSettings` 也按协议实现，不复制代码。

#### DistroAV / Spout2 / LocalVocal（外部 GPL 插件）

- 活跃、有 Windows 构建；但 GPL-2.0。
- 不捆绑安装包、不复制代码；只做：
  - 检测是否安装；
  - 打开官方 Release/文档；
  - 用户自行安装；
  - 安装后通过 OBS 的 inputKind/属性探测使用。
- 如果未来要“一键安装”，也只下载官方资产并让用户运行安装器，不把 GPL 代码并入主程序。

#### pixi-live2d-display（不建议 3.3.0）

- MIT，但最近提交 2024-08-20；Live2D Cubism 5/新 Core 兼容性未验证。
- 依赖 PixiJS/Cubism Core；打包/CEF/许可证/安全面都增加。
- 如果未来坚持做浏览器自绘：
  - pin 到具体 commit；
  - fork 并自维护；
  - 建立 Cubism 4/5 模型夹具；
  - 过 Cubism Core 许可证评审；
  - 不把它作为默认路径。
- 3.3.0 结论：**不用**。

#### Live2D Cubism SDK（专有）

- 许可不是 MIT/BSD；不能按开源处理。
- 不随包分发 Core/示例模型；不内置示例角色。
- 如未来要自研渲染器，先做许可证/商务评审，再立项。

#### OpenSeeFace（未来）

- BSD-2-Clause、活跃；但 Python/ONNX 运行时、摄像头推理、性能/打包成本高。
- 只作为未来“自研面捕”的候选后端；3.3.0 不做。

#### VSeeFace / PrprLive（闭源）

- 不能复制代码；没有公开控制 API 的稳定承诺。
- 只做“已有窗口/NDI/Spout 采集”的兜底；不承诺自动加载模型/布局。
- 如果用户已经在用，提供窗口标题/进程检测与采集引导。

#### Watt Toolkit（外部工具）

- 独立开源项目；GPL 系（实施前复核 LICENSE）。
- 只做检测/启动/引导；不复制代码、不自动改 hosts/系统代理/配置、不捆绑安装包。
- 应用使用系统代理下载；如果 Watt 已设置系统代理，自然受益。

## 4. 许可证兼容矩阵

| 来源许可证 | 复制进 MIT 主程序 | 动态链接/外部进程 | 随包分发 | 建议 |
|---|---|---|---|---|
| MIT / BSD-2 / Apache-2.0 | 可以（保留声明） | 可以 | 可以（保留声明） | 优先；但仍要审计维护性 |
| GPL-2.0 / GPL-3.0 / AGPL | **不可以**（会传染） | 可以（独立进程/插件） | 需单独合规评估 | 只做外部工具/插件；不复制 |
| LGPL | 动态链接通常可以 | 可以 | 需合规 | 尽量避免；如用需法律评审 |
| 专有（Cubism/VTS 等） | 不可以 | 按许可调用 API | 需书面许可 | 不随包；只调用公开 API |
| 未声明/NOASSERTION | **不可以** | 谨慎 | 不可以 | 视为专有；先问作者 |
| CC0 | 可以 | 可以 | 可以 | 素材可用；保留来源记录 |
| CC-BY | 可以（署名） | 可以 | 可以（署名） | 必须署名；记录作者/URL/修改 |
| CC-BY-SA | 传染 | 谨慎 | 需同许可 | 避免进入闭源资产包 |
| 平台 Logo/品牌 | 不可以（商标） | — | 不可以 | 用文字/通用图标代替 |

## 5. “不要复制”的具体黑名单

以下类型即使“能跑”也不要直接复制：

- 来路不明的 Live2D Web Widget/加载器（常见无许可证、依赖旧 Cubism、含远程脚本）。
- 旧的 Electron/CEF 包装器（Windows 7/新版 OBS 不兼容；安全面大）。
- 从博客/论坛复制的 OBS WebSocket 旧协议代码（v4/v5 混用；字段错）。
- 抓包得到的平台私有接口/推流码脚本（违反 ToS、随时失效）。
- 随机 UI Automation 脚本（坐标点击、无回退、平台一改就坏）。
- 把 GPL 插件源码复制进 MIT 主程序。
- 未授权的 Live2D 示例模型/角色图/平台 Logo。
- 带遥测/广告/捆绑安装器的“插件下载器”。
- 需要关闭杀软/修改 hosts/安装根证书的“加速器”。

## 6. 素材审计（虚拟直播间）

### 6.1 原则

- 原创 SVG/PNG 优先；下载素材只用 CC0/CC-BY 等明确许可。
- 每个资产包 `LICENSES.md`；每个文件记录作者/来源/许可证/修改/哈希。
- 不使用同人图、动漫角色截图、平台 Logo、Live2D 示例模型。
- 不用“免费素材站”的整包下载；逐个核对。
- AI 生成图如使用，记录工具/日期/人工修改，并做法律评审。

### 6.2 来源分级

| 来源 | 许可 | 可用性 | 备注 |
|---|---|---|---|
| 本项目原创 SVG | MIT | **首选** | 记录作者/日期/源文件 |
| Kenney.nl | CC0 | 可用 | 保留来源记录；确认具体 pack |
| OpenGameArt | CC0/CC-BY/CC-BY-SA | 逐项 | CC-BY 署名；SA 避免 |
| SVG Repo | 每个图标不同 | 逐项 | 必须打开单图标页面确认 |
| unDraw | 以官网为准 | 可用 | 保留许可说明 |
| Unsplash/Pexels | 各自许可 | 谨慎 | 不用于角色/商标；注意人物肖像 |
| 同人图/动漫截图 | 无授权 | **禁止** | 版权/商标风险 |
| 平台 Logo | 商标 | **禁止随包** | 用文字/通用图标 |
| Live2D 示例模型 | 专有 | **禁止随包** | 用户自备模型 |

### 6.3 验收

- [ ] 每个 PNG/SVG 有来源/许可记录。
- [ ] 没有同人图/平台 Logo/Live2D 示例模型。
- [ ] CC-BY 有署名；CC0 有来源记录。
- [ ] 资产哈希与 manifest 一致。
- [ ] 没有从“素材下载站”整包抓取。
- [ ] 没有嵌入外部字体/远程脚本。

## 7. 供应链与发布

### 7.1 依赖策略

- 主程序：**零第三方 NuGet 包**（保持现状）。
- 允许的框架程序集：`System.Windows.Automation`（UIAutomationClient/UIAutomationTypes）、`System.IO.Compression`、`System.Text.Json`、`System.Net.WebSockets`、`System.Security.Cryptography`。
- 外部 JS/原生资产：只有许可证/维护性/安全评审通过才引入；默认不引入。
- 外部插件/软件：用户自行安装；应用只检测/引导/调用协议。

### 7.2 固定与校验

| 对象 | 固定方式 |
|---|---|
| 精选插件资产 | 版本 + 资产名 + SHA-256 + 大小；目录热更新 |
| 第三方安装器 | 官方 URL + SHA-256（有则）+ Authenticode + 签名主体 |
| VTS/平台客户端 | 只检测；不捆绑；不自动更新 |
| 素材 | manifest 记录 SHA-256/尺寸/许可证 |
| 开源代码借鉴 | 记录仓库/commit/许可证/改动；保留 NOTICE |

### 7.3 SBOM/记录

建议在发布物/仓库维护 `THIRD_PARTY_NOTICES.md`（或 `LICENSES/`）：

```
项目 | 版本/commit | 许可证 | 用途 | 是否随包 | 来源 URL | 备注
```

- 只做协议参考的（obs-websocket/VTS API）也记录“仅协议参考，未复制代码”。
- 外部可选插件记录“用户自行安装，不随包”。
- 素材记录作者/来源/许可证/修改。

### 7.4 验证命令（实施时跑）

```powershell
# .NET 依赖漏洞（当前无 PackageReference，仍可跑）
dotnet list OBS_Helper.Wpf/OBS_Helper.Wpf.csproj package --vulnerable --include-transitive

# 检查签名（示例）
Get-AuthenticodeSignature .\installer.exe | Format-List

# 计算哈希
Get-FileHash .\asset.zip -Algorithm SHA256

# GitHub 仓库元数据（需要网络）
# GET https://api.github.com/repos/{owner}/{repo}
```

> 本环境对 GitHub/Google 等网络时通时断；审计数据以 2026-10-25 能取到的 API/页面为准，实施前重新核对。

## 9. 结论（3.3.0 已确认）

| 对象 | 结论 |
|---|---|
| VTube Studio API | **采用**（协议集成；不复制代码） |
| obs-websocket | **只用协议**（不复制 GPL 代码） |
| DistroAV / Spout2 / LocalVocal | **外部可选插件**（检测/引导；不捆绑） |
| Cubism SDK/Core/示例模型 | **不随包**（专有；需书面许可） |
| pixi-live2d-display | **3.3.0 不用**（久未更新；如用需 fork/pin/测试） |

| Watt Toolkit | **外部工具**（检测/启动/引导；不自动改配置） |
| 素材 | **原创优先 + CC0/CC-BY**（记录许可；不用同人/Logo/示例模型） |
| 第三方插件安装 | **精选 + 哈希/签名 + 回滚**；任意仓库高级模式，不静默 |
