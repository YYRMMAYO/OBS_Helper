## 1. 需求与边界

### 1.1 需求

1. `黑夜` 模式显示 A（导播台）的设计；`白天` 模式显示 C（排版手册）的设计。
2. `跟随系统` 时，系统深色 → A，系统浅色 → C。
3. 设计本身不重新创作：A/C 的布局、组件形态、签名元素保持不变。
4. 切换模式不丢当前页面、输入、滚动位置、连接状态与正在进行的录制/推流状态。
5. 无障碍能力不能因为两套皮肤而分叉：同一功能、同一语义、同一键盘路径。

### 1.2 术语

| 术语 | 含义 |
|---|---|
| Theme | 用户选择的 `跟随系统 / 黑夜 / 白天`；对应现有 `AppearanceSettings.Theme` |
| Skin | 视觉语言；`SignalDark`（A）与 `ManualLight`（C） |
| 双壳 | 两个 Shell 视图，各自包含侧栏、顶栏、页面宿主 |
| 双视图 | 同一页面在 A/C 下各一份 XAML，绑定同一份页面状态 |
| 共享逻辑 | ViewModel / Presenter / Service；不依赖具体 XAML 的业务与状态 |

### 1.3 “设计不变”的判定标准

**默认条件**（用于视觉验收）：

- 100% 显示缩放、100% 应用字号、未开启高对比/老年模式/减少动画；
- 中文界面，窗口宽度 ≥ 1160 DIP；
- 正常鼠标与键盘操作。

在上述条件下，A/C 的布局、间距、层级、组件形态与设计板一致；允许因字体渲染、文本换行、系统 DPI 取整产生的 ±1–2 px 差异。

**允许的无障碍例外**（会改变少量视觉值，但不改布局）：

- 对比度不达标的 token 值提亮/加深（见 §5.3）；
- 焦点环、跳转链接、错误摘要等无障碍构件；
- 高对比、老年模式、字号缩放、减少动画下的间距/字号/颜色变化；
- 操作目标在无障碍模式下放大到 ≥44×44 DIP；
- 长英文/大字号导致的换行与滚动。

> 如果坚持“连这些例外也不能改”，则无法同时承诺 WCAG 2.1 AA；文档需要在发布说明中明确“未达标项”，不能宣称已满足无障碍基线。

### 1.4 非目标

- 不新增第三套皮肤；
- 不改变 OBS WebSocket 协议、录制/推流参数与任何写操作语义；
- 不改变现有路由与功能入口数量；
- 不在本版本重做移动端/Blazor 版；
- 不引入新的 UI 框架或第三方控件库。

## 2. 现状审计（2026-11-15 工作区）

> 以下均为静态核对结果；行数/数量会随代码变化，以源码为准。

### 2.1 主题与外观

| 事实 | 位置 | 说明 |
|---|---|---|
| 明暗模式 | `Services/AppearanceService.cs` | `Theme` 支持 `system / light / dark`；`IsDarkEffective` 解析系统主题 |
| 运行时应用 | `AppearanceService.Apply()` | 把颜色、圆角、字号、导航宽度、阴影、间距写入 `Application.Resources`；控件用 `DynamicResource` 读取 |
| 系统跟随 | `IsSystemDark()` + `UserPreferenceChanged` | 读注册表 `AppsUseLightTheme`，监听系统变更 |
| 强调色 | `AccentScheme.Catalog` | 每个强调色有浅色/深色两套色阶；`CurrentAccent` 由设置决定 |
| 高对比 | `HighContrastEffective` | 应用内开关 OR 系统高对比；高对比下背景强制回默认 |
| 无障碍/老年 | `Services/Appearance/UiProfileCore.cs` | 字号、密度、导航宽度、焦点、减少动画统一计算 |
| 壁纸 | `WallpaperService` | 图片背景覆盖整窗，导航/顶栏使用半透明表面 |

### 2.2 主窗口

| 事实 | 位置 | 说明 |
|---|---|---|
| 主壳 | `MainWindow.xaml`（336 行） | 左侧导航 + 顶栏 + 页面宿主 + 引导层 + Toast/Busy/Fallback |
| 导航项 | `MainWindow.xaml` | 16 个 `RadioButton`，分 4 组；图标通过 `Tag` 传入 `StreamGeometry` |
| 当前页标题 | `MainWindow.xaml` | `FontSize="{DynamicResource FontSizeXl}"`、`FontWeight="SemiBold"`，A/C 需要不同值 |
| 跳转链接 | `MainWindow.xaml` | 无障碍/老年模式显示“跳到主内容” |
| 覆盖层 | `MainWindow.xaml` | 引导、Toast、Busy 在窗口级，切皮肤时应保留 |

### 2.3 页面与 code-behind

| 事实 | 数值 |
|---|---|
| `Views/*.xaml` | 30 个视图/窗口 |
| `Views/*.xaml.cs` | 合计 17,139 行 |
| 最大 code-behind | `SettingsPage` 2,052 行、`PluginsPage` 2,499 行、`ConsolePage` 1,209 行 |
| `x:Name` 数量 | `SettingsPage` 185 处、`ToolboxPage` 64 处、`ConsolePage` 57 处、`MobileLinkPage` 52 处 |

结论：页面逻辑与具体控件名高度耦合。直接复制 XAML 会复制逻辑；正确顺序是先抽共享 ViewModel/Presenter，再做双视图。

### 2.4 样式

`Themes/Controls.xaml`（1,092 行）提供 `Card`、`CardButton`、`SoftPanel`、`Pill`、`NavTabButton`、`BaseButton` 等。多数颜色用 `DynamicResource`，但部分几何写死：

- `Card` 的 `CornerRadius` / `Padding` 走令牌，`BorderThickness="1"` 写死；
- `BaseButton` 模板的 `CornerRadius="{DynamicResource CornerRadiusSm}"`；
- `NavTabButton` 模板内是图标 `Path` + 文本，没有编号位；
- `CardButton` 的 `BorderThickness="1"` 写死。

这些正是 A/C 差异较大的地方，需要视图级处理，不能只换资源值。

### 2.5 无障碍现状（摘要）

以 `ACCESSIBILITY.md` 与当前代码为准：

- 已有：键盘焦点触发器的多数控件、skip link、危险确认框默认“取消”、Toast 实时区域 + 主动抛事件、连接徽章可键盘、背景色板可键盘；
- 已有静态检查：`NOBS/scripts/check_accessibility.py` 的 R1（无文字控件必须有可访问名称）、R2（实时区域声明 + 事件）、R3（鼠标自绘按钮必须可聚焦 + 键盘激活）；
- 仍有限：**未用 NVDA/Narrator 实测**、无 UI Automation 自动化、无访问键、无自定义 Tab 顺序、迷你小窗键盘入口不足、图表无文字替代、高对比语义覆盖有限；
- 高 DPI：`MainWindow.MinWidth=920`，1366×768 在 150% 缩放下可用逻辑宽度约 911 DIP，可能小于最小宽度。

### 2.6 壁纸与 AC 的冲突

A、C 的设计板都没有壁纸：A 是硬件面板，C 是纸面。现有 V3.5.0 的壁纸/玻璃/透明度会直接破坏两套设计。3.7.2 必须二选一：

1. **推荐**：A/C 下禁用自定义背景，保留用户壁纸文件与设置，设置页显示“当前主题暂不支持自定义背景”；
2. 或只允许 A 使用壁纸，但需要重新设计 A 的玻璃/压暗层，且不属于“设计不变”。

### 3.3 必须保留的签名元素

- **A**：顶部 `OFF AIR / ON AIR` tally、时间码、双 VU、等宽读数、面板内高光、红/青状态语义；
- **C**：01–16 编号目录、37 px 细体页标题、发丝线、等宽章节号、直角按钮、数据表式控制台。

这些不能靠“换一个 `CornerRadius` 资源”得到；必须在各自的 XAML/模板里实现。

### 3.4 字体与许可

- 只用 Windows 系统字体：`Bahnschrift`、`Segoe UI`、`Segoe UI Light`、`Microsoft YaHei UI`、`Consolas`；不随包分发字体文件，避免许可问题。

- A 的 `Bahnschrift SemiCondensed` 只用于拉丁字母与数字；中文仍走 YaHei。

## 4. 架构方案

### 4.1 Skin 解析

```csharp
public enum UiSkin { SignalDark, ManualLight }

// 不新增用户可见的 Skin 开关；由 Theme 唯一决定。
// system -> 跟随系统；dark -> A；light -> C。
UiSkin ResolveSkin(bool isDark) => isDark ? UiSkin.SignalDark : UiSkin.ManualLight;
```

- 保留现有 `Theme` 设置（`system/light/dark`），不新增“皮肤”选项，符合“黑夜 A / 白天 C”的要求。
- `AppearanceService.Apply()` 继续写横切资源（强调色、高对比、字号、密度、减少动画），并额外写 `ActiveSkin`。
- **不要让 Skin 独立于 Theme**，否则会出现“黑夜 + C”或“白天 + A”的第四种组合，设计和测试矩阵都会翻倍。

### 4.2 双 Shell

```
MainWindow (窗口级)
├─ ToastHost / BusyOverlay / Onboarding / FallbackBanner   ← 保留，不随 Skin 销毁
└─ ContentControl (ShellHost)
   ├─ SignalShell (A)      ← 侧栏 + 顶栏 + 页面宿主
   └─ ManualShell (C)      ← 侧栏 + 顶栏 + 页面宿主
```

- 两个 Shell 都是 `UserControl`，不各自开窗口；窗口尺寸、位置、托盘状态不变。
- Shell 只负责导航、顶栏、页面宿主与视觉壳；业务服务、连接、Toast、Busy 都在窗口级或单例服务中。
- 两个 Shell 共用同一个 `NavigationService`（路由、返回、深链、热键）；A/C 只是渲染不同。

**导航数据化**：把 16 个 `RadioButton` 收敛为一个 `NavItem` 列表（`Id / Label / Icon / Group / Route`），A 模板渲染“图标 + 文字”，C 模板渲染“编号 + 文字”。这样编号不会靠手写 16 个 TextBlock 维护，也保证两套的路由与选中态完全一致。

### 4.3 页面双视图 + 共享逻辑

推荐目录：

```
Views/
  Signal/   HomePage.xaml, ConsolePage.xaml, ...
  Manual/   HomePage.xaml, ConsolePage.xaml, ...
  Shared/   （可选）共享的小型 UserControl
ViewModels/
  HomeViewModel.cs, ConsoleViewModel.cs, ...
```

规则：

1. **每个页面两份 XAML，但只有一份状态与交互逻辑**；
2. 逻辑放在 ViewModel/Presenter，视图只做绑定、动画、无障碍属性；
3. 页面级服务（OBS、搜索、诊断、计时器）继续用 `AppServices` 的单例，不随视图复制；
4. 页面视图实现 `IPageStateAware`，用于切换 Skin 时保存/恢复 UI 状态。

**为什么不复制 code-behind**：`SettingsPage` 2,052 行、`PluginsPage` 2,499 行、`ConsolePage` 1,209 行，且大量 `x:Name`。复制后任何 bug 要修两遍，两套界面的行为必然漂移。共享化是这次改造的主体工作。

**为什么不用单 XAML + 两套 DataTemplate/ControlTemplate**：A/C 的导航结构、标题尺度、卡片/分节方式不同；把两套布局都塞进一个视觉树会变成两棵树的叠加，复杂度和可访问性都更差。两份 XAML 更直白，也更容易做视觉回归。

### 4.4 运行时切换与状态保持

切换流程：

1. 记录当前 `Route`、导航选中项、滚动位置、焦点元素的 `AutomationId`、输入框文本、下拉/复选/分段选择、展开状态、筛选条件；
2. 若存在模态对话框或正在拖拽：**延迟切换**，关闭对话框/结束拖拽后再执行；
3. 更新 `AppearanceService.Settings.Theme`，计算新 Skin；
4. 设置 `ActiveSkin`，`ShellHost` 切换到另一套 Shell；
5. 在新 Shell 中导航到同一 Route，恢复 `IPageStateAware` 状态；
6. 焦点回到原控件（按 `AutomationId`），找不到时回到页面标题；
7. 通过实时区域播报“已切换到黑夜模式 / 白天模式”；
8. 不重连 OBS、不重启计时器、不清空 Toast/Busy 状态。

**不要保留两棵完整的视觉树**：两套页面同时存活会让 OBS 事件、定时器、Toast 订阅翻倍，内存与焦点管理都会变复杂。切换时销毁旧视图、保留服务状态，是更安全的选择。

**过渡**：默认 150–200 ms 淡入淡出；`ReduceMotionEffective` 为真时立即切换；高对比模式下也不做淡入淡出（避免闪白/闪黑）。切换期间禁用重复点击。

### 4.5 服务与事件生命周期

- OBS 连接、录制/推流状态、计时器、诊断任务、Toast、Busy：全部在单例服务中，Skin 切换不重建；
- 页面视图订阅服务事件时必须在 `Unloaded`/`Dispose` 中退订；
- Shell 切换时显式 `Dispose` 旧页面的订阅，避免两个视图同时响应一次 OBS 事件；
- 托盘菜单、迷你控制条、计时器窗口、提词器窗口是独立窗口：本期建议**跟随当前 Skin 的语义色**，但只做一套结构，避免再翻倍；如果需要完整 A/C，另立设计任务。

### 4.6 导航、路由与热键

- 路由表不变；`Ctrl+F`、`Alt+Left`、托盘/深链跳转都走 `NavigationService`；
- 两个 Shell 的导航项必须产生相同的 `Route` 与选中状态；
- C 的编号是“目录序号”，不是快捷键；读屏名称必须包含“第 N 项 + 页面名”，不能只读数字；
- 返回按钮、页面标题、skip link 在两套 Shell 中保持相同的可访问名称与顺序。

### 4.7 设置、迁移与兼容

| 设置 | 3.7.2 行为 |
|---|---|
| `Theme` | `system/light/dark` 继续；映射到 A/C |
| `Accent` | A 默认信号青，C 默认信号蓝；用户自定义强调色可保留，但“恢复默认”按当前 Skin 取默认 |
| `BackgroundMode=image` | 推荐在 A/C 下忽略，保留文件与设置；设置页给出说明 |
| `UiRadius` | A 可自定义；C 强制 0（或在 C 下隐藏该项），否则破坏版式 |
| `FontFamily` | 正文可保留用户字体；C 的展示型标题由 Skin 固定，避免 37 px 细体被替换成粗体 |
| `HighContrast` | 优先级最高，覆盖 A/C；见 §5.7 |
| 旧配置 | 首次升级按现有 Theme 直接进入对应 Skin；不丢失壁纸/强调色/字号设置 |
| 回退 | 建议 3.7.2 保留一个隐藏的“经典外观”开关（仅一个版本），用于线上回滚；默认关闭 |

### 4.8 资源与文件结构（建议）

```
Themes/
  Common.xaml        ← 焦点、滚动条、转换器、通用文本
  Signal.xaml        ← A 的 Card/Button/Nav/Title/Pill 样式
  Manual.xaml        ← C 的对应样式
  Palette.xaml       ← 现有默认调色板（保留）
Controls/            ← 现有自定义控件；必要时加 Skin 参数
Shells/
  SignalShell.xaml(.cs)
  ManualShell.xaml(.cs)
Views/
  Signal/…  Manual/…
Services/
  AppearanceService.cs       ← 增加 ActiveSkin / ResolveSkin
  Appearance/UiSkinState.cs  ← 可选：切换协调器
  Ui/PageStateService.cs     ← 状态快照/恢复
```

不要在两套 Skin 中定义同名资源再同时合并到 `Application.Resources`；每个 Shell/页面在自己的 `Resources` 中合并对应字典，或用前缀键区分，避免“最后加载的皮肤覆盖另一个”的隐蔽 bug。

## 5. 无障碍设计

> 本节是 3.7.2 的硬约束。A/C 可以看起来完全不同，但**语义、键盘路径、朗读信息、焦点行为必须相同**。

### 5.1 原则与优先级

1. **系统高对比** > **应用内高对比** > **无障碍/老年模式** > **系统字号缩放** > **Skin**。
2. Skin 只改变视觉表达，不改变功能、路由、文案语义、控件类型与键盘顺序。
3. 状态不能只靠颜色表达：A 的 LED 必须同时有文字/图形；C 的印章必须同时有文字。
4. 无障碍模式允许改变间距、字号、目标尺寸、动效；这是“设计不变”的例外，必须在验收记录中写明。
5. 未实测的能力不得写成“已支持”：NVDA/Narrator、真机 DPI、UIA 自动化都要单独列证据。

### 5.2 两套 Skin 的共享契约

| 项目 | 要求 | A 落地 | C 落地 |
|---|---|---|---|
| 正文对比度 | ≥4.5:1 | `#EAF0FF` on `#0B0D10` = 17.05:1 | `#111` on `#FCFCFA` = 18.38:1 |
| 次要文字 | ≥4.5:1 | `#8B95A5` on `#15181D` = 5.88:1 | `#5E5E58` on `#FCFCFA` = 6.35:1 |
| 大字号 | ≥3:1 | 17 px/600 已远超 | 37 px/300 已远超 |
| 焦点环 | ≥3:1，2–3 px，1–2 px 偏移 | `#38E0C0` on `#0B0D10` = 11.67:1 | `#1F3BFF` on `#FCFCFA` = 6.54:1 |
| 交互边界 | ≥3:1 | 输入/按钮边框用 `#6B768C`（3.89:1）；`#262C35` 只做装饰线 | 交互边框用 `#111`；`#DCDCD6` 只做装饰线 |
| 键盘 | 所有操作可达，无鼠标独占 | 图标导航有名称；面板/表格可 Tab | 编号导航有名称；表格行可聚焦 |
| 焦点顺序 | 跟随视觉顺序 | 侧栏 → 顶栏 → 内容 | 目录 → 顶栏 → 内容 |
| 目标尺寸 | 常规 ≥24×24，推荐 32×32；无障碍/老年 ≥44×44 | 视觉紧凑，但无障碍模式必须放大 | 直角按钮不小于 32；老年 44 |
| 字体缩放 | 所有文字走令牌；功能文字 ≥10.5 px @100% | 9 px 标签需提亮，见 §5.3 | 37 px 标题可缩放；表格用 rem/令牌 |
| 减少动画 | 系统/应用开关均生效 | VU、扫描线、悬停动效可停 | 无动效依赖 |
| 状态表达 | 文字 + 形状 + 颜色 | Tally + 文本 + 灯 | 印章 + 文本 + 边框 |

### 5.3 对比度审计与最小修正

以下是设计板关键色的计算对比度（WCAG 公式，sRGB）。**这是本文最重要的无障碍发现：A 的暗标签与交互边框、C 的小字/序号均有多处不达标；不能“完全一像素不改”又宣称 AA。**

#### A（黑夜）

| 组合 | 对比度 | 结论 |
|---|---|---|
| 正文 `#EAF0FF` / `#0B0D10` | 17.05:1 | 通过 |
| 次要 `#8B95A5` / `#15181D` | 5.88:1 | 通过 |
| 品牌青 `#38E0C0` / `#0B0D10` | 11.67:1 | 通过 |
| 品牌底字 `#04241F` / `#38E0C0` | 9.86:1 | 通过 |
| 红标 `#FF4D4D` / `#2A1214` | 5.37:1 | 通过 |
| 琥珀 `#FFB547` / `#0B0D10` | 11.07:1 | 通过 |
| **暗标签 `#5C6675` / `#0B0D10`** | **3.35:1** | **不通过**（8.5–9 px 小字） |
| **暗标签 `#5F6B7A` / `#15181D`** | **3.28:1** | **不通过** |
| **交互边框 `#3B3D50` / `#15181D`** | **1.67:1** | **不通过**（按钮/输入框边界） |

修正：

- 功能性小标签（导航组名、单位、字段名）从 `#5C6675` 提到 **`#7F8B9A`（5.14:1）** 或 `#8B95A5`（5.88:1）；
- 交互边框（按钮/输入框/可点击卡片）从 `#3B3D50` 提到 **`#6B768C`（面板上 3.89:1）**；`#262C35` 只做装饰线；
- 纯装饰性分隔（不发信息的线）可以保留低对比，但不能承载文字；
- 小标签字号从 8.5–9 px 提到 **≥10.5 px @100%**，并随字号档位缩放；
- 状态灯必须配文字：`● 录制中`、`● 已连接`，不能只有一个红/绿点。

#### C（白天）

| 组合 | 对比度 | 结论 |
|---|---|---|
| 正文 `#111` / `#FCFCFA` | 18.38:1 | 通过 |
| 次要 `#5E5E58` / `#FCFCFA` | 6.35:1 | 通过 |
| 蓝 `#1F3BFF` / `#FCFCFA` | 6.54:1 | 通过 |
| 反白 `#FFFFFF` / `#111` | 18.88:1 | 通过 |
| **橙 `#E8590C` / `#FCFCFA`** | **3.49:1** | **不通过**（正文小字） |
| **灰 `#8C8C86` / `#FCFCFA`** | **3.29:1** | **不通过**（说明文字） |
| **序号 `#A6A69F` / `#FCFCFA`** | **2.38:1** | **不通过**（目录序号） |
| 发丝线 `#DCDCD6` / `#FCFCFA` | 1.34:1 | 仅装饰，不可作交互边界 |

修正：

- 小字橙色改用 **`#C2410C`（5.04:1）** 或 `#A63A00`（6.34:1）；`#E8590C` 只用于 ≥3:1 的大字/图标/边框；
- 说明文字从 `#8C8C86` 改用 **`#5E5E58`（6.35:1）**；
- 目录序号从 `#A6A69F` 改用 **`#6B6B66`（5.22:1）**；序号若只是装饰，也要保证读屏不依赖它，且视觉可辨；
- 发丝线 `#DCDCD6` 只用于分节；输入框、按钮、可点击卡片的边界必须是 `#111` 或 ≥3:1 的颜色；
- 选中态不能只靠蓝色：加粗、下划线/2 px 边或 `✓` 勾选。

> 以上修正只改颜色/字重/字号，不改布局；属于 §1.3 的“无障碍例外”。如果设计方不接受，必须在发布说明里列出“未达到 WCAG AA 的文本/组件”。

### 5.4 A（黑夜）专项

- **暗色不等于纯黑**：保留 `#0B0D10` 底、`#EAF0FF` 文字，避免纯黑+纯白造成光晕；面板用 `#15181D` 分层。
- **小字可读性**：A 的工业感依赖 8.5–9 px 等宽标签；落地最小 10.5 px，并允许 1.2–1.3 倍行高。原设计板上的极小字只适用于展示，不适用于 100% DPI 的软件界面。
- **VU / 时间码**：给 `AutomationProperties.Name` 和文字摘要（如“麦克风 -18 dB，正常”）；不要每秒更新读屏；更新频率限制在 1–2 秒或状态变化时。
- **状态色盲可辨**：录音红、推流青、警告琥珀都配文字与形状（圆点/方块/三角），不能只靠色相。
- **发光/扫描线**：纯装饰，`ReduceMotion` 或高对比下关闭；不承载信息。
- **焦点环**：在深色面板上使用 2 px `#38E0C0` + 1 px 深色外描边，保证在面板与卡片上都可见。
- **窗口控制**：最小化/最大化/关闭按钮必须有 `AutomationProperties.Name`（WPF 原生标题栏通常已有，但自绘时不能漏）。

### 5.5 C（白天）专项

- **1 px 发丝线**：150%/200% DPI 下使用 1 DIP + `UseLayoutRounding`/`SnapsToDevicePixels`；不要用 0.5 px，避免消失或发灰。
- **37 px 细体标题**：中文回退字重可能变粗；若实际回退到 Regular，视觉仍可接受，但要在 Windows 10/11 中文环境核对。大字号阈值只需 3:1，当前 `#111` 远超。
- **编号目录**：读屏名称必须是“第 01 项，首页”，不能只读“01”；当前项加 `AutomationProperties.ItemStatus="当前页"`。
- **下划线/选中态**：选中项用 2 px 黑线 + 字重，不只靠蓝色；hover 不能替代 focus。
- **表格化控制台**：场景/音源/输出行要有行标题与列标题；纯图形（电平条、缩略图）要有文字摘要或可访问名称。
- **焦点环**：白底上用 `#1F3BFF` 2 px + 2 px 偏移；在高对比下改用系统高对比色。
- **纸张/网格背景**：纯装饰；不要用低对比网格承载分组信息，分组必须靠标题/线/间距。

### 5.6 主题切换的无障碍行为

这是双 Skin 特有的风险，必须专门验收：

1. **播报**：切换完成后通过 `AutomationProperties.LiveSetting` + `RaiseAutomationEvent(LiveRegionChanged)` 播报“已切换到黑夜模式 / 白天模式”；不要把整页内容重新朗读一遍。
2. **焦点**：优先恢复到切换前的控件（按 `AutomationId`）；找不到时回到页面标题（`Focusable=True` + `HeadingLevel=Level1`）；不要抢走用户正在输入的焦点。
3. **模态**：对话框/向导/确认框打开时**延迟切换**；关闭后再执行，避免焦点与视觉树被替换。
4. **录制/推流**：切换不触发 OBS 重连/停录；状态由服务保持，切换后仍可朗读“录制中 00:42:18”。
5. **高对比**：高对比下 A/C 都渲染成高对比色，切换仍要播报；不要用淡入淡出造成闪白。
6. **减少动画**：关闭过渡，立即切换。
7. **读屏/UIA**：视觉树被替换后，UIA 客户端可能丢失当前节点；至少保证焦点落到新树的有效元素，并抛结构变化/实时区域事件。**需要 NVDA/Narrator 实测**，未测前不得宣称“切换对读屏无感”。
8. **键盘**：焦点落在原控件或页面标题；`Tab` 从当前焦点继续，不能回到已销毁的旧树；快捷键（Ctrl+F、Alt+Left）继续生效；不要留下两个隐藏 Shell 同时响应快捷键。

### 5.7 高对比 / 老年模式 / 字号 / 减少动画

| 模式 | 对 A/C 的约束 |
|---|---|
| 系统高对比 | 覆盖两套 Skin 的文本/背景/边框/焦点/状态色；A 的青、C 的蓝不得绕过；高对比下不使用壁纸 |
| 应用内高对比 | 同系统高对比；设置页必须能关闭，关闭后恢复用户原 Theme |
| 老年模式 | 导航/按钮 ≥44×44；字号 ≥18 px 起；隐藏装饰/壁纸；保留 A/C 的布局语言但放大 |
| 无障碍模式 | 字号/焦点/动效/朗读/键盘优先；允许 A 的密度变宽、C 的 37 px 标题变大 |
| 系统文本大小 | 继续乘 `SystemTextScaleFactor`（当前实现）；两套 Skin 都不得写死像素字号 |
| 减少动画 | 系统 `ClientAreaAnimation=false` 或应用开关；A 的 VU/扫描线、切换淡入、悬停动效全部停止 |

**已知取舍**：A 的紧凑表格在 200% 字号下可能溢出；优先允许行高/列宽增长与横向滚动，而不是缩小文字。C 的 232 px 侧栏 + 37 px 标题在 1366×768 / 150% 下可能超出 `MinWidth=920`，需要把最小宽度提到 1024 或实现窄屏折叠。

### 5.8 读屏 / UIA 专项清单

| 控件/场景 | 要求 |
|---|---|
| 导航项 | 可访问名称 = 页面名；C 额外含“第 N 项”；当前项 `ItemStatus` |
| 页面标题 | `HeadingLevel=Level1`；切换后焦点目标 |
| 图标按钮 | 必须有 `AutomationProperties.Name`；无文字按钮不得留空（R1） |
| 状态药丸（未连接/录制中/推流中） | 名称含状态，不只含颜色；变化时更新 |
| Toast / 错误 | `LiveSetting=Assertive` + 主动 `RaiseAutomationEvent`；错误不自动消失 |
| 连接徽章 | 可 Tab、空格/回车激活；名称含“已连接/连接失败/未连接” |
| VU / 时间码 / 迷你走势图 | 文字摘要 + 可访问名称；不要高频朗读 |
| 场景/音源/输出行 | 行标题 + 状态；点击区域可聚焦 |
| 对话框 | `Window.Title`、初始焦点、`Esc` 取消、危险操作默认“取消”、关闭后焦点返回 |
| 迷你小窗 | 提供键盘入口（或等价控制台入口）；不能既不可键盘又无替代 |
| 提词器 | 键盘滚动/退出；点击穿透时提示热键 |
| 引导 | 步骤标题/描述可读；当前步 `ItemStatus`；按钮名称；减少动画 |

### 5.9 测试矩阵与工具

**自动化**

- 现有：`dotnet test`、`python NOBS/scripts/check_accessibility.py`、`check_resources.py`、`check_docs.py`；
- 新增建议：
  1. `check_contrast.py`：从 A/C token 表读取前景/背景对，按 4.5:1（正文）/3:1（大字、UI、焦点）断言；
  2. `check_skin_views.py`：断言 30 个视图都有 A/C 对应或明确“仅一套”的豁免清单；
  3. UIA 冒烟测试（可选，需引入 UI Automation 测试依赖）：导航、主题切换、对话框焦点；
  4. 视觉回归：每页 A/C 截图，100%/125%/150% DPI 各一份。

**人工**

| 维度 | 覆盖 |
|---|---|
| 键盘 | 仅键盘走完首页/控制台/设置；Tab/Shift+Tab/Enter/Space/Esc |
| 读屏 | NVDA 与 Narrator 各一次：导航、状态、Toast、主题切换（**当前未做，列为 3.7.2 出口条件**） |
| 高对比 | 系统高对比开/关；A/C 各一次 |
| 字号 | 100%、128%、系统 200%；A/C 各一次 |
| DPI | 100%/125%/150%/200%；1366×768 与 1920×1080 |
| 长文本 | 中/英；英文长标签不截断、不重叠 |
| 动效 | 减少动画开/关；主题切换无闪白 |

### 5.10 证据边界（必须保留在文档里）

- 本文的对比度是**计算值**，不是屏幕实测；实际渲染受字体、次像素、主题高对比影响；
- **未使用 NVDA / Narrator 实测**；未做 UIA 自动化；不能写“支持屏幕阅读器”；
- 未在 150%/200% 真机复核；`MinWidth=920` 的溢出风险仍未关闭；
- 现有 `check_accessibility.py` 只覆盖 R1–R3，不检查朗读效果、焦点顺序合理性、高对比配色；
- 以上每一项在 3.7.2 发布说明里只能按实际测试结果写“已验证/未验证”。

| 2 · 其余视图 | 26 个视图/窗口；先补 A/C 设计再实现 | 全部路由两套可用；对话框/小窗不遗漏 | 4–8 周 |
| 3 · 无障碍与回归 | 高对比/老年/字号/DPI/读屏/截图回归/发布文档 | §7 验收全过；ACCESSIBILITY.md 更新 | 2–3 周 |

**总计**：4 页切片约 3–4 周；全量约 2–4 个月（单人，熟悉 WPF）。

### 6.2 页面顺序

1. 首页（A/C 差异最大，验证双视图）；
2. 控制台（数据密度、场景/音频/输出，验证表格 vs 卡片）；
3. 功能中心（卡片 vs 目录）；
4. 设置（表单、主题切换本身、无障碍开关）；
5. 诊断 / 监控 / 日志（图表与动态结果）；
6. 手机联动 / 模板 / 插件 / 搭建 / 工具箱；
7. 对话框、迷你小窗、计时器、提词器、新手引导。

### 6.3 先决条件

- **设计补齐**：除 4 个页面外，其余 26 个视图/窗口没有 A/C 设计板；“设计不变”需要先有设计，或明确“只保留一套结构”的豁免清单；
- **共享逻辑抽取**：至少先完成 4 个主页面的 ViewModel/Presenter，再开始复制视图；
- **状态清单**：先定义 `IPageStateAware` 的字段与恢复优先级；
- **高对比方案**：先定一套高对比色板，否则 A/C 会在系统高对比下产生两套未知结果。

## 7. 验收标准

### 7.1 视觉

- 4 个已设计页面在 100% DPI、默认字号下与设计板对照：布局、层级、组件形态一致；允许 ±2 px 与字体渲染差异；
- A 的 tally/时间码/VU、C 的编号目录/37 px 标题/发丝线必须存在；
- 125%/150% DPI 下无重叠、截断、横向溢出；C 的 232 px 侧栏有窄屏策略。

### 7.2 行为

- 同一路由在两套 Skin 下的功能、按钮、状态完全一致；
- 切换后：路由不变、输入不丢、滚动位置恢复、焦点可见、没有重复的 OBS 订阅；
- 切换耗时 <300 ms（不含网络）；内存不因反复切换持续增长；
- 录制/推流中切换不影响输出；
- 模态框打开时切换被延迟，关闭后执行。

### 7.3 无障碍

- `check_accessibility.py` R1–R3 通过；
- 新增对比度检查通过（正文 4.5:1、大字/UI/焦点 3:1）；
- 仅键盘可完成首页/控制台/设置的主路径；
- 高对比、老年、128%/系统 200% 字号、100%/125%/150% DPI 各一轮；
- NVDA/Narrator 主题切换朗读实测通过（若未做，发布说明必须写“未验证”）；
- A/C 的状态都不只靠颜色表达；
- 主题切换播报、焦点恢复、模态延迟有记录。

### 7.4 回归与文档

- `dotnet test`、`check_resources.py`、`check_accessibility.py`、`check_docs.py` 通过；
- `ACCESSIBILITY.md` 更新“已知限制/证据边界”；
- `README`/`NOBS/README` 的数字若变化，按 `check_docs.py` 同步；
- 3.7.2 发布说明写清“新增双主题/无障碍修正/未验证项”。

## 8. 风险与开放决策

| 风险/决策 | 影响 | 建议 |
|---|---|---|
| 17k 行 code-behind 共享化 | 最大成本；拖延会变成两套逻辑 | 先抽 4 页 ViewModel，再双视图 |
| 26 个视图没有 A/C 设计 | “设计不变”无从验收 | 先补设计板，再排期 |
| 壁纸与 C 冲突 | 纸感被破坏 | A/C 下禁用自定义背景；保留文件/设置 |
| 强调色用户自定义 | C 的蓝/橙体系被改 | 默认跟随 Skin；高级用户可覆盖 |
| 1366×768 / 150% | C 的 232 px 侧栏 + 37 px 标题可能溢出 | MinWidth 提到 1024 或窄屏折叠 |
| 主题切换闪白/焦点丢失 | 观感与无障碍风险 | 150–200 ms 淡入；减少动画时直接切；焦点恢复 |
| 两套 Skin 行为漂移 | 维护成本 | 共享 ViewModel + 双视图视觉回归 |
| 读屏未实测 | 不能宣称支持 | 3.7.2 前完成 NVDA/Narrator 冒烟 |
| 高对比只覆盖文本/线 | 状态色仍可能不达标 | 3.7.2 扩展语义色/焦点/图表 |
| 字体回退 | C 的 37 px 细体在中文下变粗 | Windows 10/11 中文实测并微调 |

**需要产品确认的开放项**：

1. 壁纸：A/C 都禁用，还是只允许 A？
2. 自定义强调色/圆角/字体：C 下是否允许覆盖？
3. 主题切换是否允许在录制中执行（建议允许）；
4. 迷你小窗/提词器/计时器是否也做 A/C 两套（本期建议只跟随语义色）；
5. 是否保留“经典外观”回滚开关（建议保留一个版本）；
6. 全量范围：4 页 / 全部 30 个视图，先定这个再谈排期。
