## 一、修复：知识库「GitHub raw 主通道」自上线起从未生效（既有缺陷）

知识库 / 插件目录的更新设计是**双通道**：主通道拉 GitHub raw（随 commit 即生效），失败才兜底拉 Release 资产。审校时实测发现**主通道的两条地址都恒返回 404**：

| 地址 | 实测 |
|---|---|
| `raw.githubusercontent.com/YYRMMAYO/OBS_Helper/master/OBS_Helper.Wpf/Assets/problems.json` | **404** |
| `raw.githubusercontent.com/YYRMMAYO/OBS_Helper/master/NOBS/OBS_Helper.Wpf/Assets/problems.json` | **200** |

根因：**仓库根目录下才是 `NOBS/`**（根下另有 README、assets 等），raw 路径少了这一层。`plugins.json` 同样如此。也就是说：

- 「raw 主通道」**从来没有生效过**——每次检查都在静默 404，然后落到 Release 资产兜底；
- 危害不是「拿不到数据」（兜底一直有效），而是**知识库只能随我们发 Release 才能更新**，
  「改一行 JSON 提交即全网生效」的设计承诺一直没兑现，而且本机日志里连一条失败记录都没有。

修复与加固：

1. **地址改正**为 `…/master/NOBS/OBS_Helper.Wpf/Assets/…`（问题库与插件目录两条）；
2. **失败可见**：raw 通道返回非 2xx / 空内容、Release 资产兜底不可用 / 返回非 2xx，全部记入应用日志
   （原实现只在抛异常时记一行，404 属于「静默返回」，这正是它能潜伏这么久的直接原因）；
3. **地址常量单独成文件** `Services/Update/KnowledgeBaseUrls.cs`（纯常量、无依赖），并配单测钉死：
   - 形状校验：https + `raw.githubusercontent.com` + `master` 分支 + 以仓库相对路径结尾；
   - **落地校验**：URL 里的仓库相对路径必须能在本机源码树里找到对应文件——
     少了 `NOBS/` 的那一版会直接测试失败（这是这次缺陷最强的回归防线，且不需要联网）。

> Release 资产兜底（`OBS_Helper_Knowledge_*.json` / `OBS_Helper_Plugins_*.json`）**保持不变**，
> 网络受限或 raw 被墙时仍然是可靠退路；两条通道现在都会如实记日志。

## 二、新手引导升级为「跳转式引导」（不再只是念文案）

V2.9 的引导是纯文字覆盖层：卡片居中、遮罩很重，用户读完还得自己去找入口。V2.9.1 改成**边看界面边讲**：

| 步骤 | 自动跳转到的页面 | 卡片上额外的跳转按钮 |
|---|---|---|
| 第一步 · 连上 OBS | `控制台` | ↗ 官网下载 OBS（站外） |
| 第二步 · 出问题先来这里 | `首页` | 搜索问题 → / 问我一下 → / 日志分析 → |
| 第三步 · 一键体检 | `诊断` | 工具箱 → |
| 第四步 · 开播、装修与调教 | `搭建` | 场景模板 → / 插件广场 → / 系统监控 → / 设置 → |

实现要点：

- **每一步在渲染时自动把主界面切到对应页面**（`pushHistory: false`，不污染返回栈），
  卡片上同时给出「本步对应页面」胶囊——页面名取自主窗口路由表，不手写，页面改名不会对不上；
- **卡片从正中挪到右下角、遮罩压到 ≈17% 黑**：引导的重点是「看界面」，遮罩太重会把刚跳过去的页面
  压得看不清，「跳转式引导」就白做了；遮罩仍拦住底下的点击，保持「跟着引导走」的语义；
- **额外跳转按钮**区分站内（`X →`，切页面）与站外（`↗ X`，开浏览器）；
- **引导结束清空返回历史**：引导过程里的跳转不该让用户上手第一下点「返回」就退回某个只是被介绍过的页面；
- **纯逻辑层补齐跳转契约**（`OnboardingGuide.cs`）：每步对应页面必须是非空、已注册、互不重复的路由名；
  卡片上的站内按钮不得指向本步已自动打开的页面；站外按钮必须是官方域名（见第三节）；
- **Headless 自检加强**：逐步真实导航 + 渲染，校验「页面名与路由表一致」「按钮数量与步骤定义一致」
  「外链落在官方域名下」，并比对自检期间的错误增量。

## 三、官方 OBS 下载入口（防「下载站」「银狐」类仿冒包）

背景：不少用户拿不到官方 OBS——搜索引擎广告位与「软件下载站」里混着仿冒安装包（常见捆绑安装器与
银狐类木马）。本版在所有合适的位置加上**只指向官方渠道**的下载入口：

- **官网**：`obsproject.com`（中文站 `https://obsproject.com/zh-cn`、下载页 `…/zh-cn/download`，实测 200）；
- **GitHub**：`github.com/obsproject/obs-studio/releases`（官方二进制发布页）；
- **安装包直链**：点「下载最新 Windows 安装包」时，经 GitHub API 解析**当前稳定版**的
  `*-Windows-x64-Installer.exe` 资产地址后交给浏览器下载——不写死版本号，资产改名 / 新版本发布都不会失效；
  解析不到就退化为打开官方发布页并说明「展开 Assets 选 Windows x64 Installer」。

安全设计（这次的重点是「跳出去的那一下不能被做手脚」）：

- **域名白名单**：所有外链必须 https 且落在 `obsproject.com`（含子域，如官方 CDN `cdn-fastly.obsproject.com`）
  或 `github.com/obsproject/obs-studio` 之下；API 响应被篡改 / 结构异常时**宁可拿不到直链**也不跳第三方；
- **常量化**：入口集中在 `Services/Update/ObsDownloadLinks.cs`，不散落 URL 字面量，并有单测覆盖
  正例（官网 / 中文下载页 / 官方 CDN / 官方 Release 资产）与反例（http、同形域名、他人仓库、第三方镜像、file://）；
- **提示用户自己核对**：界面给出「OBS 完全免费开源、下载不需要注册或付费、没有 Pro 版；安装前可核对
  数字签名是否为 `OBS Project Corporation`」——这是用户自己能验证的判据，比「请从官网下载」更有用。

入口位置：**搭建页顶部**、**工具箱（版本情报之后）**、**首页欢迎卡（未连上 OBS 时才出现）**、
**新手引导第一步**、**排障指引「快速自检」第 1 条**。

> 说明：直链交给浏览器下载，不做「静默下载到本地再运行」——用户能亲眼看到文件来源与签名，
> 这比应用替他下载更透明。

## 四、其他

- 路由名常量表从 `Navigation/NavigationService.cs` 拆到 `Navigation/Routes.cs`（纯常量、零 WPF 依赖），
  这样「引导里的路由名真的存在」可以被单元测试直接校验（架构文档里一直写的就是 `Routes.cs`，现在名副其实）；
- 单元测试工程链接了 4 个新的纯逻辑文件（Routes / KnowledgeBaseUrls / ObsDownloadLinks / ObsInstallerAsset）；
- Headless 自检的引导项描述更新为「4 步渲染 + 逐步跳转 + 进度点 + 显隐」；引导一步改为走**生产路径**
  （`NavigationService.Navigate`，async void）后再断言，不再由自检自己 `await NavigateAsync` 代劳 ——
  否则「引导真的会自动跳页」这件事根本没被验证。已用「故意写错一个路由名」做了反向验证：自检会失败并报出具体步骤；
- **文档修正**：中英文 README 里的问题库数量长期停留在「149 条（v2.0）」——实际自 v2.1 起已是
  **212 条（v2.2）**（见 commit `0a9d45e`，数据文件里 212 条问题、首页 10 个分类），本次一并校正；
- 工程与安装脚本版本号对齐到 **2.9.1**。

| 产物 | 说明 |

请用安装包或便携包覆盖升级 —— 这与以往发版的增量策略一致。
