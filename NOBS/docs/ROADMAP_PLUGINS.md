# 路线图：插件生态方向（V2.2 规划）

> 基于 2025–2026 年 OBS 生态公开调研（OBS 官方论坛、GitHub 各插件仓库、
> OneStream / Host-Stage / Bilibili 等中外评测文章，检索时间 2026-08），
> 结合本应用「离线可用 · 数据仅存本机」的定位制定的优化方向与具体功能清单。

---

## 一、调研摘要：2025–2026 OBS 插件生态六个信号


| #   | 信号                                                                                                                                                  | 对本应用的启示                            |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| 1   | **OBS 32.1 内置 Plugin Manager**（工具 → 插件管理器），官方开始正面处理"插件版本 / 兼容性"这个长期痛点                                                                               | 排障工具应跟进"已装插件体检"，与诊断流程联动            |
| 2   | **AI 类插件全面成熟**：Background Removal（v1.4.x）、LocalVocal（本地字幕翻译）、CleanStream（AI 降噪）稳定可用，但开销可观（抠像约 +5–15% CPU / 100–300MB 内存；字幕约 +5–10% CPU / 200–500MB） | 用户"装了 AI 插件就掉帧"会成为新的高频故障源，需要性能预算引导 |
| 3   | **StreamFX 实质停更**（OBS 30+ 兼容性恶化），社区转向**单一职责轻量插件**（Composite Blur、Advanced Masks 等接棒）                                                                | 老教程用户仍在装 StreamFX 报障，知识库应有替代迁移建议   |
| 4   | **多平台推流换血**：obs-multi-rtmp 在新版 OBS 上可靠性下滑（带宽骤降、编码过载、杀软误报），Aitum Multistream / Vertical（76 万+ 下载）成为主流推荐                                              | 多平台推流故障的诊断建议需区分插件代际，避免误导           |
| 5   | **竖屏 / 短视频分发成为刚需**（TikTok / Shorts / 视频号），Twitch 双格式推流进入测试                                                                                          | 竖屏搭建向导是高价值场景                       |
| 6   | **自动化常青树**：Advanced Scene Switcher 保持月更节奏（1.33→1.36），宏系统是结构化直播的事实标准                                                                                 | 自动化相关排障需求会持续增长                     |

## 二、本次已落地（随本文档同版本发布）

**插件广场页面**（`Views/PluginsPage.xaml(.cs)`，一级导航「插件」）：

- 7 个分类 × 26 个精选插件（自动化 / 视觉特效 / AI 智能 / 音频 / 多平台竖屏 / 录制后期 / 输入互动）；
- 全部链接指向 GitHub 仓库或 OBS 官方论坛插件区，**收录前逐一验证可达性（2026-08 全部 200）**；
- 支持关键词筛选（名称 / 描述模糊匹配）+ 分类 chips 过滤 + 「热门 / AI」徽标；
- 附安装小贴士（安装路径、重启生效、32.1 插件管理器、大版本兼容建议）。

## 三、后续优化方向（按优先级）

### P0 —— 与核心排障能力闭环

**P0-1 本地插件体检（只读）**

- 扫描 `%ProgramFiles%\obs-studio\obs-plugins\64bit`、`data\obs-plugins` 及便携版目录，枚举已装插件的 DLL 名称与文件版本；
- 插件广场顶部新增「本机已装 N 个插件」面板：列出清单、标注"广场收录 / 未收录"；
- 只读不改：不提供自动安装 / 卸载，规避安全与误删风险；
- 复用 `ObsPathService` 的路径定位能力。

**P0-2 日志分析 × 插件嫌疑联动**

- `ObsLogAnalyzer` 增加"插件加载失败 / 崩溃签名"识别（如 `LoadLibrary failed`、插件名 + crash 记录）；
- 诊断报告命中时给出：嫌疑插件名 → 一键跳转插件广场该条目（复用路由参数机制）；
- 知识库同步补充 StreamFX 替代迁移、obs-multi-rtmp 已知问题等条目（对应信号 3 / 4）。

**P0-3 插件数据外置到知识库**

- 把页内静态数组迁入 `problems.json` 同源的知识库 JSON，复用 `KnowledgeBaseUpdater` 的分离热更新通道；
- 收益：链接失效、新插件上架无需发版即可修复（与现有"110 条知识库 v1.5"机制完全一致）。

### P1 —— 降低上手门槛

**P1-1 直达 Releases 下载**

- 卡片增加「下载」按钮，跳转 `github.com/<repo>/releases/latest`；
- 用 Releases API 取最新版本号做角标展示；匿名限流 60 次/小时/IP → 结果缓存 + 启动节流，失败静默。

**P1-2 AI 插件性能预算评估**

- 结合监控页（`SystemMonitorService`）实时采样 CPU / 内存 / GPU 信息，在插件广场 AI 分类的卡片上给出个性化提示：
例："当前空闲内存 < 500MB，启用 LocalVocal 字幕可能加剧掉帧"；
- 与 P0-2 联动：掉帧诊断命中时若检测到 AI 插件，输出开销说明。

**P1-3 竖屏 / 多平台搭建向导**

- SetupPage 新增"竖屏 9:16 双画布"与"多平台同时推流"两条分步向导（基于 Aitum Vertical / Multistream 的实测流程），步骤可跳转对应问题条目与插件卡片。

### P2 —— 锦上添花

- **P2-1 插件更新提醒**：用户可在体检面板"关注"插件，启动静默查新（节流 24h），有新版仅 Toast 不弹窗；
- **P2-2 场景模板依赖标注**：模板落地前检测所需插件是否已装，缺失时给出一键跳转；
- **P2-3 英文界面**：i18n 时将插件广场描述纳入翻译范围。

## 四、原则与风险控制

1. **只读优先**：本机检测一律只读，安装 / 卸载永远由用户去官方渠道完成；
2. **链接可信**：仅收录 GitHub 官方仓库与 OBS 论坛资源，收录即验证可达性，外置知识库后支持随时远程纠错；
3. **限流友好**：任何在线查询（Releases API 等）都带缓存与节流，失败静默不打扰；
4. **隐私红线不变**：插件扫描结果仅存本机，不上传。
