## 1. 两种开播模式

### A. OBS 直推（RTMP / RTMPS）

```text
平台官方后台复制「服务器地址 + 推流码/直播码」
  → 应用写入 OBS（SetStreamServiceSettings）
  → 开播前检查
  → StartStream
  → 轮询 GetStreamStatus 确认 outputActive
```

- 优点：画质/码率/场景完全由 OBS 控制；不需要平台客户端；可多平台/多路（配合现有向导）。
- 缺点：需要平台提供推流码；部分平台只对特定账号/地区/资格开放。
- OBS 请求（v5）：
  - `SetStreamServiceSettings`，`streamServiceType="rtmp_custom"`，`streamServiceSettings={server,key}`；
  - `GetStreamServiceSettings` 复核存在性；
  - `StartStream` / `StopStream` / `GetStreamStatus`。
- **注意**：v5 请求名是 `SetStreamServiceSettings`，不是 `SetStreamSettings`；当前代码只有读取封装，写入需新增。
- v5 的 `SetStreamServiceSettings` 只有 `streamServiceType` / `streamServiceSettings` 两个字段，**没有 `save` 参数**；写入后要用 `GetStreamServiceSettings` 复核，是否随 OBS 配置持久化以 OBS 自身行为为准（不要假设重启后一定保留，UI 要允许用户再确认）。

### B. 平台客户端 + OBS 虚拟摄像头

```text
OBS 启动虚拟摄像头（StartVirtualCam）
  → 平台客户端添加“摄像头”源
  → 选择 OBS Virtual Camera
  → 平台客户端开始直播
```

- 优点：适用于不提供通用推流码的平台（抖音是典型）；平台侧负责推流/审核/互动。
- 缺点：OBS 只作为摄像头；平台可能压缩画质；平台客户端必须保持前台/后台运行；摄像头选择需要用户操作。
- OBS 请求：`StartVirtualCam` / `StopVirtualCam` / `GetVirtualCamStatus`。
- 平台侧：抖音官方帮助明确支持 OBS 虚拟摄像头作为摄像头源（见 §3.1）。

### C. 平台客户端自身的“第三方推流/推流码”

有些客户端在设置里提供“第三方推流”或“OBS 模式”，直接给出 RTMP 地址/密钥。这种情况优先走 A（直推），因为它比虚拟摄像头画质更好、控制更强。是否提供取决于平台/账号/版本，目录里用 `acquisition` 标记。

## 2. 平台目录数据模型

建议 `Assets/platforms.json` / `platforms.en-US.json`：

```jsonc
{
  "schemaVersion": 1,
  "updated": "2026-10-25",
  "platforms": [
    {
      "id": "bilibili",
      "name": "哔哩哔哩",
      "nameEn": "Bilibili",
      "region": "cn",
      "acquisition": "directRtmp",          // directRtmp | companionVirtualCam | companionThirdParty | manual | unsupported
      "officialSite": "https://live.bilibili.com/",
      "dashboardUrl": "https://link.bilibili.com/p/help/index#/tools-tutorial",
      "helpUrl": "https://link.bilibili.com/p/help/index#/tools-tutorial",
      "downloadUrl": "https://live.bilibili.com/liveHime",
      "companionApp": "bilibili-livehime",
      "stream": {
        "protocol": "rtmp",                // rtmp | rtmps
        "serverHint": "从官方开播设置复制",
        "keyLabel": "直播码"
      },
      "verifiedAt": "2026-10-25",
      "verifiedLevel": "officialHelp",     // officialHelp | officialApp | community | unverified
      "notes": "官方帮助中心给出 OBS 开播流程：直播间管理 → 开播设置 → rtmp 地址 + 直播码。"
    }
  ]
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `acquisition` | 推荐获取方式；决定 UI 走直推还是虚拟摄像头 |
| `dashboardUrl` | 官方后台/开播设置入口 |
| `helpUrl` | 官方帮助（优先于社区教程） |
| `downloadUrl` | 平台客户端官方下载页 |
| `companionApp` | 对应 `companion_apps.json` 的 id |
| `verifiedAt` / `verifiedLevel` | 最后核对日期/证据等级；UI 可显示“官方帮助已验证” |
| `notes` | 人话说明；不要写死按钮路径到代码 |

## 5. 平台客户端检测与下载

### 5.1 检测策略

不要只认一个 exe 名。用多信号交叉：

1. **注册表卸载项**：`HKLM/HKCU` 的 `Uninstall` 下显示名/安装位置/发布者；
2. **安装目录**：`Program Files`、`%LocalAppData%`、`%ProgramData%` 的已知目录；
3. **进程**：`Process.GetProcesses()` 按主模块文件名/产品名/公司名匹配；
4. **窗口**：`Process.MainWindowTitle`/窗口类名（只读，不注入）；
5. **Steam**：`appmanifest_1325860.acf` + 库路径（VTube Studio）。

每个信号给出 `Confidence`（high/medium/low）；低置信度只显示“可能已安装”，让用户确认；不要误启动同名恶意程序。

### 5.2 下载/安装模式

| 模式 | 适用 | 行为 |
|---|---|---|
| `officialPage` | 抖音/B 站等动态下载页 | 打开官方页面；用户下载/安装 |
| `directInstaller` | 有稳定官方直链 | 应用内下载 → 哈希/签名 → 用户点击运行安装器 |
| `store` | VTube Studio（Steam） | 打开 `steam://install/1325860` 或商店页；不静默装 Steam |
| `none` | 无官方桌面端 | 只给官方入口/手动 |

**统一要求**：
- HTTPS + 官方域名白名单；重定向后再次校验；
- 限制大小/超时/取消；MZ/PE 头；
- SHA-256（目录有则必须匹配）；
- `WinVerifyTrust` 校验 Authenticode；展示签名主体；
- **不静默安装**、不 `/S`、不替用户接受许可；
- 安装后重新探测；失败给“打开安装目录/官方页/重试”。

## 6. 推流码/密钥的安全 UX

### 6.1 原则

- 默认**不落盘**；只存在内存；写入 OBS 后尽快释放。
- 不写日志、不进诊断报告、不进 AI 请求、不进反馈附件。
- 不持续监听剪贴板；只允许用户点击“从剪贴板粘贴”。
- 不自动清空用户剪贴板（用户可能还要粘贴到别处）；提供“清除剪贴板”按钮。
- 可选“记住推流码”默认关闭；开启才写入 `secrets.dat`，并在 UI 明示。

### 6.2 UI

- 输入框遮罩（`••••••`），只显示长度/是否已填。
- “显示 5 秒”按钮：倒计时后自动遮回；读屏用户默认只听“已填写，长度 N”，不自动朗读密钥。
- “复制/粘贴/清除”三个明确动作；粘贴后校验非空/去空白/禁止换行。
- 平台服务器地址与密钥分开显示；服务器可给默认值但允许覆盖。
- 写入 OBS 前展示摘要：平台、服务器、密钥已填、将写入 OBS、是否开播；用户确认。

### 6.3 失败处理

| 情况 | 提示 |
|---|---|
| 服务器为空 | 从平台后台复制完整的 RTMP/RTMPS 地址 |
| 密钥为空 | 重新复制直播码；密钥可能过期 |
| 地址不是 rtmp/rtmps | 检查是否复制成了网页地址 |
| OBS 拒绝 | 查看 OBS 日志；不要盲目重试 |
| 开播后立刻断开 | 密钥过期/平台风控/网络；重新获取密钥 |
| 已在下行丢帧/拥塞 | 降码率/换节点；现有诊断/带宽工具 |

## 7. 虚拟摄像头流程（抖音为主）

### 7.1 OBS 侧

1. `VirtualCamCheckService` 检查驱动/插件；
2. 如果 OBS 未运行：复用 `SimpleRecordingService` 的拉起/连接链路；
3. `StartVirtualCam`；轮询 `GetVirtualCamStatus` 直到 `outputActive=true`；
4. 在 UI 显示“虚拟摄像头已开启”，并显示设备名（`OBS Virtual Camera`）；
5. 记录“本次由应用启动”标记；停止时只停自己启动的。

### 7.2 平台侧

**默认图文**（抖音官方步骤）：

1. 打开抖音直播伴侣并登录；
2. 添加素材 → 外接设备 → 摄像头；
3. 基础设置 → 摄像头 → 选择 `OBS Virtual Camera`；
4. 调整画面/美颜/镜像（按需）；
5. 在直播伴侣里开始直播（用户操作）。

**P1 UI Automation 辅助**：

- 用户显式开启“帮我选择摄像头”；
- 找到直播伴侣窗口（标题/进程/签名）；
- 展开“添加素材” → “摄像头”；
- 在摄像头下拉框中匹配 `OBS Virtual Camera` / `OBS 虚拟摄像机`（本地化名称可能不同）；
- 读取当前选中项确认；
- 任一步失败：停止，显示同样的图文步骤；不重试点击。
- **不**自动点“开始直播”、不自动登录、不处理弹窗/协议。

### 7.3 验证

- OBS `VirtualCamStatus.Active == true`；
- 平台预览出现画面（用户确认；可选 UIA 读取预览控件状态，但不截图上传）；
- 如果平台提示“摄像头被占用”：关闭其他使用虚拟摄像头的软件（Zoom/Teams/浏览器）；
- 如果画面黑屏：检查 OBS 场景/源、虚拟摄像头输出、平台是否选错设备；
- 如果平台以管理员运行而 OBS 不是：虚拟摄像头可能不可见；提示“以相同权限运行”或重启平台。

## 8. UI Automation 辅助模式（P1）

### 8.1 设计

- 默认关闭；每次开启需确认“将操作哪个窗口、做哪几步”。
- 只使用 `System.Windows.Automation`（Windows Desktop 框架程序集，不引入 NuGet）。
- 每一步：
  1. 查找窗口；
  2. 查找控件（`AutomationId`/`Name`/`ControlType` 白名单）；
  3. 执行 `Invoke`/`ExpandCollapse`/`SelectionItem`；
  4. 读取状态确认；
  5. 失败即停止。
- 不使用坐标点击、不注入、不读账号数据、不截图上传。
- 记录步骤名/结果到日志（不含窗口文本/账号）。

### 8.2 失败原因（必须接受）

- 平台 UI 改版；
- Electron/CEF 未暴露 UIA 树；
- 应用以管理员运行，本应用不是；
- 语言/DPI/主题变化；
- 反自动化/安全软件拦截；
- 平台条款不允许自动化。

**回退**：同一屏显示图文步骤 + “我已手动选择，继续”按钮；不要让用户卡死。

## 9. 开播状态机与错误

```text
Idle
 → 选择平台
 → 检查 OBS（安装/运行/连接）
 → 选择模式（直推/虚拟摄像头）
 → 获取推流信息/启动虚拟摄像头
 → 预检（编码器/网络/磁盘/推流服务/录制状态）
 → 写入 OBS / 等待平台
 → 开播/确认
 → 直播中
 → 停止（只停本次启动的输出）
```

| 错误码 | 场景 | 出口 |
|---|---|---|
| `GOLIVE_NO_OBS` | 没装 OBS | 官方下载 |
| `GOLIVE_OBS_NOT_RUNNING` | OBS 未运行 | 启动并等待 |
| `GOLIVE_OBS_NOT_CONNECTED` | 未连接 | 自动连接 |
| `GOLIVE_PLATFORM_UNSUPPORTED` | 平台未核验/不支持 | 官方入口 + 手动 |
| `GOLIVE_KEY_MISSING` | 没填密钥 | 官方后台复制 |
| `GOLIVE_KEY_INVALID` | 格式/过期 | 重新复制 |
| `GOLIVE_SET_FAILED` | 写入 OBS 失败 | 查看错误/日志 |
| `GOLIVE_START_FAILED` | StartStream 失败 | 编码器/网络/密钥分类 |
| `GOLIVE_VCAM_FAILED` | 虚拟摄像头启动失败 | 驱动/占用/管理员 |
| `GOLIVE_PLATFORM_APP_MISSING` | 平台客户端未装 | 官方下载/打开页面 |
| `GOLIVE_PLATFORM_NOT_FOUND` | 检测不到窗口 | 手动打开/选择窗口 |
| `GOLIVE_UIA_FAILED` | 辅助失败 | 图文回退 |
| `GOLIVE_DOUBLE_OUTPUT` | 同时推流+虚拟摄像头 | 明确当前输出，避免双路 |

## 10. 测试矩阵

| 平台/场景 | 测试 | 预期 |
|---|---|---|
| B 站 | 官方后台复制 rtmp/直播码 → 写入 OBS → 开播 | 成功；错误密钥有明确提示 |
| 抖音 | OBS vcam → 直播伴侣选摄像头 | 画面出现；不自动开播 |
| 抖音 | vcam 被 Zoom 占用 | 提示占用；给出关闭建议 |
| YouTube/Twitch | 网络允许时手动核对 | 服务器/密钥写入成功；失败分类 |
| Kick/Facebook/Trovo/NicoNico/AfreecaTV | 官方入口/手动 | 不硬编码；可手动完成 |
| 未核验平台（快手/视频号/小红书/TikTok） | 选择后 | 只显示官方入口/手动，不显示“一键开播” |
| OBS v4/Win7 | 直推 | 不支持写入时明确降级，不假装 |
| 无管理员 | 抖音 vcam | 虚拟摄像头仍可用；UIA 不可用时回退 |
| 平台客户端更新 | 旧 UIA profile | 失败回退图文，不崩溃 |
| 网络断开 | 下载/开播 | 明确错误；可重试 |

## 11. 维护与复核

- 每个平台目录条目带 `verifiedAt`、`verifiedLevel`、`notes`；每版发布前复核一次。
- 平台入口变更时只改 JSON（热更新），不改代码；`check_platform_catalog.py` 校验：
  - id 唯一；
  - URL 必须 https + 官方域名白名单；
  - `acquisition` 枚举合法；
  - `verifiedLevel` 合法；
  - 未核验平台不得标 `directRtmp` 的“一键”能力。
- 不在代码里硬编码推流服务器地址；可给默认值，但允许用户覆盖。
- 不把社区教程当官方依据；官方帮助/客户端优先。
