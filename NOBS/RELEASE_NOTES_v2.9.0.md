## 一、新手教程（首启分步引导）

参照同系列软件 AIStudioHub 的首启引导做法，为「OBS 排障助手」做了一套适配自身功能面的四步引导：

| 步骤 | 讲什么 | 对应真实入口 |
|---|---|---|
| 第一步 · 连上 OBS | 控制台填地址密码即可连接；连不上也不影响离线使用 | `控制台` + 连接徽章 |
| 第二步 · 出问题先来这里 | 分类翻 / 关键词搜 / 一句话问助手 / 日志分析 | `首页`、`搜索`、`助手`、`设置 → 排障指引` |
| 第三步 · 一键体检 | 自检清单 + 智能诊断三通道 + 工具箱八个体检卡 | `诊断`、`工具箱` |
| 第四步 · 开播、装修与调教 | 分步搭建、场景模板、插件广场、监控与设置 | `搭建`、`模板`、`插件`、`监控`、`设置` |

实现要点：

- **覆盖层**位于主窗口最上层（含左侧导航），卡片 + 进度圆点 + `跳过 / 上一步 / 下一步`，最后一步按钮变为「开始使用」；
- **只记一个「已完成」标记**（`prefs.json` 的 `onboarding.completed`），不记进度 —— 中途关掉窗口下次仍从第一步开始，符合新手引导的语义；
- **随时可重看**：`设置 → 新手引导 → 重新展示引导`，点击后主窗口立即重播，**无需重启**（静态事件解耦，与 AIStudioHub 同做法）；重看时会清掉「已完成」标记，避免重看后中途关闭导致下次不再展示；
- **尊重无障碍设置**：「减少动画」开启时不播放淡入淡出；
- **首启不叠弹窗**：首启时把「启动更新检查」推迟到引导结束之后，避免引导与更新弹窗互相打架；
- **文案与游标逻辑抽成纯逻辑**（`Services/Shell/OnboardingGuide.cs`），有 20 项单测钉死（步骤完整性、越界夹取、首/末步边界、展示判定），并纳入 Headless 自检 —— 逐步渲染覆盖层，拦截资源名拼错一类只在展示时才炸的错误。

### 新增「维护状态」字段并标出维护放缓的条目

目录新增 `maintain` / `maintainNote` 字段：**近 12 个月内有提交或发行记为 `active`**，更久记为 `slow`。6 个条目被标为**维护放缓**并在卡片上以警示色明示（都仍在 24 个月内有动静、且暂无同类替代，故保留而非删除）：`RTSP Server`、`Zoom to Mouse`、`Freeze Filter`、`Auto Subtitle`、`Soundboard`、`Scale to Sound`。

字段缺失（旧目录 / 热更新文件）按「活跃」处理，不给维护正常的插件打误导性黄标；卡片仅在「维护放缓」或「带补充说明」时才显示该行，避免逐张重复噪音。页面顶部新增一行元信息：`目录 v1.4 · 57 条 · 2026-09-26 复核 · 其中 6 条维护放缓`。

## 三、对齐最新 OBS（32.2.2）

截至本版发布，OBS Studio 最新稳定版为 **32.2.2**（2026-08-14）。本版用**真实 32.2.2 日志与配置**逐项核对了兼容面，并修掉三处真实缺陷：

### 1. 日志头部字段在真实日志里全部解析为空（严重）

OBS 日志每行都带 `HH:mm:ss.mmm:` 前缀，而旧规则对 CPU / 内存 / 系统版本 / 帧率 / 码率用了**纯行首锚定**，于是这些字段在任何真实日志上都匹配不到。实测结果：`CPU / 内存 / 系统版本 / 帧率 / 码率` 全为空。

修复：统一改用「可选时间戳前缀」锚定（既保留锚定语义，又能吃到真实日志，并兼容 Tab 缩进的二级字段）。

实测（本机 OBS 32.2.2 日志）：修复后 `OsVersion=10.0 Build 19045 …`、`Cpu=AMD Ryzen 9 3900X`、`Memory=32675MB Total, 21992MB Free`、`Fps=60` 全部正确解析。

### 2. 显卡解析出垃圾值，连带双显卡错位检测失效

旧的显卡正则把序号段做成可选，于是 `Available Video Adapters:` 里的 `Adapters:` 被当成适配器名，`Gpu` 被解析成 `s:`。由于双显卡错位检测与编码过载分诊都依赖 `Gpu` / `Adapters`，这两项能力在任何真实日志上都失效。

修复：拆成「实际渲染适配器（`Loading up D3D11 on adapter …`）」与「枚举清单（`Adapter N: …`）」两条规则，并要求 `Adapter` 后必须跟编号；实际渲染的适配器也并入清单。

实测：`Gpu=NVIDIA GeForce RTX 2080 Ti`、`Adapters=[NVIDIA GeForce RTX 2080 Ti]`；用双显卡样例验证，核显渲染 + 独显在位时正确给出 `LOG-GPU-DUAL` 双显卡错位告警。

### 3. 色彩范围检测在 32.x 日志上永不命中

OBS 30 前后日志格式变更：老版单独打印 `color range: Full`，32.x 合并为 `YUV mode: Rec. 709/Partial`。只认老格式的话，这条规则在新版日志里永远不命中。

修复：规则同时兼容两种格式，并用真实样例验证 `Rec. 709/Full` 命中、`Rec. 709/Partial` 不命中。

### 4. 本机插件体检漏扫 OBS 32.x 的新插件目录（严重）

OBS 32.x（配套 32.1 的插件管理器）新增了「一插件一目录」的插件根布局：

```
%ProgramData%\obs-studio\plugins\<插件名>\bin\64bit\<插件>.dll   ← 新增的全局插件根，旧版完全没扫
%AppData%\obs-studio\plugins\<插件名>\bin\64bit\<插件>.dll        ← 旧版只扫了根目录一层，扫不到
```

修复：新增全局插件根，并把插件根展开成一插件一目录的实际 DLL 目录（根目录本身仍扫，兼容旧式摆法）。

实测（本机）：`%ProgramData%\obs-studio\plugins\obs-helper-dock\bin\64bit\obs-helper-dock.dll` 与 `%AppData%\obs-studio\plugins\obs-control-studio-bridge\bin\64bit\…` 此前均被漏扫，现在都能列出；体检面板的来源标签新增「全局插件目录」。

### 5. 新增「插件重复安装」日志规则

真实日志里发现 OBS 会告警 `Dock id 'obs-helper-dock' already used!  Duplicate library?`，本机实际就装了**两份** `obs-helper-dock.dll`（插件根一份 + OBS 安装目录一份）。据此新增 `LOG-PLUGIN-DUPLICATE` 规则，并把「不要装两份」写进插件广场的安装小贴士。

### 6. 实时日志尾随预警从未真正运行（严重）

V2.8 的「实时日志尾随预警」按 `*.log` 查找 OBS 会话日志，但 **OBS 的日志扩展名是 `.txt`**（`logs\2026-08-27 19-41-42.txt`），于是它永远找不到文件、整条链路静默失效。

修复：抽出纯逻辑 `ObsLogFileFinder`（同时认 `.txt` / `.log`，按修改时间取最新），并配 11 项单测防止回归。

### 7.「音频缓冲不断增长」在健康日志上误报

审校真实日志时发现：OBS 每次启动都会打印 `adding 42 milliseconds of audio buffering, total audio buffering is now 42 milliseconds`，而规则按「出现过缓冲」匹配，导致**每个健康日志都会报一条「音画不同步风险」警告**。

修复：改为只在缓冲总量 ≥ 100 ms 或 OBS 明确报出缓冲上限（`Max audio buffering reached`）时提示；一次性初始缓冲不再误报。实测本机 32.2.2 真实日志的这条误报已消失，而真正的问题项（插件重复安装）仍正常报出。

### 未改动的兼容面（已核对，无需变更）

- **obs-websocket 协议**：OBS 32.2.2 内置 obs-websocket 5.7.4、RPC Version 1，与本应用握手参数一致；
- **配置键**：实测 32.2.2 的 `basic.ini` 中 `[Video] ColorFormat/ColorSpace/ColorRange`、`[Audio] SampleRate`、`[SimpleOutput] RecFormat2/StreamEncoder/RecEncoder/VBitrate`、`[AdvOut]` 等键名与旧版一致，色彩 / 采样率 / 录前自检等只读体检继续有效；
- **知识库版本相关表述**：`problems.json`（v2.2）中的 32.2.x 插件加载、Hybrid MP4、WebRTC 联播等条目仍然准确。
