# 功能模块登记规则（V3.4.0 起）

功能中心（`功能中心` 页面，路由 `features`）是产品对用户展示能力的**唯一总入口**。
为避免「做了功能但用户找不到」，从 V3.4.0 起执行以下规则：

1. **每个版本的新功能必须登记模块**
   - 在 `Services/Shell/FeatureCatalog.cs` 的 `Modules` 中新增模块，或把条目加入既有模块；
   - 模块必须有：`Id`、标题/说明文案键、图标、目标路由（+ 可选 Tab）、版本号、能力清单；
   - 新能力的 `FeatureEntry` 必须指向真实路由；`FeatureCatalogTests` 会校验 46 项、ID 唯一与路由存在。

2. **功能中心同时收纳历史便捷功能**
   - 不只展示本版新增，`常用功能` 段包含 V3.3.0 及更早的开播/录制、虚拟直播/插件、诊断/工具箱、外观/系统；
   - 新增历史功能时同样登记，保证用户不需要记住「它在哪一页」。

3. **入口可见性**
   - 一级导航固定包含 `功能中心` 与 `手机联动`（V3.4.0 主推）；
   - 首页保留主推 Hero 卡（手机联动）与「查看全部新功能」；
   - 以后新增模块必须同时出现在功能中心，不能只藏在某个页面的二级 Tab。

4. **文案与无障碍**
   - 模块标题/说明/能力名全部走中英文案键；
   - 卡片可键盘聚焦、按钮有可访问名称；触控目标 ≥ 44 px（手机页面）。

5. **变更检查**
   - 提交前运行：`dotnet test --filter FeatureCatalogTests`、`python scripts/check_docs.py`；
   - 功能中心路由必须加入 `OBS_SELFTEST=1` 自检（已加入 `cases`）。

| 智能与复盘 | V3.4.0 | `insights` | 3 |

| 虚拟直播与插件 | V3.3.0 | `virtuallive` / `plugins` / `settings` | 7 |
| 诊断与工具箱 | 常用 | `diagnostic` 等 | 10 |
| 外观与系统 | 常用 | `settings` / `performance` / `home` | 6 |
| 开源依赖 | V3.4.1 | `plugins` | 1 |

> V3.4.1 起，手机页的可用性与兼容性修复不单独占模块（属于 `mobile` 模块内改进）；
> 新增的「开源依赖中心」登记为 `deps` 模块（路由 `plugins`）。
