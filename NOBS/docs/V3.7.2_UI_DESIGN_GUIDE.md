## 1. 这一版的范围

| 项目 | 结论 |
|---|---|
| 皮肤数量 | 2：A · 导播台（黑夜）/ C · 排版手册（白天） |
| 皮肤开关 | 不新增。由现有 `主题 = 跟随系统 / 白天 / 黑夜` 唯一解析：黑夜 → A，白天 → C |
| 覆盖范围 | 23 条路由页 + 对话框 / 迷你小窗 / 计时窗 / 提词器 / 新手引导（跟随语义色） |
| 页面逻辑 | **零复制**。两套皮肤共用同一棵视觉树、同一份 code-behind、同一路由表 |
| 切换行为 | 只换资源令牌，不重建页面：焦点、滚动、输入、OBS 连接、录制/推流状态天然保留 |
| 不改动 | OBS WebSocket 协议、录制/推流参数、写操作语义、功能入口数量 |

### 1.1 为什么采用「统一视觉树 + Skin 令牌」

技术方案给出的完整路线是「双 Shell + 每页双 XAML」，自估 30 个视图需 2–4 个月，且要先抽出约 17,139 行 code-behind 的共享逻辑。本轮 3.7.2 的交付约束是「只更新 UI 视图 + 功能审计」，因此选择：

- **结构差异放在壳层与组件模板**：编号目录、37 px 标题、tally、发丝线、卡片/按钮形态；
- **页面不复制**：页面继续只引用 `Card` / `Button` / `Pill` / `SectionTitle` 等共享样式；
- **每页双 XAML 留给后续版本**：等某个页面出现「A/C 必须用不同控件树」的真实需求时，再单独拆该页。

这样做的代价与边界写在 §10，明确不宣称「已按技术方案完成全量双视图」。

## 2. 皮肤解析规则

```text
主题 = 跟随系统 → 系统浅色 → C；系统深色 → A
主题 = 白天     → C
主题 = 黑夜     → A
高对比          → 保留皮肤结构，颜色按高对比色板覆盖
```

- 皮肤只影响视觉，不改变功能、路由、文案语义、控件类型与键盘顺序。
- 强调色默认跟随皮肤：A = 信号青 `#38E0C0`，C = 信号蓝 `#1F3BFF`。用户点选色板后固定为用户选择；设置页可「恢复主题默认强调色」。
- 圆角：A 可按用户偏好微调（4–12 px）；C 固定直角，设置页在下拉框旁给出说明并禁用该下拉框。

## 4. Shell 规格

### 4.1 侧栏

- **A**：品牌区 → 分组标签 → 图标 + 文字导航（图标 18 px，选中态为信号青柔和底 + 青色文字/图标）。
- **C**：品牌区 → 分组标签 → **编号目录**（`01`–`16`，跨分组连续）+ 文字；无图标；选中态为浅灰底 + 左侧 2 px 黑线 + 加粗；读屏名称为「第 01 项，首页」，当前项 `ItemStatus=当前页`。
- 编号只是目录序号，不是快捷键；不改变 Tab 顺序（侧栏 → 顶栏 → 内容）。
- 设置页左栏同样使用编号目录（`01`–`13`），与主侧栏同源。

### 4.2 顶栏

| 区域 | A | C |
|---|---|---|
| 标题 | 17 px / 600，紧凑 | 37 px / 300，标题前显示目录序号（如 `16`） |
| 副标题 | 11 px 次要色 | 11 px 次要色 |
| 右侧 | **tally**：`● OFF AIR 00:00:00` → 录制/推流时 `● ON AIR + 时长`；搜索 / 连接徽章 / 提词器 / 设置 | 无 tally；搜索 / 连接徽章 / 提词器 / 设置 |
| 底边 | 无 | 1 px 发丝线 |
| 背景 | 不透明机柜黑 | 不透明纸白 |

tally 状态同时用文字 + 圆点表达，不只靠颜色；读屏名称包含状态与时长；无录制/推流时计时器停止，不空转。

### 4.3 内容区

- 背景使用 `ContentBackgroundBrush`：默认 = 皮肤底；用户自定义纯色/壁纸时按 §3.2 规则处理。
- 页面标题由顶栏统一渲染，页面内部不再重复 `H1`。
- 滚动条、焦点环、Toast、Busy 遮罩在窗口级，换肤不销毁。

## 7. 无障碍规则

1. 高对比 > 应用内高对比 > 无障碍/老年模式 > 字号缩放 > 皮肤。
2. 状态不只靠颜色：A 的 LED/tally 配文字；C 的印章/编号配文字；导航选中态带字重与边线。
3. 编号目录读屏名称 = 「第 N 项，页面名」；当前项 `ItemStatus=当前页`。
4. 换肤通过实时区域播报「已切换到黑夜/白天模式」，不重读整页；视觉树未替换，焦点不丢。
5. 焦点环：A 信号青 / C 信号蓝，2 px + 偏移；键盘路径与视觉顺序一致。
6. 字号与密度走 `UiProfileCore` 令牌；C 的 37 px 标题随字号档位缩放。
7. 减少动画：A 的悬停/按压缩放与页面入场动效归零；C 本就不依赖动效。

**未验证项**（不得宣称「支持屏幕阅读器」）：NVDA / Narrator 实测、UIA 自动化、真机 150%/200% DPI、Windows 10/11 中文环境的 37 px 细体字重回退。证据边界见 [`V3.7.2_AC_THEME_TECH.md` §5.10](V3.7.2_AC_THEME_TECH.md)。

## 8. 自定义背景 / 壁纸

- 默认关闭（`bgMode=default`），两套皮肤使用各自底色。
- 用户开启纯色背景时：C 保持原色；A 自动压暗（72% 机柜黑 + 28% 用户色），保证浅色正文可读。
- 用户开启图片背景时：保留 V3.5.0 的铺放、压暗、模糊与轮播；顶栏与导航始终使用不透明皮肤表面，避免标题被壁纸冲掉。
- 自定义背景不属于「设计 1:1」验收范围；验收截图使用默认底。

## 10. 与技术方案的差异与后续

| 项目 | 技术方案 | 本轮实现 | 后续 |
|---|---|---|---|
| 页面视图 | 每页双 XAML | 单视觉树 + 令牌/模板切换 | 出现「必须不同控件树」的页面再拆双视图 |
| Shell | 双 Shell | 单 Shell + 皮肤令牌（编号/图标由模板切换） | 若 Shell 结构继续分化，再拆双 Shell |
| 页面状态 | `IPageStateAware` 快照 | 不重建视图，天然保留 | 双视图落地时再引入 |
| 26 个视图设计板 | 需先补设计 | 以本轮截图作为 A/C 设计视图基线 | 设计方复核后替换为正式设计板 |
| 壁纸 | 建议 A/C 禁用 | 保留可用 + 默认关闭 + A 自动压暗 | 观察用户反馈再决定是否禁用 |
