# OBS帮助助手 V2.9.4 发布说明

> 主题：**简单录像** —— 三档预设一次配好、OBS 没启动也能拉起并自动开录、
> 录之前有一句话结论、录之中看得到时长与剩余、录完直接找得到文件。

V2.9.3 的「一键部署录制环境」把与录制质量直接相关的配置一次到位了，
但它回答的是「配置应该长什么样」。按「我就想录个像」再走一遍，
缺口很具体：入口深、动作碎、不认识状态、OBS 没开机就没路、录制中看不见、停止后没收尾。
本版把「配好 → 验好 → 开录 → 录得住 → 录完找得到」串成首页上的一次操作，
并且**不碰用户没同意过的任何参数**。

上游依据：用户视角结论 [`../docs/FEATURES_USERVIEW_2026-10-05.md`](../docs/FEATURES_USERVIEW_2026-10-05.md)，
逐文件施工图 [`../docs/SIMPLE_RECORDING_DESIGN.md`](../docs/SIMPLE_RECORDING_DESIGN.md)。

## 1. 简单录像：三档预设

首页顶部新增「简单录像」卡，用户只需在三个词里选一个。三档预设只声明「录什么」，
不声明「怎么编码」：

| 预设 | 录像规格 | 说明 |
|---|---|---|
| `quick` **快速录像**（默认） | 1080p · **60fps** · HQ · Hybrid MP4 · 48kHz | 通用推荐 |
| `meeting` **会议 / 网课** | 1080p · **30fps** · HQ · Hybrid MP4 | 文件小、CPU 友好 |
| `game` **游戏高码率** | 1080p · **60fps** · HQ · Hybrid MP4 · **自动分段** | 长录制不产生单个巨型文件 |

预设落到配置上的写项，只新增这几类**可验证的键**：

| 写项 | 键 | 取值 | 差异 |
|---|---|---|---|
| 录像格式 | 复用 V2.9.3 的格式写项 | Hybrid MP4（`hybrid_mp4`） | 三档一致 |
| 录像质量 | `SimpleOutput/RecQuality` | `HQ` | 三档一致 |
| 音频轨 | `SimpleOutput/RecTracks` | `1` | 三档一致（兼容旧版 OBS 的音频轨默认值） |
| 分段 | `RecSplitFile` + `RecSplitFileTime` + `RecSplitFileSize` | `true` + 时间 / 单段大小 | **仅 `game`** |

- 帧率（30 / 60）与画布 / 输出分辨率（1920x1080）**复用 V2.9.3 已经写过的同一批目标**：
  两者都从同一份 `RecordingEnvCore.StaticTargets` 取，键名只有一处定义 ——
  否则早晚出现「部署卡写 `RecFormat2`、简单录像写 `RecFormat`」这类漂移；
- 采样率（48kHz）沿用 V2.9.3 的口径：**只有 WebSocket 通道写**，文件通道不写
  （INI 里音频设置的位置随 OBS 版本变动，赌错就是把用户配置搞乱）；
- **本版没有新增任何一个码率写项**。三档都刻意不碰输出模式（`Output/Mode`）、
  编码器族（`RecEncoder`）与推流参数 —— 那些属于用户自己的选择，改了会连带影响
  他正在用的工作流，且本机无法验证取值正确性。「游戏高码率」这个档名对应的是
  60fps + 自动分段，码率仍由用户自己在 OBS 里设定；需要改编码参数时走界面的「高级设置」，
  跳到 V2.9.3 那张部署卡。

## 2. 一次点击背后的状态机

```
Idle → Checking ─┬─ Blocked              （缺配置 / 正在推流 / 文件通道写不了）
                 └─ SettingUp            （先整备份，再按当前值 → 目标值落地）
                        → LaunchingObs   （OBS 没跑才需要）
                        → WaitingObs     （等 obs-websocket 就绪，带超时）
                        → Recording      （调 StartRecord）
                        → Stopping → Stopped（提示文件 + 打开目录 / 转 MP4）
```

按「现在到底是什么状态」分流，每一档都给得出可照做的下一步：

| 条件 | 行为 |
|---|---|
| 已连上 OBS | 走 obs-websocket 落地（即时生效、无需重启）→ 直接开录 |
| 没连上、**OBS 进程也没跑**，`basic.ini` 可写 | 先整备份再落地 → `LaunchingObs` → `WaitingObs`（每 1 秒轮询、最长 75 秒）→ 自动开录 |
| 没连上、但 OBS 进程在跑 | **不落地、不拉起**，返回可照做的原因（去 OBS 打开 WebSocket，或退出 OBS 走文件通道） |
| 录制中 / 推流中 | `Blocked`，直接返回，**不写任何配置** |

「正在推流时要拦住」这条是**硬门槛而不是提示**：直播中不去改输出参数，也不抢录制输出。
V2.9.3 的实现里，这种情形会掉进「OBS 在跑但没连上」的误导性文案（起因是
`WebSocketAvailable` 已经把录制 / 推流中排除，但没有把**原因**补上），本版把原因补齐。

## 3. OBS 没启动：拉起、等就绪、自动开录

录不了的第一大原因是 **OBS 根本没开**；在此之前，全套工具链只有「探测 OBS 是否在跑」，
没有任何启动能力。本版新增启动链路，并把「怎么找 exe」做得可验证：

- **候选来源**：注册表 `Uninstall\OBS Studio`（HKLM / HKCU / WOW6432Node）的 `DisplayIcon`
  （形如 `"C:\...\bin\64bit\obs64.exe",0`），叠加已探测到的安装根
  （`根\bin\64bit\obs64.exe` → `根\obs64.exe` → `根\bin\obs64.exe`）；
- **解析与探测分离**：`DisplayIcon` 字符串解析、安装根推导、候选去重与存在性过滤
  都是纯逻辑（零 WPF），被单测钉死四种形态（带引号 + `,0` 尾巴 / 无引号 / 只有路径 / 空值）；
  碰注册表与文件系统的部分留在服务层。这样「路径推导错在哪一段」永远有机器证据；
- **启动**：`Process.Start` + `UseShellExecute`，启动失败捕获异常并给出可读原因；
- **找不到就不猜路径**：便携版（`portable_mode.txt`）与绿色解压版的识别能力有限，
  找不到 exe 时返回一条「请自己启动 OBS」的文案键，绝不赌一个路径把别的东西拉起来。

文件通道改完的收尾也补上了：界面会提示**需要重启 OBS 才生效**（WebSocket 通道不需要）。

## 4. 录之前一句话，录之中看得见，录完找得到

### 4.1「现在能不能录」只有一行结论

不想读六行自检清单的人，只看这一行：就绪，或者阻断 + 原因 + 出口。
判定按硬门槛排序：

```
正在推流 → 缺配置 / 文件通道写不了 → OBS 在跑但没连上 → 录前自检有失败项 → 有警告项 → 就绪
```

失败项 / 警告项来自既有的录前自检（`PreflightCheckCore`），这里只做**结论的汇总**，
不新增一套判定口径。

### 4.2 录制中：已录时长与剩余可录

| 显示项 | 口径 |
|---|---|
| 已录时长 | 按「开始录制到现在」计，**暂停的时间不计入** —— 口径写在界面上，不让人自己猜 |
| 剩余可录 | `空闲空间(GB) × 1024 × 8 ÷ (预设码率(kbps) × 1.5) ÷ 60`（分钟），即给码率留 **50% 冗余**，沿用工具箱磁盘写入体检的同一口径 |
| 低空间提示 | 剩余低于 **10 分钟**时提示 |
| 已写文件大小 | 由调用方从文件长度取，原样回传 |

时长与剩余在首页卡、控制台输出区与托盘 ToolTip 上共用同一份状态；
托盘菜单新增「打开录像目录」，录制中 ToolTip 带上已录时长 —— 不必把主窗口翻出来。

### 4.3 停止后的收尾

- 提示**文件已生成**并读回文件大小（回应「录完才发现是空文件」）；
- 一键**打开目录**；
- 本机有 ffmpeg 时可一键**无损转封装成 MP4**；没有 ffmpeg 时给 OBS 自带
  「重新封装录像」的菜单路径，而不是留一个点了报错的按钮。

## 5. 入口与设置

| 位置 | 改动 |
|---|---|
| 首页 | 顶部插入「简单录像」卡（预设三选 / 一句话结论 / 开始-停止主按钮 / 进度 / 状态 / 收尾按钮 / 折叠的逐项「当前 → 建议」） |
| 控制台 | 输出区新增录制信息行（时长 / 剩余可录 / 文件） |
| 托盘 | 菜单新增「打开录像目录」；录制中 ToolTip 带已录时长 |
| 设置 → 录制 | 「默认预设」下拉 + 「文件通道时允许自动启动 OBS 并开录」开关（持久化在 `prefs.json`） |

「替你启动一个外部程序并且自动开始录制」是有副作用的动作，所以它是**显式设置项**：
是否允许由用户在设置里决定，而不是悄悄替他执行；关掉后仍可自己启动 OBS 再录。

## 6. 沿用 V2.9.3 的落地纪律

| 纪律 | 本版做法 |
|---|---|
| 先整备份 | 任何写入前先整份备份当前配置集，**备份失败即中止** |
| 写后读回校验 | 文件通道写盘后重新读回、逐项比对目标值 |
| 可回滚 | 每一项都记旧值，回滚就是把旧值写回去 |
| 逐项可取消 | 折叠区列出「当前 → 建议」，每一项都能单独不应用、单独取消 |

硬口径保持不变：**不写推流参数、不写输出模式、不写编码器族、不写码率**；
录制中 / 推流中一律不落地；不静默安装、不静默改配置、不做无人值守的后台改写。
新增文案中英成对，键集由既有单测（键集一致 / 值非空 / 英文侧无汉字）钉死，
语言切换时新控件随当前页面原地重放一并刷新，`主窗口` 无需新增代码。

## 7. 质量基线

- 本版的纯逻辑都有单测覆盖，重点是「编译器看不见」的错法：
  三档预设的数量 / 顺序 / 键唯一、预设解析的归一化（大小写 / 未知 / 空）、
  预设清单里**只出现录制相关参数**（断言不含 `Mode` / `StreamEncoder` /
  `VBitrate` / `RecEncoder`）、只有 `game` 才写分段、就绪判定的每一条阻断原因、
  进度估算的边界（0 码率不除零、0 剩余、低空间阈值）、
  `DisplayIcon` 的四种形态与安装根候选的顺序 / 去重 / 存在性过滤；
- 新增文案自动纳入既有的中英键集检查；XAML 引用继续由 `scripts/check_resources.py`
  与 Headless 自检把关；
- 两个目标框架（`net10.0-windows` / `net6.0-windows`）均需可编译，不使用 .NET 7+ 独有 API；
- **具体测试项数与自检结果以本轮验收产出为准**，本说明不预先写死数字。

## 8. 已知边界

- ⚠️ **预设取值与「拉起 OBS → 自动开录」链路没有对真实 OBS 做过端到端验证**：
  `HQ` / `hybrid_mp4` / `RecSplitFile*` 这些取值落到真实 OBS 上是什么样、
  WebSocket 就绪的实际时延，本版只做到**协议 / 键名 / 纯逻辑单测**级别。
  按本项目的证据标注口径，这属于**人工核对项**，本说明不宣称已验证；
- ⚠️ **便携版 / 绿色解压版 OBS 的安装路径识别能力有限**：只认注册表 `DisplayIcon`
  与常见安装目录；找不到 exe 时不猜路径，直接提示用户自己启动 OBS；
- **剩余可录是估算**：按预设码率 × 1.5 冗余推算，不是实测写入速率，
  真实码率随画面内容波动，估算值只用于「还要不要清磁盘」这类判断；
- **文件通道写入的项需要重启 OBS 才生效**，界面上有对应引导；WebSocket 通道不需要；
- 录制中 / 推流中一律不落地配置，这是硬门槛，不是提示。

## 9. 升级方式

- **应用内增量更新**：「检查更新」→ 增量更新，下载后自动校验、提权替换并重启；
- **完整安装包 / 便携包**：见 Release 资产，便携包解压即用；
- 产物命名与构建口径沿用 V2.9.3：主构建（`net10.0-windows`）与 `_win7` 兼容构建
  （`net6.0-windows`）双份、共用同一个 AppId。兼容构建所用 .NET 6 已停止安全更新，
  新机器请一律使用主构建。
