# V3.3.0 Live2D 一键配置技术指引

> 配套主文档：[`PLAN_V3.3.0.md`](PLAN_V3.3.0.md)
> 本文只讨论 Live2D 形象接入：模型从哪里来、如何校验、如何交给 VTube Studio、如何在 OBS 里得到带透明背景的画面，以及失败时怎么退。
> **已确认（2026-10-25）**：3.3.0 采用“**VTube Studio 公开 API + OBS 采集**”路线；不做自研 Live2D 渲染器/面捕，不以 `pixi-live2d-display` 作为 3.3.0 依赖。
> **结论先行**：这样能在不引入 Cubism 运行时许可证风险、不破坏零第三方 NuGet 包底线的前提下，做到真正的“一键配置”。

---

## 1. 目标与边界

### 1.1 用户目标

用户有一份 Live2D 模型（通常是 `.model3.json` 目录），希望：

1. 选模型；
2. 选一个布局（全身/半身/右下角/左侧）；
3. 点一次“一键配置”；
4. 在 OBS 里看到带透明背景、能跟着自己动的虚拟形象；
5. 如果中间缺软件/缺权限，知道下一步做什么。

### 1.2 本方案能承诺的

- 自动检测 VTube Studio、启动它（经用户同意）、通过公开 API 加载模型；
- 自动在 OBS 创建/复用一个“虚拟形象”源，优先 NDI/Spout2，退虚拟摄像头/窗口采集；
- 自动按画布计算位置/缩放，适配横屏/竖屏；
- 自动保存配置（模型 id、采集方式、布局、场景），下次可复用；
- 每一步失败都有错误码、人话说明、可执行出口；
- 不修改用户原模型文件；不删除用户已有场景；默认新建场景集合。

### 1.3 本方案不承诺的

- 不承诺所有 Live2D 模型都能被 VTS 加载（模型版本/授权/文件完整性由 VTS 决定）；
- 不承诺 NDI/Spout2/虚拟摄像头一定可用（取决于 OBS 插件、驱动、GPU、网络）；
- 不承诺窗口采集一定透明（Windows 版本/OBS 捕获后端/VTS 渲染方式都会影响）；
- 不承诺“零点击”：首次需要用户在 VTS 内允许 API、在 Steam 安装 VTS、在 OBS 里确认设备；
- **不自带** Live2D 模型、Cubism Core、面捕模型或追踪软件。

## 2. 路线选择

### 2.1 三条路线对比

| 维度 | A. VTube Studio 集成 | B. 浏览器源 + Cubism Web | C. 原生渲染 + 面捕 |
|---|---|---|---|
| 面捕 | 现成（VTS） | 无，需要另接追踪 | 需自研/集成 OpenSeeFace 等 |
| 物理/表情/动作 | 现成 | 需要自己实现/依赖第三方 | 需要自己实现 |
| 透明输出 | NDI/Spout/虚拟摄像头/窗口 | OBS browser source 透明 | 自绘窗口/共享纹理 |
| 许可证 | 只调用公开 API | Cubism Core 专有；pixi-live2d-display MIT 但久未更新 | Cubism Native 专有 |
| 工作量 | 中 | 大 | 很大 |
| 维护风险 | VTS API 版本 | CEF/JS/Cubism 版本 | 图形/驱动/模型兼容 |
| 3.3.0 结论 | **已选（P0）** | 3.3.0 不做 | 不做 |

### 2.2 已确认：3.3.0 不做浏览器自绘

- `pixi-live2d-display` 是 MIT，但最近提交是 2024-08-20；Live2D Cubism 5 模型/新版 Core 的兼容性需要自己验证和维护。
- Cubism Core 是专有许可，不能按 MIT 处理；随包分发需要逐条核对许可与署名。
- OBS browser source 能渲染，但**没有面捕**；要做口型/眨眼/头部追踪仍要引入跟踪链路。
- 本地 HTTP + JS 资源 + CEF 兼容 + 安全面（本地服务、CSP、路径穿越）会显著扩大攻击面。
- 结论：3.3.0 **不做**；未来如要做纯展示/待机，需单独立项、先过 Cubism 许可与维护性评审。

### 2.3 为什么不做原生渲染器

- 需要 Cubism Native SDK、OpenGL/D3D 渲染、纹理/遮罩/物理/动作/表情、窗口透明、GPU 兼容、打包与签名。
- 还需要摄像头推理（人脸关键点/表情/头部姿态）与模型参数映射；这是另一个产品级工程。
- 与“零第三方 NuGet 包、单文件发布、Win7 兼容构建”冲突明显。
- 结论：不做；如果未来要做，先单独立项、单独许可证评审、单独性能预算。

## 3. 环境检测

### 3.1 OBS

复用现有能力，不另写：

- `ObsPathService.TryDetectInstallDir()` / `ObsLaunchCore`：找 OBS；
- `ObsConnectionService.EnsureConnectedAsync()`：确保连接（单飞/超时/取消）；
- `SimpleRecordingService` 的“拉起 OBS → 等 WebSocket”链路：OBS 未运行时复用；
- `ObsConnectionService.Profile.ObsVersion`：版本兼容判断；
- `VirtualCamCheckService`：虚拟摄像头驱动/插件检查。

检测结果：

```
ObsState = NotInstalled | NotRunning | RunningNotConnected | Connected | ProtocolV4
```

- `ProtocolV4`（Win7 构建）：Live2D 的 NDI/Spout 源创建可能可用，但 `SetVideoSettings` 等 v5 能力不可用；必须按 `ObsLegacyV4Core.SupportsRequest` 判断，不假装支持。
- OBS 未运行：先问用户是否允许启动；复用现有 `LaunchConsent` 偏好，不每次弹。

### 3.2 VTube Studio

多信号探测，避免误判：

| 信号 | 说明 |
|---|---|
| 进程 | `Process.GetProcessesByName("VTube Studio")` 等；以实际 exe 名为准，大小写不敏感 |
| Steam 安装清单 | `steamapps\appmanifest_1325860.acf`；Steam 库路径从注册表 + `libraryfolders.vdf` 解析 |
| 安装目录 | `steamapps\common\VTube Studio`；也允许用户手动指定 |
| 窗口标题 | `VTube Studio` / `VTube Studio Window 2`（多实例） |
| UDP 发现 | `47779` 上的 `VTubeStudioAPIStateBroadcast`（含 `active`/`port`/`instanceID`/`windowTitle`） |

检测结果：

```
VtsState = NotInstalled | InstalledNotRunning | RunningApiOff | RunningApiReady | RunningAuthRequired | AuthDenied
```

- `RunningApiOff`：VTS 在跑，但 API 未开启；给图文步骤（VTS 设置里开启 API 访问）。
- `RunningAuthRequired`：API 开了，但没有本应用 token；走 `AuthenticationTokenRequest`。
- `AuthDenied`：用户拒绝过；提示可在 VTS 内重新允许，或换 token。
- 多实例：用 UDP 广播的 `instanceID`/`windowTitle` 让用户选；不要随便连第一个。

### 3.3 模型

用户选择：
- `.model3.json` 文件；
- 模型目录（含 `.model3.json`）；
- VTS 已有模型列表（如果 VTS 已连接/已读目录）。

检测结果：

```
ModelState = Invalid | ValidNotImported | ImportedToVts | LoadedInVts
```

## 4. 模型导入与校验

### 4.1 目录结构

典型 Live2D Cubism 3/4/5 模型目录：

```
MyModel/
├── MyModel.model3.json
├── MyModel.moc3
├── MyModel.physics3.json
├── MyModel.pose3.json
├── MyModel.userdata3.json
├── textures/
│   ├── texture_00.png
│   └── texture_01.png
├── motions/
│   └── *.motion3.json
├── expressions/
│   └── *.exp3.json
└── ...
```

VTS 还可能带 `*.vtube.json`（VTS 模型配置）与 `*ModelIcon*.png`。应用**不修改**这些文件，只复制/读取。

### 4.2 校验步骤

1. 规范化路径：`Path.GetFullPath`；拒绝 UNC/设备路径/相对路径异常。
2. 找到唯一的 `.model3.json`；多个时让用户选。
3. 解析 JSON（`System.Text.Json`）；必须含 `FileReferences`；读取 `Moc`、`Textures`、`Physics`、`Pose`、`Motions`、`Expressions`、`UserData`。
4. 逐项解析引用路径：
   - 拒绝 `..`、绝对路径、盘符、UNC、符号链接/reparse point；
   - 所有引用必须落在模型根目录内；
   - 目标文件必须存在；扩展名必须符合预期（`.moc3`/`.png`/`.json` 等）。
5. 检查 `.moc3` 头（可选）：读取前 4 字节，确认是 `MOC3`；版本过高时提示“VTS 可能不支持”，不阻断（由 VTS 最终判定）。
6. 限制：
   - 文件数 ≤ 2000；
   - 总大小 ≤ 512 MB（可配置，默认值）；
   - 单纹理 ≤ 8192×8192；总纹理像素预算（例如 64 MP）；
   - 单 JSON ≤ 8 MB；
   - 拒绝可执行文件（`.exe`/`.dll`/`.bat`/`.cmd`/`.ps1`/`.scr`/`.msi`）出现在模型目录。
7. 计算清单：
   - 每个文件相对路径 + 长度 + SHA-256；
   - 目录整体 hash = 对“排序后的相对路径 + 文件 hash”再做 SHA-256；
   - 生成 `modelId = slug(模型名) + "-" + hash[..8]`。
8. 复制到托管目录：
   - `%LocalAppData%\OBS_Helper\live2d\models\<modelId>\`；
   - 同 hash 已存在则复用；
   - 复制到临时目录 → 校验 → 原子改名；
   - 失败清理临时目录。
9. 写清单 `manifest.json`：原始路径、模型名、hash、文件列表、导入时间、授权确认、VTS 目录（如已复制）。

### 4.3 复制到 VTS

- 先通过 `VTSFolderInfoRequest` 拿 `models` 目录名（通常是 `Live2DModels`），不要硬编码。
- VTS 安装目录下的 `StreamingAssets\<models>` 是目标；用户可能没有写权限（Program Files/Steam 库）。
- 复制前：
  - 检查 VTS 是否运行；运行中复制后需要重启/重新扫描才可见；
  - 目标目录不覆盖同名；用 `<模型名>-<hash8>` 子目录；
  - 记录“应用管理的副本”，写进清单；
  - 若目标已存在同 hash，复用，不重复复制。
- 复制后：
  - 提示“需要重启 VTS 或重新加载模型列表”；
  - 如果用户同意，关闭/重启 VTS？**不要强杀**；可以请求用户手动重启，或调用 VTS 的退出 API（如果有）并不推荐。
  - 重新连接后 `ModelsRequest`，按 `live2DModelName`/目录名匹配，拿到 `modelID`。
- 卸载：
  - 只删除清单里“应用复制到 VTS”的目录；
  - 用户原有模型不动；
  - 如果 VTS 正在使用，先提示关闭/切换模型。

### 4.4 授权与隐私

- 首次导入必须勾选：“我确认拥有该 Live2D 模型的使用权/再分发授权；本应用只在本机复制，不上传。”
- 不内置示例模型；不在日志里打印模型文件内容/纹理；路径可按现有 `LogSanitizer` 规则处理。
- 模型目录可能含作者信息/购买凭证；只读必要文件，不扫描无关文件。

## 5. VTube Studio API 客户端

### 5.1 传输

- WebSocket：`ws://127.0.0.1:<port>`，默认 `8001`；只用回环地址，拒绝外部主机。
- 端口发现：监听 UDP `47779`（只收不发），解析 `VTubeStudioAPIStateBroadcast`；超时回退 `8001`。
- 消息：JSON 文本；`apiName="VTubeStudioPublicAPI"`，`apiVersion="1.0"`，`requestID` 唯一，`messageType` 请求名，`data` 载荷。
- 超时：每个请求 5 秒；连接 3 秒；重连退避 1/2/4/8 秒，最多 3 次。
- 单飞：同一时间只允许一个鉴权/模型加载流程；UI 按钮防重复。

### 5.2 鉴权

```
1) 读 secrets.dat: vts.api.token
2) 有 token:
   AuthenticationRequest { pluginName, pluginDeveloper, authenticationToken }
   → authenticated=true  → 就绪
   → authenticated=false → 删除 token，走 3)
3) 无 token / 失效:
   AuthenticationTokenRequest { pluginName, pluginDeveloper, pluginIcon? }
   → VTS 内弹窗，用户允许 → AuthenticationTokenResponse { authenticationToken }
   → 存 secrets.dat
   → AuthenticationRequest 再确认
4) 用户拒绝 / API 未开:
   → 映射错误，给图文步骤；不循环弹窗
```

- `pluginName` / `pluginDeveloper` 必须与申请 token 时一致；固定为产品名与开发者名，不要随语言变。
- `pluginIcon` 可选：128×128 PNG base64；可用应用图标生成，但不要每次请求都带大图。
- token 最长 64 字符；只存 `secrets.dat`；提供“撤销/清除本应用授权”按钮（删除本地 token，并提示用户可在 VTS 内撤销）。
- 日志只记“已鉴权/被拒绝/API 未开”，不记 token。

### 5.3 模型相关请求

| 目的 | 请求 | 关键字段 | 说明 |
|---|---|---|---|
| 文件夹名 | `VTSFolderInfoRequest` | — | 取 `models`/`config`/`backgrounds` 等目录名 |
| 模型列表 | `ModelsRequest` | — | 解析可用模型列表；不要硬编码 response 字段，按 API 文档取 `modelID`/名称/文件名 |
| 当前模型 | `CurrentModelRequest` | — | 判断是否已加载、模型 id、位置/缩放 |
| 加载模型 | `ModelLoadRequest` | `modelID` | 空 id = 卸载；有 2 秒全局冷却；配置窗口打开时可能失败 |
| 移动/缩放 | `MoveModelRequest` | `timeInSeconds`（0~2）、`valuesAreRelativeToModel`、`positionX`/`positionY`/`rotation`/`size` | 用于布局；不要每帧狂发 |
| NDI | `NDIConfigRequest` | `ndiActive`、`useNDI5`、`useCustomResolution`、`customWidthNDI`/`customHeightNDI` | 需要 `ControlNDISettings` 权限；有 3 秒冷却 |
| 热键 | `HotkeyTriggerRequest` | 热键 id | 可选：触发表情/动作；需要先 `HotkeysInCurrentModelRequest` |

**错误映射**（示例）：

| VTS 错误 | 用户提示 | 动作 |
|---|---|---|
| 用户拒绝授权（errorID 50） | 你在 VTS 内拒绝了本应用 | 重新申请 / 打开 VTS 设置 |
| API 未开启 / 连接失败 | VTS 的 API 访问没有开启，或端口被改 | 图文步骤 / 手动端口 |
| 模型加载冷却 | 刚加载过模型，请等 2 秒 | 自动等待后重试一次 |
| 配置窗口打开 | VTS 正在打开配置窗口，无法加载模型 | 关闭窗口后重试 |
| 需要权限 | 需要 NDI 控制权限 | 申请 `ControlNDISettings` 或改用其它采集 |
| 模型不存在 | VTS 里找不到该模型 | 重新导入/重启 VTS/刷新列表 |

> 具体错误 ID 以 VTS 仓库 `Files/ErrorID.cs` 为准；实施时把常用错误映射成枚举，未知错误保留原始 message 到日志（脱敏后）。

### 5.4 客户端实现建议

- 新建 `Services/Live/VTubeStudioClient.cs`：
  - `ConnectAsync(port, ct)`
  - `AuthenticateAsync(ct)`
  - `GetFolderInfoAsync(ct)`
  - `GetModelsAsync(ct)`
  - `LoadModelAsync(modelId, ct)`
  - `MoveModelAsync(...)`
  - `SetNdiAsync(bool, ct)`
  - `DisposeAsync()`
- 新建 `VtsProtocolCore.cs`（纯逻辑）：
  - 构造请求 JSON；
  - 解析响应/错误；
  - 校验 `apiName`/`apiVersion`/`messageType`；
  - 把 VTS 错误映射成 `VtsError` 枚举；
  - 可单测，不需要真实 VTS。
- 不要把 WebSocket 逻辑塞进页面 code-behind；页面只订阅状态。

## 6. OBS 采集链路

### 6.1 能力探测（不要硬编码插件字段）

1. `GetInputKindList` 读取本机可用 inputKind。
2. 对候选 kind 创建“临时探测输入”（隐藏/不加入场景），用 `GetInputPropertiesListPropertyItems` 读取属性项；探测后删除。
3. 候选：

| 方式 | 常见 inputKind（需探测） | 关键设置 | 备注 |
|---|---|---|---|
| NDI | `ndi_source` | `ndi_source_name` 等 | DistroAV 版本不同字段可能不同；先列出 NDI 源再匹配 VTS |
| Spout2 | `spout2_input` 等 | sender 名称 | Off-World-Live 插件；GPL，外部安装 |
| 虚拟摄像头 | `dshow_input` | `video_device_id` | 用属性列表匹配 `VTube Studio`/`OBS Virtual Camera` 等名称 |
| 窗口采集 | `window_capture` | `window`、`method`、透明设置 | Windows 10 1903+ WGC 可尝试透明；否则色键 |

> 不要假设 `ndi_source`/`spout2_input` 的字段名永远不变；以 `GetInputPropertiesListPropertyItems` 的实际返回为准。插件未装时，`GetInputKindList` 里就不会有该 kind。

### 6.2 选择顺序

```
NDI（若 VTS NDI 可开 + OBS NDI 插件存在）
  → Spout2（若追踪软件支持 + 插件存在）
    → VTS 虚拟摄像头（若 DirectShow 设备存在）
      → 窗口采集 + 透明/色键
        → 图文引导（不创建源）
```

- NDI：
  - 先 `NDIConfigRequest` 开启（需要权限）；等待 3 秒冷却；
  - OBS 里创建 NDI 源，列出源并匹配 VTS 的实例/窗口名；
  - 如果 NDI 源列表为空，回退。
- Spout2：
  - 列出 sender；匹配 VTS/追踪软件；
  - 没有 sender 就回退。
- 虚拟摄像头：
  - 创建 `dshow_input` 临时源，查 `video_device_id` 列表；
  - 匹配 `VTube Studio`、`VTS`、`OBS Virtual Camera` 等（以实际设备名为准）；
  - 选中后保留源；音频仍用麦克风。
- 窗口采集：
  - 用 `window_capture` 的属性列表匹配 VTS 窗口标题；
  - 先尝试 WGC/透明；不支持时让用户把 VTS 背景设为纯绿/纯蓝，再加 `chroma_key_filter_v2`；
  - 不承诺 100% 透明；必须给“检查窗口采集方法/色键/背景”的提示。

### 6.3 场景与布局

- 如果用户从房间模板进入：
  - 找到 `role=avatar` 的占位源；
  - 删除/隐藏占位，创建/复用真实采集源；
  - 保持模板的层级/裁剪/边框位置。
- 如果没有模板：
  - 默认新建场景集合 `虚拟形象 · <模型名>`；
  - 创建场景 `主画面`；
  - 创建“虚拟形象”源，放到画布中央。
- 布局预设（按 `BaseWidth`/`BaseHeight` 计算）：

| 预设 | 目标框 | 说明 |
|---|---|---|
| 全身居中 | 高 ≈ 90% 画布，宽按比例 | 适合 16:9 全身 |
| 半身底部 | 高 ≈ 65%，底部对齐 | 常见杂谈 |
| 右下角半身 | 宽 ≈ 28%，右下留 40 px | 游戏直播 |
| 左侧 1/3 | 宽 ≈ 32%，左对齐 | 竖屏/双人 |
| 竖屏居中 | 宽 ≈ 90%，上半部 | 1080×1920 |

- 用 `SetSceneItemTransform` 设置 `positionX/Y`、`boundsType`、`boundsWidth/Height`、`alignment`；不要只设 scale（不同源原始尺寸不同）。
- 层级：`SetSceneItemIndex`；确保形象在背景之上、边框/文字之下（按模板 `zOrder`）。
- 裁剪/旋转：保留用户模板里的 transform；Live2D 只改位置/缩放，不覆盖裁剪。

### 6.4 音频

- OBS 采麦克风：`wasapi_input_capture`（共享源），VTS 只负责面捕/口型。
- 不要从 NDI/Spout/虚拟摄像头再采音频；否则双声/回声。
- 如果用户使用 VTS 的“麦克风输入”做口型，OBS 仍采同一支麦克风；VTS 不需要把音频输出给 OBS。
- 如果用户使用 VTS 的 NDI 音频（少见），在 UI 明确“视频用 NDI，音频用麦克风”，默认关闭 NDI 音频。

### 6.5 预览与验证

- `SaveSourceScreenshotAsync`/`GetSourceScreenshot` 抓一帧到临时 PNG；
- 检查：
  - 文件存在且 > 0；
  - 可选：像素采样（中心区域是否全透明/全黑/全绿）；不要做重型图像分析；
- 黑屏/透明：
  - 检查源是否隐藏、场景是否当前、NDI/Spout 是否在推、虚拟摄像头是否被占用、窗口是否最小化；
  - 给出“换采集方式”的一键按钮。
- 预览图只在本机显示；不上传、不进日志；可删除。

## 7. 状态机与错误处理

### 7.1 状态机

```
Idle
 → CheckingObs
 → CheckingVts
 → AwaitingModel
 → AwaitingConsent        (复制模型/启动 VTS/API 授权)
 → ImportingModel
 → ConnectingVts
 → Authenticating
 → LoadingModel
 → ChoosingCapture
 → ApplyingScene
 → Verifying
 → Done
```

每个状态：
- `StepId`、`Title`、`Detail`、`Progress`、`CanCancel`、`CanRetry`；
- 失败进入 `Failed`，保留已完成步骤，允许“重试当前步/换方案/跳过”；
- 取消：清理临时文件/临时源；不删除已成功的模型副本（除非用户选择“撤销导入”）；
- 不把“OBS 源已建但预览黑屏”标成成功；状态必须是 `NeedsAttention`。

### 7.2 错误码建议

| 错误码 | 场景 | 出口 |
|---|---|---|
| `L2D_NO_OBS` | 没装 OBS | 官方下载卡 |
| `L2D_OBS_NOT_RUNNING` | OBS 未运行 | 启动并等待 |
| `L2D_OBS_NOT_CONNECTED` | OBS 未连接 | 自动连接/控制台 |
| `L2D_OBS_V4_LIMITED` | Win7/v4 不支持某步 | 降级/手动 |
| `L2D_NO_VTS` | 没装 VTS | Steam 商店/官方说明 |
| `L2D_VTS_NOT_RUNNING` | VTS 未运行 | 启动 VTS |
| `L2D_VTS_API_OFF` | API 未开 | 图文步骤 |
| `L2D_VTS_AUTH_DENIED` | 用户拒绝 | 重新申请/打开设置 |
| `L2D_VTS_PORT` | 端口找不到 | 手动端口/UDP 诊断 |
| `L2D_MODEL_INVALID` | 模型缺文件/越界 | 重新选择 |
| `L2D_MODEL_TOO_BIG` | 超限 | 说明限制 |
| `L2D_MODEL_COPY_FAILED` | 权限/占用 | 关闭 VTS/换目录 |
| `L2D_MODEL_NOT_IN_VTS` | VTS 列表没有 | 重启 VTS/刷新 |
| `L2D_LOAD_FAILED` | 加载失败 | 关闭配置窗口/等待冷却 |
| `L2D_CAPTURE_UNAVAILABLE` | 没有可用采集 | 安装插件/窗口采集 |
| `L2D_PREVIEW_BLACK` | 预览黑屏 | 检查源/NDI/窗口/色键 |
| `L2D_AUDIO_DOUBLE` | 可能双声 | 提示只用麦克风 |

### 7.3 回退策略

- VTS 不可用 → “只采集已有追踪窗口”（P1）或图文引导；
- NDI 不可用 → Spout2 → 虚拟摄像头 → 窗口+色键；
- 窗口透明失败 → 纯色背景 + 色键；
- OBS v4 → 不调用 v5-only 请求；能给提示就给，不能就跳过；
- 模型导入失败 → 不删除用户原文件，保留错误详情。

## 8. 安全、许可与隐私

| 面 | 措施 |
|---|---|
| 模型文件 | 只读解析；复制到托管目录；不执行；拒绝可执行文件；路径穿越/符号链接防护 |
| 模型授权 | 用户确认拥有使用权；不内置模型；不提供下载站链接 |
| VTS token | `secrets.dat`；日志不打印；可清除；请求仅回环 |
| VTS 进程 | 只通过公开 WebSocket API；不注入、不读内存、不改配置 |
| NDI/Spout | 只使用已安装的 OBS 插件；不捆绑 GPL 插件；不静默安装 |
| 预览截图 | 只在本机临时目录；可删除；不上传 |
| 日志 | 模型路径/用户名按现有规则脱敏；不记录 token/密钥 |
| 第三方链接 | 只允许官方 Steam/GitHub/OBS 域名；HTTPS |

**许可证边界**：
- VTube Studio 是第三方软件，按其许可使用；本应用只调用公开 API。
- Live2D Cubism Core/模型受 Live2D 许可约束；本应用不分发。
- NDI/Spout2/DistroAV 等插件是 GPL 系；只做外部安装引导，不复制、不捆绑。

## 9. 测试计划

### 9.1 纯逻辑单测

- `Live2DModelCore`：
  - 正常模型解析；
  - 缺 `.moc3`、缺纹理、缺 physics；
  - `..`/绝对路径/符号链接；
  - 文件数/大小/纹理尺寸超限；
  - 可执行文件混入；
  - hash 稳定、同 hash 复用、不同 hash 不覆盖。
- `VtsProtocolCore`：
  - 请求 JSON 形状；
  - 鉴权成功/失败/拒绝；
  - `ModelsRequest`/`ModelLoadRequest`/`MoveModelRequest`/`NDIConfigRequest` 响应解析；
  - 未知错误保留 message；
  - 超时/断线错误。
- `Live2DCaptureCore`（纯逻辑）：
  - 候选排序（NDI > Spout > vcam > window）；
  - 设备名匹配；
  - 布局计算（横屏/竖屏/DPI/边界）；
  - 失败回退决策。

### 9.2 集成/手工

| 场景 | 预期 |
|---|---|
| VTS 未装 | 引导到官方商店；不崩溃 |
| VTS 已装未运行 | 启动 VTS；等待 API；用户允许 |
| VTS API 未开 | 图文步骤；重试成功 |
| 用户拒绝授权 | 明确错误；可重新申请 |
| 模型已在 VTS | 直接列出/加载；不重复复制 |
| 模型新导入 | 复制 → 重启 VTS → 列表出现 → 加载 |
| NDI 可用 | 自动建 NDI 源；透明；预览正常 |
| NDI 不可用 | 回退 Spout/vcam/window；不卡死 |
| 窗口采集 | 透明/色键至少一种可用；失败给提示 |
| 竖屏模板 | 布局不越界；形象不被裁切 |
| OBS v4/Win7 | 不调用 v5-only；明确降级 |
| 音频 | 只有一路麦克风；无双声 |

### 9.3 验收标准

- 有 VTS + 有效模型 + OBS 的用户，从“选择模型”到“OBS 场景出现形象”≤ 5 次点击（不含 VTS 首次授权）。
- 任一失败步骤都有错误码 + 人话 + 一个可执行动作。
- 不修改用户原模型；不删除用户场景；默认新建集合。
- 预览截图不落日志；token 不出现在任何日志/诊断。
- 关闭/重开应用后，配置可复用（模型 id、采集方式、布局）。
