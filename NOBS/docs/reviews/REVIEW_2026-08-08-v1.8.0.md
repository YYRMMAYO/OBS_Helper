# OBS 排障助手 · V1.8.0 审查报告

审查日期：2026-08-08
版本：V1.8.0
范围：`NOBS/OBS_Helper.Wpf/Services/Ai`（免费模型校验与默认值）、`NOBS/OBS_Helper.Wpf/Views/SettingsPage.*`（模型下拉）、`NOBS/OBS_Helper.Wpf/OBS_Helper.Wpf.csproj`（版本号）、README（仓库根 + NOBS）。

---

## 一、整体结论

本版修复用户实测报错 **`HTTP 400 code 1214 "modelCode:不存在"`**（免费 AI 用智谱通道诊断必现失败）。经三遍交替检查（构建自检 → 代码审查 → 构建自检 + 回归实测），无遗留问题。

---

## 二、根因

1. **模型名不可信**：设置页的模型框是自由文本输入，用户（或误操作）把「显示名」（如 `智谱 GLM 4.7 flash`）保存进了 `prefs.json` 的 `freeModel`，请求时原样发给智谱 → `1214 modelCode:不存在`，每次诊断都 400。
2. **免费模型编码本身在变动**：智谱线上曾静默下线 `glm-4.7-flash`（文档仍写免费，线上 400/1214；`/v4/models` 已不含它）；当前实测 `glm-4.7-flash` 恢复可用但**高峰频繁 429 限流**（3 次实测仅 1 次成功），`glm-4-flash-250414` 稳定（3/3 成功）。

## 三、修复

1. **模型下拉选择**（`Views/SettingsPage.xaml(.cs)`）：模型框从自由文本改为 `ComboBox`，只列出「当前线上实测可用」的编码——杜绝手输显示名/过期编码；
2. **非法值自动回退**（`Services/Ai/AiSettingsService.cs`）：`EffectiveFreeModel` 对已保存值做白名单校验（`KnownFreeModels` / `KnownPollinationsModels`），不在白名单一律回退默认——**老用户 prefs 里已存的脏值无需手动清理，升级即自愈**；
3. **默认模型改为稳定档**：`glm-4-flash-250414`（实测 3/3 稳定、文档标注免费）作为默认，`glm-4.7-flash` 保留下拉（更新但高峰限流）；
4. **保留免 Key 通道**：Pollinations（国外 · 免 Key）继续可用，用户可一键切换（按需求「不可以用就保留不用 API key 的模型」）。

## 四、验证记录（三遍交替）

| 遍次 | 方式 | 结果 |
| --- | --- | --- |
| 第 1 遍 | `dotnet build`（Debug）+ 真实智谱模型探测 | 构建 0 错误；`/v4/models` 列出 8 个在线编码；批量实测候选模型（200/403/400 分类）；`glm-4-flash-250414` 3/3、`glm-4.7-flash` 1/3 |
| 第 2 遍 | 代码审查（模型校验 + 下拉 + 回退逻辑） | 修复项全部落实后复核通过 |
| 第 3 遍 | `dotnet build`（Release）+ `OBS_SELFTEST=1` + 回归实测 | 构建通过、自检 15 PASS / 0 FAIL；回归实测：填入脏值 `智谱 GLM 4.7 flash` → `EffectiveFreeModel` 归一为 `glm-4-flash-250414` → 真实诊断 `engine=free` 成功（未回退），偶发 429 时优雅回退本地 |

回归实测要点：老用户升级后，即使 `prefs.json` 里存着非法模型名，诊断也会自动用默认免费模型发起，不再 400。

## 五、遗留说明

- 智谱免费档高峰偶发 429（模型访问量过大），应用侧「失败即回退本地」兜底；若长期如此可在下拉里改选 `glm-4.7-flash` 或切 Pollinations。
- `KnownFreeModels` 为线上实测快照；智谱若再次调整模型编码，需同步更新该列表（文档与线上不一致时以实测为准）。
