# 用户视角功能结论：简单录像 与 其它便捷功能（2026-10-05）

> 本文是 **V2.9.4 的开工依据**：先如实描述软件现状，再从用户视角找出「想录个像」这条路上
> 真正硌脚的地方，最后给出「简单录像」的定义与其它便捷功能的优先级。
> 逐文件改动、文案键与单测清单在 [`SIMPLE_RECORDING_DESIGN.md`](SIMPLE_RECORDING_DESIGN.md)。
>
> 结论的证据边界：所有「现状」都在本机源码里逐处读过并标注了文件；
> 「推荐做法」属于工程判断，不是实测数据 —— 需要真机验证的地方单独标了 ⚠️。

---

## 一、现状盘点：软件已经有什么

| 能力 | 落点 | 现状 |
|---|---|---|
| 一键部署录制环境 | `Services/ObsConfig/RecordingEnvCore.cs`、`RecordingEnvService.cs`、`Controls/RecordingEnvCard.xaml.cs` | 6 项推荐值（Hybrid MP4 / HQ / 录像目录 / 1920x1080 / 60fps / 48kHz）；双通道落地（WebSocket `SetProfileParameter` 或 `basic.ini`）；**应用前整备份、逐项可取消、写盘后读回校验、可回滚** |
| 录前自检 | `Services/Obs/PreflightCheckCore.cs` | 6 项只读：录像格式防崩溃、录像路径与剩余空间、是否软编、采样率、麦克风设备、关键帧间隔 |
| 录制控制 | `Views/ConsolePage.xaml.cs`、`Services/Obs/ObsConnectionService.cs` | 开始 / 停止 / 暂停；开始不二次确认，停止要确认 |
| 热键 / 托盘 / 小窗 | `Services/Shell/GlobalHotkeyService.cs`、`TrayService.cs`、`Views/MiniControlWindow.xaml.cs` | 录制开关热键、托盘录制中标识、置顶小窗开关 |
| 录制守护 | `Services/Shell/RecordWatchdogService.cs` + `RecordWatchdogCore.cs` | 断连时在录 / 心跳超时 / 重连后发现录制丢失 → 托盘强提醒 |
| 定时停止 | `Services/Shell/ControlTimerService.cs` | 15/30/45/60/90 分钟到点自动停 |
| 录像工具 | `Services/ObsConfig/RecordingToolsService.cs`、`Views/ToolboxPage.xaml` | 打开录像目录、ffmpeg 无损转封装、录像盘写入测速 |

## 二、把现状翻成用户视角：还差什么

现有「一键部署录制环境」的真实语义是**「一键改配置」**，不是**「一键开始录像」**。
按「我就想录个像」走一遍，缺口很具体：

1. **入口深**：部署卡在「搭建」页；首页九宫格、托盘菜单都没有直达路径；
2. **动作碎**：点完部署卡还要选预设 / 勾项 / 应用，结尾没有「现在开始录」；
3. **不认识状态**：`RecordingEnvService.BuildPlanAsync` 只按「连上了 / 没连上但 OBS 没跑 / 其它」分流，
   不告诉用户「现在能不能录」；
4. **不够用的部署项**：没有录像分段、没有关键帧间隔 —— 而这两项恰好是「录长视频」与「后期剪辑」的关键；
5. **自检与部署互不相通**：自检在「诊断」页，与「搭建」页的部署卡各管一段，用户得自己记住三部曲；
6. **OBS 没开机就没路**：`ObsPathService` 只有 `IsObsRunning` / `DetectProcess`（只读探测），
   全仓库**没有启动 obs64.exe 的能力**，也没有「文件通道改完要重启 OBS 才生效」的收尾引导；
7. **录制中看不见**：`ConsolePage.RenderOutputs` 只有「进行中 / 已暂停」两个词，
   没有时长、没有占用空间、没有剩余可录时长；
8. **守护只报警不解决**：拾到丢失后要用户自己回 OBS 重开；
9. **停止后无收尾**：不提示文件已生成，也没有「停止并打开目录 / 转 MP4」的直达。

## 三、「简单录像」的定义

> **一句话**：把「配好 → 验好 → 开录 → 录得住 → 录完找得到」串成一次点击，
> 且不改用户没同意过的任何参数。

### 3.1 三档预设（用户只需选一个词）

| 预设 | 录像规格 | 说明 |
|---|---|---|
| `quick` 快速录像（默认） | 1080p **60fps** · HQ · Hybrid MP4 · 48kHz | 通用推荐 |
| `meeting` 会议 / 网课 | 1080p **30fps** · HQ · Hybrid MP4 | 文件小、CPU 友好 |
| `game` 游戏高码率 | 1080p **60fps** · HQ · Hybrid MP4 · **自动分段** | 长录制不产生单个巨型文件 |

三档都**只写现有部署口径已经覆盖的键**，新增的只有：
`RecFormat`（三档一致）、`RecQuality`（三档一致）、`RecTracks=1`（兼容旧版 OBS 音频轨默认值）、
`RecSplitFile=true` + `RecSplitFileTime` / `RecSplitFileSize`（仅 `game`）。

**刻意不碰**：输出模式（`Output/Mode`）、编码器族（`RecEncoder`）、码率（`VBitrate`）、推流参数。
理由与 V2.9.3 一致 —— 改这些会连带影响用户正在用的工作流，且本机无法验证取值正确性。
需要它们时走「高级设置」（跳现有部署卡）。

### 3.2 一次点击背后的 11 步状态机

```
Idle → Checking ─┬─ Blocked              （缺配置 / 正在推流 / 文件通道写不了）
                 └─ SettingUp            （先整备份，再按当前值 → 目标值落地）
                        → LaunchingObs   （OBS 没跑才需要）
                        → WaitingObs     （等 obs-websocket 就绪，带超时）
                        → Recording      （调 StartRecord）
                        → Stopping → Stopped（提示文件 + 打开目录 / 转 MP4）
```

- **已有 WebSocket 通道**：`SettingUp → Recording`，一步到开录；
- **OBS 已退出**：先按 `basic.ini` 落地 → 询问是否「启动 OBS 并开始录像」→ 本工具拉起 OBS → 轮询连接 → 自动开录；
- **正在推流**：`Blocked`。这条是硬口径：直播中不去改输出参数、也不抢录制输出。

### 3.3 落地约束（沿用项目的既有纪律）

1. 任何写入前先整备份，备份失败即中止（复用 `ObsBackups.CreateBackupAsync`）；
2. 每一项都记旧值、可回滚（复用 `RecordingEnvResult.Rollback`）；
3. 写入后读回逐项校验（复用 `RecordingEnvService` 的文件通道校验）；
4. 新动作全部走文案表，中英各一份；
5. 不静默安装、不静默改配置、不做无人值守的后台改写。

## 四、用户视角还有哪些便捷功能值得做

按「离痛点多近 × 实现成本」排序，分四组。**标注「本版」的已在 V2.9.4 落地**。

### P0 · 第一支录像的焦虑（与「简单录像」共用基建）

| 功能 | 用户场景 | 本版 |
|---|---|---|
| **自检 + 部署 + 开录三合一** | 「不知道能不能录，先试一下」 | ✅ 本版 |
| **OBS 没启动也能一键进入可录状态** | 「OBS 根本没开」 | ✅ 本版（拉起 + 等就绪 + 自动开录） |
| **「现在能不能录」的一句话结论** | 不想读 6 行清单 | ✅ 本版（就绪 / 阻断 + 原因） |
| OBS 在跑但没连上时的引导 | WebSocket 未开 / 密码不对 | ✅ 本版给出可照做的原因与出口 |

### P1 · 录得住（录制可靠性）

| 功能 | 为什么值 | 本版 |
|---|---|---|
| **录制中显示时长 + 剩余可录时长** | 「还要多久录满」是录制场景第一大未知 | ✅ 本版 |
| 磁盘将满的提前处置（提醒 + 一键分段） | 现在只有 30 分钟一次的托盘低谷预警 | ⏳ 仅保留提示（分段仅 `game` 预设默认开） |
| 录制中断后一键重开 | 守护只提醒，用户还要回 OBS | ⏳ 下一版（需要把守护通知改成可操作） |
| 停止后文件落盘核对 | 「录完才发现是空文件」 | ✅ 本版（停止后读文件大小并提示） |

### P2 · 录完省事（后期与文件管理）

| 功能 | 本版 |
|---|---|
| **停止后一键打开目录** | ✅ 本版 |
| **停止后一键转 MP4**（有 ffmpeg 时） | ✅ 本版（无 ffmpeg 时给 OBS 自带转封装指引） |
| 录像盘写入体检前置 | ⏳ 已有测速卡，未与开录串联 |
| 录制文件完整性快检（0KB / 未收尾 MP4） | ⏳ 下一版候选 |

### P3 · 更大范围的便捷（价值高但工作面大，未做）

- 一键准备采集场景（复用 `SceneTemplateService` 建「显示器捕获 + 麦克风 + 桌面音频」教学场景）；
- 三个问题问出「场景 + 参数」的问答式向导，替代参数清单；
- 迷你小窗常显录制时长与剩余空间；
- 每次启动的静默 5 秒体检（配置一致性 / 录像盘 / Game DVR / GPU 偏好）；
- 录制失败 → 自动取最新日志 → 分析 → 给处置建议（三块都已存在，只是没串起来）。

### 明确不做

- **不静默改配置**：沿用「先备份、可回滚、逐项可取消、写操作需显式确认」；
- **不碰推流参数与输出模式**：与 V2.9.3 口径一致；
- **不做无人值守的后台常驻改写**：与本项目「只读探测优先」的基调冲突。

## 五、风险与证据边界

1. ⚠️ `RecQuality=HQ` / `hybrid_mp4` / `RecSplitFile*` 这些**取值本身没有对真实 OBS 验证过**
   （V2.9.3 发布说明已如实记录「一键部署没有对真实 OBS 跑过端到端落地」）。
   本版的处理是：**不新增没有依据的写项、不碰用户自有选择**，并把「没有真机验证」写进审查记录；
2. ⚠️ 拉起 OBS 的可执行文件路径来自注册表 `Uninstall\OBS Studio` 的 `DisplayIcon` 与常见安装目录；
   便携版（`portable_mode.txt`）与绿色解压版的识别能力有限，找不到时**不猜路径**，直接让用户自己开 OBS；
3. **`SettingUp` 必须拒绝直播中执行**：这条是硬门槛，不是提示；
4. **新增文案必须中英双份**（`StringTableZhHans` / `StringTableEnUs` 键集由单测钉死）；
5. **双目标构建**（`net10.0-windows` / `net6.0-windows`）：不使用 .NET 7+ 独有 API，
   需要 polyfill 时走 `Services/Compat`。
