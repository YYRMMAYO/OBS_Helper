# OBS 排障助手 V2.9.3 发布说明

> 主题：**把随包离线内容也做成中英双份**、**一键部署录制环境**、**扩展获取与反馈通道**、
> **兼容到 Windows 7 SP1**。

上一版（V2.9.2）把界面与代码内文案做成了中英双语，但**随包的数据资产只有中文** ——
英文界面下知识库、插件广场、场景模板、排障指引这四处仍然显示中文。
本版补齐这块，并顺手把「装不上 / 装错包 / 下不下来 / 不能反馈」这几件事一并解决。

---

## 1. 随包内容全量英译（知识库 / 插件 / 模板 / 指引）

| 资产 | 体量 | 英文并列文件 |
|---|---|---|
| 知识库 | 212 条 / 57,717 汉字 | `problems.en-US.json` |
| 插件广场 | 57 条 | `plugins.en-US.json` |
| 场景模板 | 12 套 / 323 处可译叶子 | `scene_templates.en-US.json` |
| 排障指引 | 全文 | `troubleshooting.en-US.md` |

**中文文件名刻意保持不变**：现有中文热更新地址（GitHub raw）、Release 资产名、
用户本机已下载的缓存文件都依赖 `problems.json` 这些名字，改了就是静默回归。
英文资产是**并列的新文件**，后缀 `.en-US`。

英译的口径（写进作业规范并逐条执行）：

- **只译「展示文案」，不译「逻辑键」**：`id` / `category` / `related` / `platforms` /
  `links[].url` / `repo` / `dlls` / `maintain` / `inputKind` / `transform` / `settings` 里的数值
  一律逐字照抄；
- **展示值用固定映射**，不自创近义词：`severity` 的 `常见→Common`、`一般→Occasional`、
  `严重→Critical`、`进阶→Advanced` 等与 `Localization/DataValues` 认识的英文串一一对应，
  `steps[].level` 的 `基础→Basic`、`进阶→Advanced`、`兜底→Fallback`、`提示→Note` 同款对齐；
  插件角标 `热门→Popular`；
- **同一中文来源名必须译成同一英文名，且不同中文名不得撞名**：场景模板里的
  `sources[].name` 会被**写进 OBS**，`shared: true` 的来源靠名字跨场景复用 ——
  译错这一处的后果是重复创建设备、占住摄像头，是唯一会导致「功能坏了」的翻译错误，
  因此有专门的单测（`SceneTemplates_SourceNamesAreConsistentAndDistinct`）；
- **数字 / 单位 / 路径 / 快捷键 / 菜单路径原样**：`48kHz`、`1920x1080`、`60fps`、
  `%ProgramData%\obs-studio\plugins`、`Ctrl+Shift+R`、`Settings → Output → Recording`；
- **不许残留汉字与全角标点**：机器可查，漏一处测试就红。

## 2. 内容按语言装载（`Localization/ContentAssets`）

新增统一入口，解析次序固定：

```
当前语言的外部缓存（%LocalAppData%\OBS_Helper\data\problems[.en-US].json）
  → 当前语言的随包内嵌
    → 中文随包内嵌（最后兜底，且**必写 WARN 日志**）
```

最后一级兜底必须写日志这条是**刻意设计**：否则英文用户会「安静地看到中文内容」——
正是 V2.9.1 修 raw 404 时踩过的那个坑（静默失败能潜伏很久）。

知识库 / 插件目录 / 场景模板 / 排障指引四处读取方全部改走该入口，
并在**语言切换时丢弃按语言缓存**（挂在 `LocalizationService.Changed` 上），
因此切语言是即时的：不需要重启，也不需要手动触发刷新。

## 3. 热更新两条通道按语言分发

| 通道 | V2.9.3 改动 |
|---|---|
| GitHub raw 主通道 | 新增 `problems.en-US.json` / `plugins.en-US.json` 地址；`RawFor()` 与随包资产命名共用同一套后缀规则，避免两处各写一套 |
| Release 资产兜底 | 匹配器**按语言严格区分**：中英资产挂在同一个 Release 上，原来的「前缀 + `.json` 后缀」匹配会把两份都认下来，中英用户互相拿到对方的文件。新增 `UpdateService.AssetMatchesLanguage`（含大小写不敏感与仿冒名用例） |
| 本地缓存文件 | 按语言分文件：中文沿用 `problems.json` 以保证兼容，英文用 `problems.en-US.json` |
| 节流状态 | 也按语言分（否则切到英文会被中文那份的 6 小时节流挡住） |
| 语言切换 | 补一次静默刷新当前语言那一份（英文那份的节流状态是全新的，因此会真的联网拉一次） |

`build.ps1` 现在会导出**四份**资产（中英 × 知识库 / 插件目录）到 `PAKE/windows/`，
Release 兜底通道才真正对英文用户可用。

## 4. 一键部署录制环境

装好 OBS 之后最实际的一步：把与录制质量直接相关的配置一次到位。
按「录制向」逐项列出现状与建议，**全部先自动备份、可一键回滚、每项可单独取消**：

| 项 | 建议值 | 理由 |
|---|---|---|
| 录像格式 | `hybrid_mp4` | 崩溃 / 断电也能救回文件，主流剪辑软件直接认 |
| 录像质量（简单模式） | `HQ` | 画质与体积的平衡点 |
| 录像保存目录 | 当前解析到的可用目录 | 避免默认落在系统盘 |
| 画布 / 输出分辨率 | 1920x1080 | 画布与输出一致，避免二次缩放的模糊与开销 |
| 帧率 | 60 | 录制更顺滑；机器吃力可取消勾选 |
| 音频采样率 | 48000 | 直播 / 录制的事实标准，避免爆音与音画漂移 |

两条落地通道，按可用性自动选择：

- **obs-websocket**（首选，OBS 已连接）：逐参数 `SetProfileParameter`，改完即时生效、无需重启；
- **basic.ini 文件层**（OBS 已退出）：只改当前配置集下的 `basic.ini`，**写盘前先整体备份、
  写盘后重新读回逐项校验**；写不了音频采样率（INI 里音频设置的位置随 OBS 版本变动，
  赌错就是把用户配置搞乱）—— 界面上会明说「需要改采样率请连上 OBS」。

明确不做的事：**不碰推流参数、不碰输出模式**（那些属于用户自己的选择，改了会连带
影响他正在用的工作流），也不做无人值守的静默全自动改写。

三档阻断原因各自给人话：找不到配置目录 / OBS 在跑但没连上（WebSocket 未开或密码不对）/
读不到当前配置集的 `basic.ini`。

## 5. 获取 OBS 的通道扩展

在原有三条**官方**入口（官网下载页 / GitHub 发布页 / 当前稳定版直链）之上新增：

- **应用内下载官方安装包**：解析当前稳定版直链（不是写死版本号）→ **再次校验落在官方域名下**
  （`obsproject.com` 含官方 CDN 子域 / `github.com/obsproject/obs-studio`）→ 流式下载带百分比进度
  → 下完露出「运行安装向导」。**不做静默安装**：用 ShellExecute 打开官方安装程序，
  UAC 与安装路径始终由用户决定；
- **瓦特工具箱（原 Steam++）** `steampp.net`：GitHub 拉不动时的第一条退路 ——
  它的「网络加速 → GitHub」是本地反向代理、只对白名单域名生效，装完勾选 GitHub 一键加速即可；
- **微软商店的 OBS Studio** `apps.microsoft.com/detail/XPFFH613W8V6LV`：官方下载页里的
  「Get it from Microsoft」就是这一条；中文说明里如实标注「商店版更新略慢于官网」。
  低于 Win10 1809 的系统上**隐藏该入口**而不是留一个点了报错的按钮。

备用通道与官方源**分开判定**（`IsTrustedAlternativeChannel` vs `IsOfficialDownloadUrl`）：
把第三方塞进「OBS 官方下载」的白名单会让「只从官方渠道下载」这句防伪提示失真。

## 6. BUG 反馈

- **表单**（腾讯文档，`docs.qq.com`）+ **GitHub Issues** 两个入口，出站前都过白名单
  （https + 限定域名 / 本仓库，同前缀仿冒域拒绝）；
- **二维码随包内嵌**（`Assets/feedback_qr.png`）：离线可扫，不依赖任何在线二维码服务。
  生成脚本用两个互不相关的实现交叉核对，**再用独立解码器（zxing-cpp）把 PNG 读回来**，
  断言解出的文本与表单地址逐字符一致 —— 编出来的图真的能扫出这个地址才算过；
- 二维码里编的内容与按钮指向的地址由单测钉死为同一个常量，防止二者漂移
  （扫码的用户被送到另一个页面是**没有任何提示**的）；
- 资源缺失时整格收掉并给出「请用上面按钮」的说明，而不是留一块白框。

## 7. 兼容到 Windows 7 SP1（双目标构建）

`.NET 10` 最低只支持 Windows 10，而 **.NET 6 是最后一个官方支持 Windows 7 SP1 的版本**。
本版改成**双目标并存**，同一份源码编两遍：

| 构建 | TFM | 产物 | 安装包 MinVersion |
|---|---|---|---|
| 主构建 | `net10.0-windows` | `OBS_Helper_Setup_2.9.3.exe` / `OBS_Helper_Portable_2.9.3.zip` | `10.0` |
| 兼容构建 | `net6.0-windows` | `OBS_Helper_Setup_2.9.3_win7.exe` / `OBS_Helper_Portable_2.9.3_win7.zip` | `6.1sp1` |

- 两者共用同一个 AppId：在用户眼里就是一个软件，Inno 才会把「换构建」识别成升级而不是并存装两份；
- `MinVersion` 是「装得上但跑不起来」的最后一道拦截 —— 装错构建时用户看到的是
  「双击没反应」，而不是一句能照做的提示；
- 兼容层（`Services/Compat`）只做**语义完全等价**的替换，不为迁就老框架降低功能：
  `required` 成员的编译期 polyfill、`char.IsAsciiDigit` 等价的实现、
  `AesGcm` 新旧构造函数（两条分支密文完全一致）、
  文件夹选择对话框（net8+ 用 WPF 的 `OpenFolderDialog`，net6 退到 WinForms 的
  `FolderBrowserDialog` —— 托盘图标本来就在用它，不引入新依赖）；
- 界面按系统版本显隐入口（微软商店需要 Win10 1809+），并给出「当前为 Windows 7 兼容构建」的说明文案。

> ⚠️ 兼容构建用的是 .NET 6，**已停止安全更新**。它是为「必须在 Win7 上跑」的场景准备的退路，
> 新机器请一律使用主构建。

## 8. 顺手修掉的既有问题

- **单测里一个会「过期」的用例**：`GraphicsEnvCheckCoreTests.DriverAgeParsing` 把驱动日期
  写死成 `20260801…` 并断言「距今 0 个月」，于是**测试本身随系统日期漂移**——
  在 2026-10 跑就变成 2 个月直接失败（本版开工时的基线就是 441 项里挂 1 项）。
  改成按当前日期相对生成，越久跑越准。

## 9. 质量基线

- **560 项单元测试全部通过**（上一版 441 项，本版新增 119 项）；
  新增部分专盯「编译器看不见」的错法：中英形状逐条对等、英文侧不残留汉字与全角标点、
  展示值落在 `DataValues` 认识的取值内、场景来源名一致且不撞名、
  指引标题层级 / 代码围栏 / 链接 URL 与中文版一一对应、
  资产按语言的解析与回退次序、Release 资产匹配不串语言、INI 打补丁的保真性与读回校验、
  Windows 版本判据的每一档、下载与反馈入口白名单；
- **三轮分视角审校**（数据安全与出站 / 双目标与构建边界 / 交互与文案一致性），
  记录见 [`../../docs/reviews/REVIEW_2026-10-05-v2.9.3.md`](../../docs/reviews/REVIEW_2026-10-05-v2.9.3.md)，
  其中如实标注了「哪些结论有机器证据、哪些只是人工核对」；
- 全程零第三方 NuGet 包（纯 BCL）。

## 10. 已知边界

- 英译由人工 + 机器校验共同把关：**形状与取值可机器验证**，
  「英文版 OBS 的实际菜单文案是否逐字一致」这类只能对着英文版 OBS 核的部分，
  已在审校记录里标注证据边界，不宣称已 100% 对齐；
- 兼容构建（net6.0-windows）功能与主构建一致，但性能与内存略逊（旧运行时），
  且不再收到 .NET 安全更新；
- 微软商店的 OBS 在部分区域（如欧盟）存在区域限制，界面文案已如实提示。
