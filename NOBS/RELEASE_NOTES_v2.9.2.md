# V2.9.2 发布说明 — 国际化（中文 / English 即时切换）

> 界面、托盘、通知、报错提示与各类体检结论全部支持中英两套文案，**默认简体中文**，
> 设置页可即时切换、无需重启；安装包增加语言选择页（默认中文），选定结果作为应用首启的默认语言。
> 随包的离线内容（知识库 / 场景模板 / 插件目录 / 排障指引）本版仍为中文，
> 英文内容的落地计划见 [`docs/I18N_EN_CONTENT_PLAN.md`](docs/I18N_EN_CONTENT_PLAN.md)。

## 一、这次做了什么

### 1. 运行时语言切换（中 / 英），默认中文

- **文案表**：`Localization/StringTableZhHans.cs` + `StringTableEnUs.cs`，共 **1670 条键**，
  按模块分段（导航 / 页面 / 控制台 / 工具箱 / 插件广场 / 设置 / 日志规则 / 体检结论 / 报错码 …）。
  键名与展示文案分离：XAML 与代码引用的是键，值才随语言变。
- **即时生效、无需重启**：沿用换肤那套已经跑熟的机制 —— 把当前语言的文案整体写进
  `Application.Resources`（键为 `Loc.<文案键>`），XAML 一律用 `{DynamicResource Loc.xxx}` 引用，
  于是切换语言与切换主题走的是同一条路径。
- **代码里拼出来的文案**（列表项、卡片、报告、Toast、对话框）由
  `Services/LocalizationService` 广播 `Changed` 事件，主窗口据此把**当前页面原地重放一次**
  （复用页面既有的 `OnNavigatedToAsync` 生命周期），并刷新两枚连接徽章与托盘菜单 ——
  不需要给每个页面各写一套刷新逻辑。
- **纯逻辑文件也能取文案**：`Strings` / `DataValues` 是纯 BCL、零 WPF 依赖，
  因此日志分析器、录前自检、各类体检核心这些被单测工程直接链接编译的文件，
  可以共用同一份文案表（零第三方包的原则不变）。

### 2. 安装包语言选择页（默认中文）

- `[Languages]` 增加 **ChineseSimplified**（`compiler:Languages\ChineseSimplified.isl`）与 **English**，
  安装向导自身的文字（按钮、步骤、错误提示）随所选语言切换。
- **默认中文**：`LanguageDetectionMethod=none` + `ShowLanguageDialog=yes`，
  语言列表里简体中文排在第一位，向导一定弹语言选择页、默认选中中文，不跟随系统语言探测。
- **选定结果传给应用**：向导把 `[app] language=` 写进 `{app}\language.ini`；
  应用首启时读取它作为默认语言。判定次序是
  **用户在应用内选过 > 安装向导选过 > 简体中文**，
  所以在应用里改过语言后，重装 / 升级都不会把用户的选择覆盖掉。
- 快捷方式名、卸载项显示名、附加任务与完成页文案都做了语言化
  （`[CustomMessages]` + `{cm:...}`），英文用户装完看到的是一整套英文入口。
- 安装目录名与 AppId **刻意不随语言变化**：Inno 会记住安装目录并在升级时复用，
  若随语言改变，英文用户重装会落到第二个目录、应用内的增量更新也会找不到目标文件。
- 脚本文件按 UTF-8 **带 BOM** 保存（Inno 6 见到 BOM 必定按 UTF-8 解析；实测无 BOM 时它也会自动识别，
  带 BOM 只是把这一点固定下来，换编辑器或换旧版 ISCC 都不会退化成按 ANSI 读）。

### 3. 数据驱动的展示值：两种语言都认

知识库里 `severity` / `level` 这类字段是**展示文案**（中文「常见」、英文 `Common`），
但它们同时被逻辑用来选颜色、决定排序与排版。已经下载到本机的外部知识库文件可能是另一种语言写的，
云端 AI 回传的严重度又跟随界面语言，所以判定必须两种都认：

- `Localization/DataValues` 统一做「跨语言语义判定」（严重度分类、步骤难度、插件角标）；
- `DiagnosticSeverityMapper` 的字符串重载同时接受中英两套取值；
- 冲突软件扫描把 **`RiskLevel`（`high`/`medium`/`info`，与语言无关，用于排序与卡片配色）
  与 `Risk`（展示文案）拆开** —— 否则中英切换后 XAML 里的 `DataTrigger` 会全部落空、风险色塌成默认值；
- 主题色的中文名（深青 / 海盐蓝 …）从 `AccentScheme` 挪进文案表，界面工具提示随语言切换。

### 4. 顺手修掉的既有问题

| 问题 | 说明 |
|---|---|
| 自检未覆盖「文案资源解析」 | `{DynamicResource Loc.*}` 解析失败是**静默**的（控件留空、编译期与运行期都不报错）。自检新增两项：① 三个代表控件的实际取值非空且不是键名；② 走生产路径跑一遍 **中 → 英 → 中**，断言导航项与顶栏标题即时跟随、往返后还原。 |
| 语言是进程级可变状态、而测试并行 | `Strings.Current` 是全局状态，而大量断言直接比对本地化后的成品文案；xUnit 默认并行跑测试类，一旦有测试切到英文，并发执行的其它断言会随机失败（「单跑通过、全量挂」）。测试工程已显式关闭并行（全套串行约 1 秒）。 |
| `XAML 资源体检` 不认识文案键 | `scripts/check_resources.py` 原来只认 `Themes/*.xaml` 里的键；现已把文案表里的键一并读入并映射成 `Loc.<键>`，1392 处资源引用全部可解析。 |
| AI 工具 schema 语言冻结 | `ObsToolRegistry.Tools` 原先在构造时缓存，切换语言后仍会把旧语言的工具说明发给模型；改为每次访问现建（仅 4 个工具，构造极轻）。 |

## 二、质量基线

- **441 项单元测试全部通过**（上一版 381 项，本版新增 60 项）；
  新增测试集中在「编译器看不见、只能靠人翻页发现」的文案表错法上：
  - 中英两表**键集完全一致**、无重复键、值不为空；
  - 英文表里**不出现汉字**（漏译时最容易复制中文顶上去，人工翻页很难逐条发现）；
  - 两表的**占位符集合一致**（否则中英会各错各的参数个数，格式化时静默把 `{2}` 原样打出来）；
  - XAML 里 `Loc.*` 引用的键**真实存在**（与 `check_resources.py` 互补）；
  - 语言标识归一化（`zh` / `zh-CN` / `chinese` / `chinesesimplified` / `en` / `en-US` / `english` / 未知值）；
  - 文案缺键时「当前语言 → 中文 → 键本身」的回退次序、少传参数不抛异常；
  - `DataValues` / 严重度映射的跨语言判定。
- **Headless 自检 21 项全部 PASS**（上一版 19 项）：17 条路由 + 新手引导覆盖层（含逐步跳转校验）
  + 迷你小窗 + **文案资源解析** + **语言切换往返**。
- 三轮独立审校（功能正确性 / 安全与数据 / 构建与边界），全程零第三方 NuGet 包（纯 BCL）。

## 三、本版不做的事（已定计划）

**随包离线内容的英译**（知识库 212 条 ≈ 5.8 万汉字、场景模板、插件目录 57 条、排障指引）
本版**未做**：英文界面下的知识库、模板、插件目录、排障指引仍显示中文。
体量是界面文案的数倍，且必须整份译完才有意义（译一半的知识库不可交付），
具体做法、验收口径与风险点写在 [`docs/I18N_EN_CONTENT_PLAN.md`](docs/I18N_EN_CONTENT_PLAN.md)。

## 四、升级方式

- **应用内增量更新**：「检查更新」→ 增量更新（本版与 2.9.1 的差异主要是程序集与安装脚本，
  增量包体积仍然很小），下载后自动校验、提权替换并重启。
- **完整安装包 / 便携包**：见 Release 资产；便携包解压即用，自带 .NET 运行时。
- 2.9.0 及更早版本请在应用内选择增量更新或直接下载完整包（更早版本的增量基准对不上）。
